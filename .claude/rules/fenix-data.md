# Fenix A320 rules: data service, definition, variants and EFB

Loaded when Claude reads matching code. The cabin, documents and failures window rules are in fenix-windows.md. FNX-13 (settings lag) and FNX-19 (settings secrets) bind code outside the windows, and FNX-16 (engine readouts) belongs with the data-service rules, so all three stay here. Background: docs/a32nx.md. Full text of each rule: docs/invariants/fenix-data.md.

- [FNX-1] A Fenix data-service read of an unknown name returns `""`, not null (v3): `FenixDataValue.FromJson` maps it to `EmptyOrUnknown`, and no caller may treat that as 0, false, off or closed; a JSON null is unknown too. Full: docs/invariants/fenix-data.md#fnx-1
- [FNX-2] `FenixDataService` subscription callbacks run on a thread-pool thread, never the UI thread: a form marshals to its own thread with BeginInvoke inside try/catch ([A380C-6]), and the service itself never speaks or touches a control. Full: docs/invariants/fenix-data.md#fnx-2
- [FNX-3] Take Fenix data-service names only from open sources (the gateway's own EFB/FAP bundles, names already in the app, HubHop); never guess a name, and never introspect the schema to find one (ruled out on purpose). Full: docs/invariants/fenix-data.md#fnx-3
- [FNX-4] Fenix TO CONFIG verdicts (panel and First Officer) come only from `FenixTakeoffConfigVerdict.WatchAsync`: fresh twin reads timed from the press it saw, "normal" only with both master lights dark at or past `VerdictAfterMs` (v3's measured delay plus 1 s: never shorten it); never the cached 1 Hz lights, a fixed-time read or a pre-press baseline. Full: docs/invariants/fenix-data.md#fnx-4
- [FNX-5] Fenix knobs and push/pulls (`E_FCU_*`, the EFIS and ISIS baro, `S_FCU_VERTICAL_SPEED`, `S_FCU_EFISn_BARO_STD`) are counters the Fenix acts on by difference: step from the sim's own value (`CounterStepCode`), never an app-side count (+1 moved FCU speed -2, 2026-10-21), and read baro STD from `I_FCU_EFISn_QNH` (0 STD, 1 QNH), never the counter. Full: docs/invariants/fenix-data.md#fnx-5
- [FNX-6] A Fenix `Button_Momentary` control is a press button (`ExecuteButtonTransition`), never an Off/On combo: a held 1 flips the function once whatever its state and 0 does nothing (2026-10-21). A spring-loaded end (`Switch_3Position_Hold`, the clock's ET RST) is written, then released to the middle (`PulseSpringSwitch`): a written end holds. Full: docs/invariants/fenix-data.md#fnx-6
- [FNX-7] Never infer what a Fenix lamp means or which control owns it: label a new light by position from its switch ("Econ Flow Lower") until a press in the sim shows what lights. A button whose `StateVariable` is an OFF legend (ADR and IR `_L`, Bus Tie) sets `StateLitText` "Off" and its dark text, and that lamp's announcement says the same words. Full: docs/invariants/fenix-data.md#fnx-7
- [FNX-8] `FenixEFBForm` loads http://127.0.0.1:8083/?target=external#/efb, the target in the query before the #: a sim target (sim-capt, sim-fo, msfs2024-efb) swallows Tab and PageUp/PageDown/Home/End and drops focus 2 s after a click, and localhost pays the ::1 refusal ([A320-40]). Full: docs/invariants/fenix-data.md#fnx-8
- [FNX-9] The Fenix EFB layer (`fenix-efb-accessibility.js`) only adds roles, aria-*, Tab stops and keys calling the page's own click() (plus msfsba- ids and one moveFocus), never a request, a moved node or a written value. It keys on the page's classes: after each Fenix update re-take the tools/fenix-efb-test captures and run capture.md's live check. Full: docs/invariants/fenix-data.md#fnx-9
- [FNX-10] The Fenix `dataRefs` subscription is not a stream for every name: it sent `aircraft.engines.n.n2` once at open and never again, and errors on a value the Fenix has none for (measured 2026-10-22; EGT, flags and fuel do stream). A value that must stay fresh is read once a second with `FenixDataPoller`, never by the subscription alone. Full: docs/invariants/fenix-data.md#fnx-10
- [FNX-11] Fenix variant visibility is `FenixA320Definition.IsFitted`: each arm from that type's own package panel, never by analogy, and hides a control only when its own `FenixVariant` field is read and says the airframe lacks it; an unread field shows it, and NEO engine codes 2/3 keep N1 MODE (the model shows `Engine_IAE_Panel` for any non-zero type). Full: docs/invariants/fenix-data.md#fnx-11
- [FNX-13] After a Fenix settings write (setSetting), the settings query can still return the old value for up to about 2 s (0.4-1.9 s, measured 2026-10-22 on 3.0.0.7438): the documents and options windows both read it back with `FenixSettingReadBack.AwaitAsync` (every 250 ms, up to 16 reads); never report a write as refused from the first read alone. Full: docs/invariants/fenix-data.md#fnx-13
- [FNX-16] The Fenix Engines window's readouts (engine values, TAT, OAT) come from the Fenix's own data-service values (`FenixEngineNames`), never the stock engine SimVars, which run a generic engine model on the Fenix (IAE A321 at idle: stock N1 30.9 vs Fenix 22.4 %, EGT 506 vs 476 C, stock identical on both engines). Output O stays stock. Full: docs/invariants/fenix-data.md#fnx-16
- [FNX-19] The Fenix settings query returns the pilot's credentials: code that shows, speaks or logs settings masks `FenixOptionKeys.Secrets` (hoppie_key, navigraph_refresh_token, pushover_application_key, pushover_token, simbrief_id) by EXACT key (`FenixOptionCatalog.IsSecret`), never by substring (a substring mask hid encoder_acceleration_enabled). Full: docs/invariants/fenix-data.md#fnx-19
- [FNX-20] With Fenix encoder acceleration on or unread, a typed FCU set (`FenixA320FcuKnobSet.RunAsync`) writes at most 20 counts at a time, reads the knob back before each next write and never rewrites an unmoved knob: one -80 write hit the 100 ft floor, 46 ms-spaced writes ran it to 30600 (2026-10-24). The baro knobs are not accelerated. Full: docs/invariants/fenix-data.md#fnx-20
