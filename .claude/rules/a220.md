# Synaptic A220-300 rules

Loaded when Claude reads matching code. Background: docs/a220.md. Full text of each rule: docs/invariants/a220.md.

## Writes and transport

- [A220-1] A220 L:var names contain spaces (an add-on exception to [VAR-2]), so every A220 write goes through `ExecuteCalculatorCode` from the def's `HandleUIVariableSet`, never `SetLVar` (its space/colon guard routes to the unreliable data-def write). Never weaken that global guard; `A22X `/`INI_` prefixes classify as L:vars despite spaces. Full: docs/invariants/a220.md#a220-1
- [A220-2] Never register the `L:A22X Aural *` playback flags: the aircraft speaks its own callouts, so announcing them doubles the audio. Aural Warn Inhibit (+ Lamp) and Aural Internal Test ARE real controls. Test-pinned. Full: docs/invariants/a220.md#a220-2
- [A220-3] APU start is hold-to-start inside the control write (sustain 2 for ~3 s with seq-prefixed re-writes, release to 1), and every A220 calc string carries the `{seq} 0 *` anti-coalescing prefix. Full: docs/invariants/a220.md#a220-3
- [A220-4] A220 cache-fresh quiet vars are `Continuous` + `IsAnnounced=true`, swallowed in `ProcessSimVarUpdate` (`_silentReadoutKeys`): an `IsAnnounced=false` Continuous var gets no subscription at all, so its cache goes stale. Full: docs/invariants/a220.md#a220-4
- [A220-5] NAV radios are standby-set only: never add a NAV active-set or swap (manual active ILS tuning breaks NAV-to-NAV transfer and the 400 ft go-around retune). No spoiler-arm control: the aircraft masks the stock arm events. Both test-pinned. Full: docs/invariants/a220.md#a220-5
- [A220-6] A mode or TOGA press is never followed by silence: FG transitions announce via the monitor, `AnnounceModeResult` adds the deferred honest "no change", and TOGA diffs an FG snapshot and always speaks. Full: docs/invariants/a220.md#a220-6

## FCP knob walks and trim

- [A220-7] FCP dialogs walk, never set: stock SET events leave the WASM's FCP untouched, inc/dec ignore their parameter, and CommBus has no FCP channel. Altitude walks the 1000/100 grid; other knobs keep the measured walk; no open-loop step math. The VS thumbwheel is dead until VS/FPA engages. Full: docs/invariants/a220.md#a220-7
- [A220-8] The walk's read-back prefers `A22X.FCP Data` (30 Hz) and falls back to the 1 Hz SimConnect cache, which is SOUND (the stock AP altitude/heading/speed vars track the knob click for click): keep the grid walk without the link, keep the 1.3 s settle, and measure the step, never assume it. Full: docs/invariants/a220.md#a220-8
- [A220-9] A knob walk AIMS, never hunts: fire `round(|delta|/step)` clicks (`A220Afdx.AimClicks`); 0 clicks means already closest, so stop and say so. Calibrate direction on the first move, and name the metres mode in the result (round feet are often unselectable in metres). Full: docs/invariants/a220.md#a220-9
- [A220-10] A walk never quits before it has moved the knob: "nothing closer" is valid only from a step measured on THIS walk, not an inherited `_fcpStepCache`. Never batch several `(>K:EVENT)` in one calc string: the WASM applies a batch of n as one click. Full: docs/invariants/a220.md#a220-10
- [A220-11] The ALT push ring `L:A22X FG Altitude Fine` is a LEVEL (1 = 100 ft clicks, 0 = 1000 ft), not a pulse. The walk checks each ring write by what a burst moved, re-selects once when the step is off by over 2x (`A220Afdx.StepIsWrongRing`), and restores the pilot's ring after. Full: docs/invariants/a220.md#a220-11
- [A220-12] No stage of the altitude walk may stop "close enough": every stage exits only when ON its value (5 % of a step). The old coarse-stage exit at step/2 fired zero clicks and reported failure for a target one click away. Full: docs/invariants/a220.md#a220-12
- [A220-13] Stab trim is set by the calibrated walk over `ELEV_TRIM_UP`/`_DN` reading `efcs.pitch_trim` back (no set event, no trim L:var); it must REFUSE when the display link is down, and takes the EFB takeoff-perf figure (`abs(trimUnitsNoseUp).toFixed(1) + "UP"`). Full: docs/invariants/a220.md#a220-13
- [A220-14] Stab/rudder trim exist only on the CommBus (`efcs.pitch_trim`/`efcs.rudder_trim`); `L:A22X Horizontal Stabilizer` is the animation ratio, not cockpit units. The stab readout quotes the `pitch_trim_dn`..`pitch_trim_up` band; never expose aileron trim. Full: docs/invariants/a220.md#a220-14

## CommBus tap and flight director

- [A220-15] `RegisterViewListener` is asynchronous: subscribe CommBus `.on()` from its ready callback, retry while nothing has arrived, and ship a `diag` block with any tap (`A.afdx()` -> `A220Afdx.DescribeTap` on Alt+F). Build the diagnostic with the feature, never after it fails. Full: docs/invariants/a220.md#a220-15
- [A220-16] A220 FD state comes from `A22X.Autoflight Data` `l_fd`/`r_fd`, never `L:A22X L/R Flight Director` (a momentary press pulse that reads 0); FD entries are momentary buttons plus CommBus state rows, and a missing link reads "Unknown", never "Off". Full: docs/invariants/a220.md#a220-16
- [A220-17] FD-command and trim signs are decoded from the aircraft's rendering maths and test-pinned: `cmd_lateral` + = bank right, `cmd_vertical_fpa` + = up, `cmd_vertical_pitch` + = nose up, `rudder_trim` + = nose right (+/-1 full scale). Never re-derive one by eye. Full: docs/invariants/a220.md#a220-17

## FMS, ECL and EFB over Coherent

- [A220-18] One DisplayUnits inspector socket, owned by `A220DisplaysClient`: the display pump, FMS form and ECL form share it (`CallAgentAsync`); never open a second connection to that view. The EFB has its own view and client. Full: docs/invariants/a220.md#a220-18
- [A220-19] Drive the FMS with `H:A220_KBD_*`/`H:A220_CTP_*` events (calc path, seq-prefixed) plus clicks on field value nodes, NEVER the hardware-keyboard Entry Mode (it disables all sim input). The input authority is the unencrypted `ModelBehaviorDefs\Synaptic\A220\`, not the JS bundles. Full: docs/invariants/a220.md#a220-19
- [A220-20] The field-commit click hunt skips GRAY tokens (labels) and ranks INLINE above BELOW before nearest-dx (the FUEL page's right-aligned labels made nearest-dx click the wrong field). The agent's `bestValueNode` and `ParseFms` must stay identical. Full: docs/invariants/a220.md#a220-20
- [A220-21] MKP typing is lossy: confirm every character against the scratchpad tap before sending the next; never "fix" a dropped keystroke by raising the inter-key delay. Full: docs/invariants/a220.md#a220-21
- [A220-22] MKP CLEAR is a one-char backspace that arms `--DELETE--` on an empty scratchpad: never clear-before-typing with it. Clear via the agent's `resetScratchpad()` with tap-confirmed emptiness and `PredictScratchpadBuffer`, or entries after one INVALID ENTRY concatenate. Full: docs/invariants/a220.md#a220-22
- [A220-23] ECL actuation: item -> `checklists.json` `"sensed"` NAME -> `A220EclActionMap` (all 215 vars mapped or excluded, coverage-pinned) -> `HandleUIVariableSet`. MSFSBA never ticks a checkbox itself, one item at a time; fire handles, thrust levers and sidestick stay excluded. Full: docs/invariants/a220.md#a220-23
- [A220-24] Detect CLOSED FMS dropdowns via React fibers (`options` + `onSelect` -> `FmsField.IsDropdown`); Enter opens the list, never types the scratchpad into it. Never announce a closed dropdown's option count (it includes hidden options). Close an open one with `dropdownClose()`, never `taskMenuClose()`. Full: docs/invariants/a220.md#a220-24
- [A220-25] Read an FMS follow-up dialog (INTC CRS, HOLD, CROSSING, FIX, AIRWAYS) via `agent.fmsDialogTokens()`, scoped to the dialog's own `<g>`, never a geometric clip of the page (it swallows the list beneath). Space-join tspan runs; each follow-up raises a MOD needing EXEC. Full: docs/invariants/a220.md#a220-25
- [A220-26] Address every LEGS-page action by the aircraft's own `legIdx` from React fibers (`agent.legs()`, `openLegMenuAt`, `deleteLegAt`, calling the row's real `onClick`/`onDelete`), never ident text, occurrence or geometry: duplicate idents opened the wrong waypoint's menu. Full: docs/invariants/a220.md#a220-26
- [A220-27] Pair `Row.LegIdx` to the fiber `legs()` rows by CONTENT (`A220FmsLegParsing.AlignLegIndices`: ident match, disco to placeholder, short lookahead, unmatched -1), never a positional zip: the fiber walk omits rows the grouper shows, so a zip shifted every index by 2. Full: docs/invariants/a220.md#a220-27
- [A220-28] A discontinuity can share its `legIdx` with a neighbour: `legs()` never dedupes by idx alone, and `deleteLegAt(idx, true)` must REFUSE (`WRONG_ROW`) rather than run a non-placeholder row's `onDelete`. An idx dedupe once deleted real waypoints until the plan collapsed. Full: docs/invariants/a220.md#a220-28
- [A220-29] Find the leg ident node STRUCTURALLY (row Input props with both `onDelete` and `value`), never by x: the track line shares its column and legIdx. Compare a menu header's first token only. A `SELECT CONSTRAINT` dialog after deleting a discontinuity is a prompt, not a failure. Full: docs/invariants/a220.md#a220-29
- [A220-30] Open the LEGS revision menu ONLY from the row's fix-symbol icon (`agent.openLegMenu`), never by clicking the ident: it is a scratchpad Input that copies or submits into the leg (it corrupted a live plan). The discontinuity delete aborts when `armStatus()` never confirms. Full: docs/invariants/a220.md#a220-30
- [A220-31] Render every FMS overlay (revision menu, dialog, open dropdown) MODALLY: one `agent.overlay()` per poll, dialogs clipped via `ClipTo`, Escape dismissing the overlay first; never flatten it into the page rows. Read out the amber rejection box (`#ffe300`): it says WHY an entry was refused. Full: docs/invariants/a220.md#a220-31
- [A220-32] EFB `setField` dispatches `keyup` as well as `input`+`change`+`blur`: the EFB binds its Settings saves (the SimBrief ID the FMS uplink and loadsheet import need) and the Takeoff-perf sanitizers to `el.onkeyup`; without it the text shows but never commits. Full: docs/invariants/a220.md#a220-32
