# TFDi MD-11 rules

Loaded when Claude reads matching code. Background: docs/md11.md. Full text of each rule: docs/invariants/md11.md.

- [MD11-3] A button's own L:var is a position ONLY where proven (TFDi's tooltip reads it, or a live probe did); external power, generators and nav lights hold nothing useful there. Extend `LATCH_FIXED` only from a before/after probe. Full: docs/invariants/md11.md#md11-3
- [MD11-4] `state` blocks, lamp pairings, names and label repairs are GENERATED by `tools/md11-gen`: regenerate `md11_control_map.json`, never hand-edit it or patch C#. One lamp node per L:var, chosen by rule; never let a variant word become a label or position. (more: see full) Full: docs/invariants/md11.md#md11-4
- [MD11-5] A position control whose `state_var` is a read-only `export_vars` entry (FCP mode knobs, EFIS minimums caps) is a READ-ONLY ROW, never a walkable combo, and `SetControl` refuses it (`Md11ExportBacked`): its wheel turns the VALUE, not the mode. (more: see full) Full: docs/invariants/md11.md#md11-5
- [MD11-6] A guard cover's `state_var` is its OWN node id, never the L:var its tooltip reads (four covers' tooltips read the control under them); `finalize_controls` pins it, so never re-key a guard in C# or by per-guard curation. Full: docs/invariants/md11.md#md11-6
- [MD11-7] `Md11PanelLayout` is the ONLY source of panel order (unlisted controls appended, never dropped); a guard cover is a row only where the auto-open cannot lift it (`IsAutoOpenedGuard`), dropping a row never drops its variable, and no two rows in a panel share a spoken name. (more: see full) Full: docs/invariants/md11.md#md11-7
- [MD11-12] The EFB reader (`coherent-md11-efb-agent.js`) recognises blocks by DOM STRUCTURE (`A.BLOCKS`), colour only as the selected-state cue: never key a block on a Tailwind class alone, and never let a disabled `input` become an edit field. (more: see full) Full: docs/invariants/md11.md#md11-12
- [MD11-13] Stepper options come from the FIRST React fiber with `options`, never hand-listed and never past an empty array; a press is the pointer sequence plus `el.click()` and NOTHING ELSE; refuse targets under `pointer-events-none` (`A.isInert`); stamp a stable `key` in the reader, never a shared-shell text heuristic. (more: see full) Full: docs/invariants/md11.md#md11-13
- [MD11-16] Every MD-11 write path refuses ALOUD, before writing, when it cannot reach the aircraft: ask `CalcWriteCanLand` (calc bus) or `CanSendEvent` (stock event), never bare `CanExecuteCalculatorCode`; the probe check never moves into `ExecuteCalculatorCode` ([VAR-3]). Re-arm a NEGATIVE verdict on aircraft switch, keep a VERIFIED one. Success is silent. Full: docs/invariants/md11.md#md11-16
- [MD11-17] The `MD11MCDU` subscription never delivers the current page, so `RequestAll` keeps a start-up ONCE snapshot on a DIFFERENT request id. The window restores the cursor by ROW IDENTITY and polls only while visible; ONE `Md11McduDataManager` per connection. (more: see full) Full: docs/invariants/md11.md#md11-17
- [MD11-21] The MD-11's AI display reads use instrument views 1, 3 and 4 (indices 0, 2, 3 in `Md11DisplayReads`); the six DUs are ONE row, so "upper ECAM" is the EAD and "lower ECAM" the SD beside it, never a stacked pair. (more: see full) Full: docs/invariants/md11.md#md11-21
- [MD11-24] The three engine fire handles are READ-ONLY composite rows (`Md11CompositeState` over both vars, never the DC gate) that `SetControl` refuses aloud; never give them a value map or put them back on the walk. The Elevator Feel knob follows the same rule; the APU handle stays a combo. Full: docs/invariants/md11.md#md11-24
- [MD11-25] A flat 0 is no MD-11 reading: an export reads 0 until published, so the captain's altimeter announcer and the B key treat ≤ 0 as absent, never a baseline and never "0, 0.00". Full: docs/invariants/md11.md#md11-25
- [MD11-26] The EFB shell speaks a pressed control's changed label ONLY where the reader flags it `announceChange: true` (the two stepper arrows, the tile button, the state tile's ACTION button), never unconditionally and never by suffix or by who was pressed; the per-item `live` hint cannot do this job. Full: docs/invariants/md11.md#md11-26
