# TFDi MD-11 rules

Loaded when Claude reads matching code. Background: docs/md11.md. Full text of each rule: docs/invariants/md11.md.

- [MD11-1] Every MD-11 control write is a CEVENT through `Md11EventBus` with the `{seq} 0 *` prefix; never `SetLVar` a control var. Only three writes bypass it (`Md11EventBus.WriteExternal`), a CLOSED set, and `Md11DirectSet.Refuse` is never loosened. (more: see full) Full: docs/invariants/md11.md#md11-1
- [MD11-2] `Md11ControlState.Compose` orders lit legends, the PROVEN latch, "unpowered", then the dark meaning; dark is never "normal" without the DC gate, which is TWO vars: `MD11_DC_BUS_VOLTAGE` ≥ 20 V AND `MD11_OVHD_ELEC_DC1_BUS_OFF_LT` dark, never voltage alone. Full: docs/invariants/md11.md#md11-2
- [MD11-3] A button's own L:var is a position ONLY where proven (TFDi's tooltip reads it, or a live probe did); external power, generators and nav lights hold nothing useful there. Extend `LATCH_FIXED` only from a before/after probe. Full: docs/invariants/md11.md#md11-3
- [MD11-4] `state` blocks, lamp pairings, names and label repairs are GENERATED by `tools/md11-gen`: regenerate `md11_control_map.json`, never hand-edit it or patch C#. One lamp node per L:var, chosen by rule; never let a variant word become a label or position. (more: see full) Full: docs/invariants/md11.md#md11-4
- [MD11-5] A position control whose `state_var` is a read-only `export_vars` entry (FCP mode knobs, EFIS minimums caps) is a READ-ONLY ROW, never a walkable combo, and `SetControl` refuses it (`Md11ExportBacked`): its wheel turns the VALUE, not the mode. (more: see full) Full: docs/invariants/md11.md#md11-5
- [MD11-6] A guard cover's `state_var` is its OWN node id, never the L:var its tooltip reads (four covers' tooltips read the control under them); `finalize_controls` pins it, so never re-key a guard in C# or by per-guard curation. Full: docs/invariants/md11.md#md11-6
- [MD11-7] `Md11PanelLayout` is the ONLY source of panel order (unlisted controls appended, never dropped); a guard cover is a row only where the auto-open cannot lift it (`IsAutoOpenedGuard`), dropping a row never drops its variable, and no two rows in a panel share a spoken name. (more: see full) Full: docs/invariants/md11.md#md11-7
- [MD11-8] A walked control's state var is consumed by `ProcessSimVarUpdate` during the walk, so no forced read reaches MainForm's combo refresh mid-walk; the walker reads via `ReadFreshAsync` on the read's OWN request id, never the subscription's, and SIM_FRAME subscriptions are seeded. (more: see full) Full: docs/invariants/md11.md#md11-8
- [MD11-9] Every spoken MD-11 read-back verdict reads through `SimConnectManager.ReadFreshAsync`, never a fixed sleep and the cache, and speaks only on a DELIVERED value; `FeedbackDelayMs` is a deadline inside `Md11AnnouncementGate.EchoWindowMs`, never clamp the guard's settle. (more: see full) Full: docs/invariants/md11.md#md11-9
- [MD11-10] NAV and FMS SPD engagement are read from the FCP windows' dashes (`Md11AutoflightState`: `MD11_AFS_HDG`/`MD11_AFS_SPD` = -999), never the `MD11_CGS_*_BT` button vars; a dashed V/S window never claims PROF or APPR/LAND. (more: see full) Full: docs/invariants/md11.md#md11-10
- [MD11-11] A lamp change speaks its OWNER's composed state; a press is confirmed once after settle, its lamp echo swallowed until then; a lamp going DARK is never spoken on the spot (deferred `DarkSettleMs`, re-decided). `ExcludeFromMonitorManager` never sits on a var that speaks. (more: see full) Full: docs/invariants/md11.md#md11-11
- [MD11-12] The EFB reader (`coherent-md11-efb-agent.js`) recognises blocks by DOM STRUCTURE (`A.BLOCKS`), colour only as the selected-state cue: never key a block on a Tailwind class alone, and never let a disabled `input` become an edit field. (more: see full) Full: docs/invariants/md11.md#md11-12
- [MD11-13] Stepper options come from the FIRST React fiber with `options`, never hand-listed and never past an empty array; a press is the pointer sequence plus `el.click()` and NOTHING ELSE; refuse targets under `pointer-events-none` (`A.isInert`); stamp a stable `key` in the reader, never a shared-shell text heuristic. (more: see full) Full: docs/invariants/md11.md#md11-13
- [MD11-14] `Md11TestButtons` holds eleven test buttons 3 s via `PressAndHoldAsync`, but never the ANNUNCIATOR LIGHT TEST (it stays a tap). `Md11EventBus.Dispose` stops the pump first and writes every owed UP before draining, bounded; an UP never precedes its DOWN. (more: see full) Full: docs/invariants/md11.md#md11-14
- [MD11-15] `MD11_EXTCTL_{CAP,FO}_MIN` set the BARO minimums only and idle at -9999 (not -1); the rows' mode word comes from the silent batch-covered mirror, never the OnRequest switch, since batch-covering the switch breaks its walk. Full: docs/invariants/md11.md#md11-15
- [MD11-16] Every MD-11 write path refuses ALOUD, before writing, when it cannot reach the aircraft: ask `CalcWriteCanLand` (calc bus) or `CanSendEvent` (stock event), never bare `CanExecuteCalculatorCode`. Re-arm a NEGATIVE probe verdict on aircraft switch, keep a VERIFIED one. Success stays silent. (more: see full) Full: docs/invariants/md11.md#md11-16
- [MD11-17] The `MD11MCDU` subscription never delivers the current page, so `RequestAll` keeps a start-up ONCE snapshot on a DIFFERENT request id. The window restores the cursor by ROW IDENTITY and polls only while visible; ONE `Md11McduDataManager` per connection. (more: see full) Full: docs/invariants/md11.md#md11-17
- [MD11-18] Anything the MD-11 definition speaks from a timer checks `Md11DisabledMonitorVariablesSet` itself (MainForm's `Suppressed` wrap covers only `ProcessSimVarUpdate`), and an unchanged redelivery must not re-arm a settle timer. Full: docs/invariants/md11.md#md11-18
- [MD11-19] Wipe baseline-first trackers in `OnSimContextReset` (dropping roll-cue arms, never their V-speeds), NEVER in `ResetAnnouncementBaselines`; re-seed them from cache when `Md11SeedGate` decides on batch-delivery evidence, NEVER on a wall clock. (more: see full) Full: docs/invariants/md11.md#md11-19
- [MD11-20] The "N1 70 percent" cue (`Md11N1Cue`) is a take-off-roll cue with `TakeoffVSpeedCallouts`' gate (arms on the ground, slow, every engine below 60 %; fires once at 70 % on the ground), never a bare N1 latch; `Reset` drops only the arm. Full: docs/invariants/md11.md#md11-20
- [MD11-21] The MD-11's AI display reads use instrument views 1, 3 and 4 (indices 0, 2, 3 in `Md11DisplayReads`); the six DUs are ONE row, so "upper ECAM" is the EAD and "lower ECAM" the SD beside it, never a stacked pair. (more: see full) Full: docs/invariants/md11.md#md11-21
- [MD11-22] Never seed an MD-11 flap combo by an EXACT key: map values through `SimVarDefinition.ValueToDescriptionKey` (`NearestDialChoice` for the wheel, `LeverDetentKey` for the handle), or the first Down-arrow commits row 0 and can retract the flaps. (more: see full) Full: docs/invariants/md11.md#md11-22
- [MD11-23] The MD-11 must register `MSFSBA_BRIDGE_PROBE`, its ONLY opt-in to the calc-path probe and `CalcPathVerdict.PilotWarning`; never remove it, never add a warning of its own in the bus, and never put the probe var in `SeededScalarKeys`. Full: docs/invariants/md11.md#md11-23
- [MD11-24] The three engine fire handles are READ-ONLY composite rows (`Md11CompositeState` over both vars, never the DC gate) that `SetControl` refuses aloud; never give them a value map or put them back on the walk. The Elevator Feel knob follows the same rule; the APU handle stays a combo. Full: docs/invariants/md11.md#md11-24
- [MD11-25] A flat 0 is no MD-11 reading: an export reads 0 until published, so the captain's altimeter announcer and the B key treat ≤ 0 as absent, never a baseline and never "0, 0.00". Full: docs/invariants/md11.md#md11-25
