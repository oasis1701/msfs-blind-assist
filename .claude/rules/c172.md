# Cessna 172 Skyhawk rules

Loaded when Claude reads matching code. Background: docs/c172.md. Full text of each rule: docs/invariants/c172.md.

- [C172-1] The C172 G1000's MAIN battery is `ELECTRICAL MASTER BATTERY:2` and index 1 is the standby: never read index 1 as the master, and never send `TOGGLE_MASTER_BATTERY` without an index (it flips both batteries). Measured on MSFS 2024's stock aircraft. Full: docs/invariants/c172.md#c172-1
- [C172-2] Every G1000 switch writes its cockpit input event with an explicit value (`SwitchInputEvents`), never a toggle; `AVIONICS_MASTER_n_SET` and `FUEL_SELECTOR_SET` do not reach this cockpit. Read what the switch drives (`FUELSYSTEM` vars, `LIGHT NAV` not the lamp's `LIGHT NAV ON`); the avionics buses, standby battery and magneto read their input event. Full: docs/invariants/c172.md#c172-2
- [C172-3] A GFC 700 key is one press, `AS1000_AUTOPILOT_<KEY>_PFD` set to 1 (`AutopilotKeys`), never K: events; the selected altitude is one `AP_ALT_VAR_INC` then a write of the SimVar (`ShowSelectedAltitudeDialog`): `AP_ALT_VAR_SET_ENGLISH` ignores its value, and FLC is refused until an altitude is selected. Full: docs/invariants/c172.md#c172-3
- [C172-4] A walkaround cover's input event TOGGLES it (`CoverInputEvents`): press only after a fresh read says it differs. `COVER ON:1` is the engine cover, which stops the engine starting (the sim's autostart included), 2 the pitot, 3 the static port. Full: docs/invariants/c172.md#c172-4
- [C172-5] The fuel selector reads `FUELSYSTEM JUNCTION SETTING:1` (`FuelSelectorPositions`): 1 Left, 2 Both, 3 Right, measured by which tank drained with the engine running; its input value is one less. Never label it from the cockpit order alone. Full: docs/invariants/c172.md#c172-5
- [C172-6] Never try to hold the G1000 key at START by repeating writes: it springs back 3.0-3.6 s in whatever is sent (same-value sets ignored, `MAGNETO1_START` repeated toggles, `SET_STARTER1_HELD` undone in a frame), and each gap restarts the crank. The Starter is one START plus a backup `StarterBackupMs` later, for a set that bounces back. Full: docs/invariants/c172.md#c172-6
- [C172-7] A G1000 circuit breaker's input event is a direct set, 1 Pulled and 0 In (`BreakerInputEvents`), never a toggle; read it from the input event. ADC, Nav 1 and PFD are fed from the essential AND avionics 1 buses, and avionics bus 1's loads all are, so one of those breakers pulled alone cuts nothing: that is the aircraft, not a fault. Full: docs/invariants/c172.md#c172-7
- [C172-8] Never write the G1000's cabin door or its handle (`INSTRUMENT_DOOR_LEFT`, `UNKNOWN_DOOR_HANDLE_1`): in MSFS 2024 they are how the pilot gets out, and writing them put the pilot outside the aircraft mid-session. The windows (`AIRCRAFT_DOOR_WINDOW_PILOT`, `AIRCRAFT_DOOR_WINDOW`) are safe direct sets. Full: docs/invariants/c172.md#c172-8
- [C172-9] Take an input event's SCALE from what SimConnect delivers (debug.log's `Input event ... =` lines), never from the Coherent debugger's `B:` read: the cabin levers (`Lever`, `QuarterStep`) are percent in SimConnect, 50 written and 50 delivered, but a 0-1 fraction in Coherent, and a combo keyed on the fraction snapped back to Open after every pick. Full: docs/invariants/c172.md#c172-9
- [C172-10] A GMA 1347 key (`AudioKeyInputEvents`, `MicKeys`, `IntercomKeys`) is a momentary push that TOGGLES: its _MIDCOM input event goes to 1 and back to 0 by itself, and each push flips the key. Push only after a fresh read says it differs (`SetAudioKeyAsync`), never a direct set or the DA40's by-value write (DA40F-12). Full: docs/invariants/c172.md#c172-10
- [C172-11] The typed course is the CDI's: `SetCourseAsync` reads GPS DRIVES NAV1 and AUTOPILOT NAV SELECTED as it writes and sends the stock event for that receiver (`CourseEventFor`); never the CRS knob's own input event, whose direction was unreliable (one +1 raised NAV 1's course and lowered NAV 2's). Full: docs/invariants/c172.md#c172-11
- [C172-12] The audio rows are spoken by `NoteAudioUpdate`, which returns true and keeps its own baseline, never by the generic announcer: a knock-on of MSFSBA's own COM audio set stays quiet (`IsComAudioSideEffect`, `ComAudioGraceMs`) yet still moves the baseline, where a swallowed generic update would leave it stale and mute a later change back. Full: docs/invariants/c172.md#c172-12
- [C172-13] The squawk is BCD16: its key stays `TRANSPONDER_CODE_SET` so MainForm's squawk path encodes it, and the C172's `HandleUIVariableSet` returns false for it. Never the generic event path, which sent a typed 2300 as a plain number and set squawk 0074. Full: docs/invariants/c172.md#c172-13
- [C172-14] A typed standby goes in whole hertz (`StandbyHz`: `COM_STBY_RADIO_SET_HZ`, `COM2_STBY_RADIO_SET_HZ`, NAV1/NAV2_STBY_SET_HZ, 8.33 kHz exact) and each radio swaps through its own event; a frequency outside the band is refused aloud (`StandbyRefusal`), never clamped. Full: docs/invariants/c172.md#c172-14
- [C172-15] The transponder mode is TRANSPONDER STATE:1 written directly (Standby, On, Altitude, Ground, measured to hold) and the combo follows the sim; Off is listed so a 0 never leaves a stale pick, and refused when picked. Ident (`XPNDR_IDENT_ON`) works only On or Altitude, so in standby it is refused aloud, never sent. Full: docs/invariants/c172.md#c172-15
- [C172-16] ELECTRICAL MAIN BUS VOLTAGE and BUS VOLTAGE:n read 0 here; the buses are read as the G1000 reads them, ELECTRICAL BUS VOLTAGE by its bus names (`C172_MAIN_BUS_VOLTS`, `C172_ESS_BUS_VOLTS`). Never build battery amps on ELECTRICAL BATTERY LOAD: it reads positive charging and discharging alike (measured 2026-10-18). Full: docs/invariants/c172.md#c172-16
- [C172-17] The C172's warnings and cautions are the G1000's own CAS messages, spoken by the shared G1000 CAS watcher off the PFD; never recompute one from SimVars (it would speak twice). The FMA speaks the autopilot modes, so their rows are quiet (`IsAutopilotModeSpokenByFma`, `QuietModesTheFmaSpeaks`), the master and flight director keeping their OFF. Full: docs/invariants/c172.md#c172-17
- [C172-18] An engine reading carries the zone the G1000's own panel.xml draws (`CessnaC172Gauges`), never the DA40's band table, which has no uncoloured stretch; green holds both ends, an uncoloured reading says below or above the green arc only with an arc beyond it, and the RPM green top follows the gauge's altitude state machine (`NextRpmArc`). Full: docs/invariants/c172.md#c172-18
