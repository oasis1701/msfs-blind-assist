# Fenix A320 dependency inventory (MSFS Blind Assist)

Repository `D:\Claude\oasis1701\msfs-blind-assist`, branch `main` at `2d6444ab1` (2026-10-21). Read-only survey for the Fenix update from **v2.4.0.4720 to v3.0.0.7426**. Every `file:line` is relative to the repository root and refers to that commit.

Companion files in this folder:

- `fenix-names.txt`: every sim-facing name, one per line (`kind<TAB>name<TAB>file:line`).
- `defs.tsv`: all 894 `SimVarDefinition`s of `FenixA320Definition` (line, key, name, type, update frequency, announced, units, display name, value encoding, flags). Generated by `parse_defs.py`.
- `panels.txt`: every panel and its controls (generated). Appendix A below is the same list.
- `sections.txt`: definitions bucketed by the definition file's own section headers, with the background-monitoring-only variables.

How the app talks to the Fenix, in one paragraph: almost everything is **L:vars over SimConnect** (888 L:var definitions over 870 distinct names, plus 9 more names written only from code; read as SimConnect data definitions `L:<name>`; written with `SimConnectManager.SetLVar`), plus a handful of **MobiFlight calculator-code** read-modify-write strings for the rotary encoders, a few **stock K-events and SimVars** (COM radios, transponder, gear, weights, fuel, engine N2, camera), the **Fenix data service** (GraphQL on port 8083) for the two **MCDUs only**, the **Fenix EFB web page** on the same port in a WebView2, and **AI vision** on camera captures for PFD/ND/ECAM/standby. No H-events, no B: input events, no Fenix process, window, registry, file, memory or version access.

## (b) Transports and external endpoints

### B1. SimConnect L:vars (the main transport)

- **Read:** every definition is registered as SimConnect data definition `L:<Name>`, units `"number"` (`SimConnect/SimConnectManager.Setup.cs:475`, `SimConnectManager.DataRequests.cs:397`, `ContinuousBatchLayout.cs:28`). 455 Continuous (batched, about 1 Hz; `I_FCU_SPEED_MANAGED`, `N_FCU_EFIS1_BARO_INCH/_HPA` and the other FCU readout originals are `ExcludeFromBatch` with their own once-a-second subscription), 439 OnRequest (panels; the First Officer polls its list every second). The Fenix registers about 490 of the roughly 1000 data definitions SimConnect allows (`docs/invariants/a32nx-fenix.md:136`).
- **Write:** `SimConnectManager.SetLVar(name, value)` (`SimConnect/SimConnectManager.EventSend.cs:14-66`): if `CalcPathVerified` (MobiFlight WASM proven by the `MSFSBA_BRIDGE_PROBE` nonce probe, which only the FBW A320/A380, Headwind A330 and MD-11 run; a verdict persists to the Fenix if one of those was loaded first) → calculator code `<value> (>L:<name>)` (:54); otherwise a native `AddToDataDefinition("L:<name>")` + `SetDataOnSimObject` write (:59-66), "which works for Fenix" (:29). Measured equal to the cockpit click for the ACP latches (`docs/a32nx.md:108`).
- **Calculator code through the MobiFlight WASM module** (needed for these regardless of the probe): `ExecuteCalculatorCode("(L:E_FCU_EFIS{n}_BARO) <n> +|- (>L:E_FCU_EFIS{n}_BARO)")` (`FenixA320Definition.cs:12428-12437`) and `ExecuteCalculatorCodeUnique("(L:S_FCU_{SPEED|HEADING|ALTITUDE}) 1 -|+ (>L:...)")` with a `<seq> 0 * ` uniqueness prefix (:12454-12462; First Officer `FenixActionExecutor.cs:316`). The pilot guide lists MobiFlight WASM as required for the Fenix (`guide/airbus-aircraft.md:225`).

### B4. Fenix data service (GraphQL), used ONLY by the MCDU window

- Subscription URL `ws://127.0.0.1:8083/graphql` (`Services/FenixMCDUService.cs:45`); WebSocket subprotocol **`graphql-transport-ws`** (:133). Must be `127.0.0.1`, never `localhost` (IPv4-only listener; [A320-40]; pinned by `tests/.../FenixDataServiceAddressTests.cs`).
- Handshake: sends `{"type":"connection_init"}` (:138), requires `{"type":"connection_ack"}` (:142-146).
- Subscribe (:149-158), message `{"id":"1","type":"subscribe","payload":{"query":...,"variables":{"names":[...]}}}`, query verbatim (`FenixMCDUService.cs:155`):

  ```
  subscription ($names: [String!]!) { dataRefs(names: $names) { name value } }
  ```

  with `names` = `["aircraft.mcdu1.display", "aircraft.mcdu2.display"]` (`Services/FenixMcduSides.cs:14-17`).
- Incoming: `type == "next"` → `payload.data.dataRefs.name` / `.value` (:171-177; unknown names ignored :178-181); `type == "ping"` → replies `{"type":"pong"}` (:193-199; service pings about every 15 s); `error`/`complete` end the loop (:200-204). Reconnect backoff 3, 6, 12, 30 s (:57, :121-126). 64 KB receive buffer (:141).
- Key writes: HTTP `POST http://127.0.0.1:8083/graphql` (:46, :271), header `Accept: application/json` (:68), content type `application/json` (:270), body `{"query": <below>, "variables": {"keyName": "...", "value": 1|0}}`, mutation verbatim (`FenixMCDUService.cs:258-263`):

  ```
  mutation ($keyName: String!, $value: Int!) {
                  dataRef {
                      writeInt(name: $keyName, value: $value)
                      __typename
                  }
              }
  ```

  `keyName` = `system.switches.S_CDU{1|2}_KEY_{key}` (`FenixMcduSides.cs:32`); a press is `1`, 50 ms, `0` (:243-252); typed text 50 ms between keys (`FenixMCDUForm.cs:509-512`). Response only checked with `EnsureSuccessStatusCode` (:272).
- Screen value: an XML document parsed with `XDocument`: root's `<title>`, up to 12 `<line>` elements, `<scratchpad>` (:281-321); text carries inline lowercase format codes, decoded by `FenixMcduFormat` (colours `a c g m w y`, sizes `s`/`l`, glyphs `#` `&` `¤` `¥` `¢` `£`) (`Services/FenixMcduFormat.cs:36-47`). 24-column split (:352-367).
- dataRef names used: `aircraft.mcdu1.display`, `aircraft.mcdu2.display`, `system.switches.S_CDU{1,2}_KEY_{LSK1L..LSK6L, LSK1R..LSK6R, ARROW_LEFT, ARROW_RIGHT, ARROW_UP, ARROW_DOWN, CLEAR, INIT, DIR, PROG, FPLN, PERF, RAD_NAV, SEC_FPLN, FUEL_PRED, ATC_COM, MENU, AIRPORT, DATA, OVFLY, A-Z, 0-9, DOT, SLASH, MINUS, SPACE}` (140 expanded in `fenix-names.txt`).
- Not used by the app (memory note only): any other dataRef (engines, fuel, weights, `aircraft.fms.*`, doors), the `query { dataRef { ... } }` read form, schema introspection (refused by the service).

## (c) Hard-coded assumptions a new major version could break

### C1. Identity, naming, variants

- Code `FENIX_A320CEO` / name "Fenix A320 CEO" (`FenixA320Definition.cs:13-14`), compared as strings in `MainForm.Announcers.cs:334`, `MainForm.Hotkeys.cs:288, 522`, `MainForm.AircraftSwitch.cs:152, 1268-1269` (`StartsWith("FENIX_")`), `Forms/HotkeyListForm.cs:138`, `Forms/FirstOfficer/FirstOfficerWindows.cs:38`; menu "Fenix A320 &CEO" (`MainForm.Designer.cs:232-236`). The only "CEO" dependence is these labels; nothing is keyed on TITLE, livery, SimObject path or package name, so a renamed v3 package still loads, but nothing distinguishes a v3 airframe the profile does not fit (e.g. a neo).

### C3. Encoders (counter L:vars) and knob pushes

- `E_FCU_ALTITUDE`, `E_FCU_HEADING`, `E_FCU_SPEED`, `E_FCU_VS`, `E_FCU_EFIS{1,2}_BARO`, `E_MIP_ISFD_BARO` and the push/pull vars `S_FCU_SPEED`, `S_FCU_HEADING`, `S_FCU_ALTITUDE`, `S_FCU_VERTICAL_SPEED` are treated as relative counters: the Fenix acts on the change, not the value (`docs/fenix-increment-decrement.md:7, 275-280`).
- App-side counters (`rmpCounters`, start at 0 each session) write absolute values: `IncrementCounter`/`DecrementCounter`/`JumpCounter` (`FenixA320Definition.cs:12775-12870`). A single jump of N steps is assumed to be applied at once ("The Fenix WASM module detects the counter delta each sim frame and processes all steps at once", :12843-12846).
- Atomic read-modify-write RPN for the baro encoders and the speed/heading/altitude push/pull (:12428-12462; First Officer `FenixActionExecutor.cs:300-321`): push = -1, pull = +1. V/S push = app-side decrement, pull = increment of `S_FCU_VERTICAL_SPEED` (:11974-11980, :13232-13238).
- Step sizes: heading 1 degree (shortest-path wrap, :12955-12966), speed 1 kt or Mach 0.01, altitude 100 ft after forcing `S_FCU_ALTITUDE_SCALE` = 0 then restoring (:13048-13060), V/S 100 fpm (:13133-13134; FPA mode not handled), baro 1 hPa per step in hPa mode, 0.01 inHg per step in inHg mode (:12306-12338).
- Read-back for verification: `N_FCU_HEADING/SPEED/ALTITUDE/VS` from the cache, `N_FCU_EFIS{n}_BARO_HPA/_INCH` via `ReadFreshAsync` (:12347, :12375).

### C4. Momentary-button protocol

- Panel: `ExecuteButtonTransition` (157 call sites) = `SetLVar(name, 0)` → 200 ms → `1` → hold 200 ms (TO CONFIG 1500 ms) → `0` (:12591-12614, :12666-12739). Assumes every `S_*` pushbutton latches on the 0→1 edge and shows its state in a separate `I_*` var, so the release never loses state ([A320-3], [A320-4]; measured for RMP mode keys, EFIS filters, ECAM page keys, `docs/a32nx.md:87`).
- First Officer: `LVarActionExecutor` write spacing 150 ms, pulse 0 → 200 ms → 1 → 200 ms → 0 (`FirstOfficer/Generic/LVarActionExecutor.cs:45-51`); held tests (fire APU/ENG1/ENG2, CVR) 1 for 3 s then 0; CALL ALL 600 ms (`FenixActionExecutor.cs:30-31, 246-260`).
- Toggle buttons (EXT PWR, LS, FD, autobrake MAX, recorder GND CTL) are pulsed only when their light reads the opposite state, never while unread (`FenixFlowDefinitions.cs:805-810`).
- Rudder trim: `S_FC_RUDDER_TRIM` 0 or 2 for 200 ms then 1 (:13145-13184).
- Thrust levers both: two `SetLVar`s (:12048-12053).

### C5. Timing

Panel buttons 200/200 ms, TO CONFIG hold 1500 ms; rudder trim 200 ms; FCU value set: single counter jump, check after 750 ms and again after 750 ms, then batches of 10 steps 33 ms apart, final check 200 ms (:12885-12948); altitude scale switch 100 ms (:13051); baro set: STD→QNH 750 ms, mode 300 ms, read 500 ms, verify 750 ms + up to 1500 ms fresh read, final read 500 + 300 ms (:12301-12406). MCDU: key press 1 → 50 ms → 0, 50 ms between typed keys, reconnect 3/6/12/30 s, 15 s ping. First Officer: APU master → 3 s → START, AVAIL wait 180 s polled 1 s (`FenixActionExecutor.cs:32, 53-56`); engine start N2 wait 120 s; shutdown power-source wait 120 s, engines-stopped wait 120 s; Securing APU flap fixed 120 s; gear checks 20 s; memo/radar checks 5 s; guards 5 s; 2 s between flow steps (`FlowManager.InterStepPauseMs`, rule [FO-5]). Phase monitor: 10,000 ft +/- 300 ft hysteresis, climb/descent > 150 fpm, no-transition reminder above 18,300 ft (`FenixFlightPhaseMonitor.cs:28-29, 77-110`). Auto-AP engage: 3 s between presses, waits for an AP light reading (`FenixA320Definition.cs:12646-12651`, `BaseAircraftDefinition.cs:853`). 5 s announcement grace after an aircraft switch or connect, while ~455 continuous values first arrive (`MainForm.AircraftSwitch.cs:926`).

### C6. Data-service format assumptions (MCDU)

Port 8083, path `/graphql`, IPv4 only; `graphql-transport-ws` protocol with server pings; dataRef names `aircraft.mcdu{1,2}.display` and `system.switches.S_CDU{n}_KEY_<KEY>` with the key spellings in B4; `dataRef { writeInt(name, value) }` mutation; screen XML with `title`, `line` x12, `scratchpad`; 24 columns; colour codes `a c g m w y`, size codes `s`/`l` (a line starts large), selection = cyan + large font among small siblings, or a green segment ([A320-31]; `FenixMcduFormat.cs:6-26, 72-80`); special glyphs `#`→`-`, `&`→delta, `¤ ¥ ¢ £` arrows. Only MCDU 1 and 2 exist (`FenixMcduSides.cs:31-33`).

### C7. Stock-SimVar/event assumptions

- COM 1-3 are the stock radios (`COM*_STBY_RADIO_SET_HZ`, `COM STANDBY FREQUENCY:n`); the squawk is the stock `XPNDR_SET`.
- The gear lever follows stock `GEAR_UP`/`GEAR_DOWN`, and `GEAR HANDLE POSITION` reflects it (universal auto-gear and Shift+G).
- Flaps are read from `S_FC_FLAPS`, not `FLAPS HANDLE INDEX` ("different detent count", :12493-12494).
- Engine running from stock `TURB ENG N2` (see C1).
- Weight and fuel from stock `TOTAL WEIGHT` / `FUEL TOTAL QUANTITY WEIGHT` (lbs).
- Stock `COM RECEIVE:3` follows the VHF 2 latch, not VHF 3 (`docs/a32nx.md:111`).
- Takeoff Assist V1/VR from `N_MISC_PERF_TO_V1/VR` (`MainForm.Hotkeys.cs:521-530`); the First Officer's speed read-back from `FNX2PLD_speedV1/VR/V2` (`FenixChecklistDefinitions.cs:598-601`).

### C8. Capacity and pacing

About 490 of ~1000 SimConnect data definitions (`docs/invariants/a32nx-fenix.md:136`); "477 continuous variables" comment (`SimConnectManager.Setup.cs:806`); "~50 at 1 Hz" own subscriptions (`SimConnect/DeliveryLogPolicy.cs:15`). A v3 that needs more names pushes toward the ceiling.

### C9. Camera

Instrument view indices 7 and 8 (live list, 0-based), `MAX:2` = 18, file position 7 missing; the FO's PFD is the only whole PFD in any view (`FenixA320DisplayReads.cs:6-62`). A v3 `cameras.cfg` change moves or invalidates these.
