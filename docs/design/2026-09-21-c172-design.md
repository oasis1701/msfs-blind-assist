# Stock Cessna 172 Skyhawk (G1000) support — design

Date: 2026-09-21
Status: approved in conversation, awaiting written review
Scope: option A — cockpit panel and radios. No autopilot, no G1000 screen reading.

## 1. Goal and target

Support the stock MSFS 2024 Cessna 172 Skyhawk (G1000) — the only 172 purchasable in
the 2024 career mode — so a blind pilot can operate the physical panel, tune the radios
and transponder, and hear the aircraft's state changes, using nothing but stock SimVars
and stock K: events. No MobiFlight WASM module, no L:vars, no calc-path dependency.

Everything aircraft-independent (taxi guidance, takeoff assist, hand fly, visual landing
guidance, docking, the flight-planning EFB, weather, SayIntentions, VATSIM, the universal
readout hotkeys) already works in the C172 and is unchanged.

Out of scope for this version, recorded so they are not re-derived:

- The GFC 700 autopilot (buttons, bugs, mode callouts). Stock events would reach it; the
  pilot chose to leave it out of the first version.
- Reading or driving the G1000 PFD/MFD (flight plan, nearest, engine page, alerts). That
  is a Coherent-debugger scrape agent, the same class of work as the HS787 CDU.
- V-speed callouts (no V1/VR/V2 entry on a 172; a rotate call is a possible follow-up).
- Throttle (stays on the pilot's hardware axis).

## 2. Approach

A dedicated `Aircraft/Cessna172Definition.cs` on `BaseAircraftDefinition`, aircraft code
`C172`, modelled on `HorizonSim787Definition` — the one existing definition built almost
entirely from stock SimVars + stock events (its lights, electrics, COM tuning and squawk
are exactly this shape). Written so a future stock C152/C208 can subclass it the way
`HeadwindA330Definition` subclasses the A320.

Rejected: a data-driven "stock GA" table (new mechanism the codebase has never needed,
for a fleet of one), and a generic fallback definition for unknown aircraft (wrong
controls are worse for a blind pilot than missing ones).

Selection is by the Aircraft menu, remembered in `UserSettings.LastAircraft`, like every
other aircraft. The app has no auto-detection of the loaded aircraft and this does not
add one.

## 3. Panel structure and controls

Section **Cockpit**

| Panel | Controls (write) | State read back from |
|---|---|---|
| Electrical | Master battery, Alternator, Avionics Bus 1, Avionics Bus 2, Standby battery | `ELECTRICAL MASTER BATTERY:1`, `GENERAL ENG MASTER ALTERNATOR:1`, `AVIONICS MASTER SWITCH:1`/`:2`, standby battery var (see §8) |
| Engine | Magnetos combo Off / Right / Left / Both (`MAGNETO1_SET`), **Start Engine** button, Fuel pump, Mixture 0–100 % entry box, Alternate air (only if its stock var proves live) | two magneto bools composed into one position, `GENERAL ENG STARTER:1`, `GENERAL ENG FUEL PUMP SWITCH:1`, `GENERAL ENG MIXTURE LEVER POSITION:1` |
| Fuel | Selector Left / Both / Right (`FUEL_SELECTOR_SET`), Fuel shutoff valve | `FUEL TANK SELECTOR:1`, shutoff (see §8) |
| Lights and Ice | Beacon, Nav, Strobe, Taxi, Landing (On/Off combos, `*_LIGHTS_SET` / `STROBES_SET`), Pitot heat (`PITOT_HEAT_SET`) | stock `LIGHT *` SimVars, `PITOT HEAT SWITCH:1` |
| Flight controls | Flaps combo Up / 10 / 20 / Full (`FLAPS_UP` / `FLAPS_1` / `FLAPS_2` / `FLAPS_DOWN`), Parking brake (toggle-if-differs `PARKING_BRAKES`) | `FLAPS HANDLE INDEX`, `BRAKE PARKING POSITION`; elevator trim readout from the base `MON_ElevatorTrim` |

Section **Avionics**: Radios and Transponder (§4).

Write rules:

- A combo whose write is a K: event is claimed in `HandleUIVariableSet` (there is no
  generic Event-combo branch in `MainForm.PanelBuilder`).
- Two-state switches with only a TOGGLE event use the toggle-if-differs idiom
  (`A380ToggleCommand.ShouldFire`): fire only when the pick differs from the live value,
  treat an unknown cached value as differing, and force-read the key when nothing is sent
  so the combo snaps back.
- **Start Engine**: sets the magneto key to START (`MAGNETO1_SET 4`), polls
  `GENERAL ENG COMBUSTION:1`, and returns the key to Both (`MAGNETO1_SET 3`) when
  combustion is true or after a 10 s timeout. Announces "Engine running" or "Engine did
  not start". Serialized (a second press while a start is in flight is ignored), and
  cancelled on aircraft switch / dispose so the key is never left at START. The sequence
  is a pure state machine (`Cessna172EngineStart`) fed by the definition, so its catch,
  timeout and key-return rules are unit-tested.
- Mixture is a `_SET`-keyed entry box (0–100 %), written with `MIXTURE1_SET`
  (0–16383), read back from the lever position percent.

Read-only status blocks (`GetPanelDisplayVariables`), never spoken, excluded from Ctrl+M:

- Engine: RPM, oil pressure, oil temperature, fuel flow, EGT.
- Fuel: left and right tank quantity (gallons).
- Electrical: main bus voltage, battery amps.

The screen-reader rule applies throughout: a panel pick is never announced by the app;
the global `_uiSetEcho` wrap keeps the resulting SimVar change silent.

## 4. Radios and transponder

**Radios panel**

- COM1 / COM2: active-frequency readout (`COM ACTIVE FREQUENCY:n`, rendered
  `000.000 MHz` via `TryGetDisplayOverride`, never a bare "137"), standby entry box keyed
  `COM_STANDBY_FREQUENCY_SET:n` (validated 118.000–136.975, `*1e6`, sent with
  `COM_STBY_RADIO_SET_HZ` / `COM2_STBY_RADIO_SET_HZ`), and a Swap button
  (`COM_STBY_RADIO_SWAP` / `COM2_RADIO_SWAP`). Validation failures are spoken; success is
  not (the frequency change announces itself).
  To be exact: that holds for the ACTIVE frequency. Setting a STANDBY frequency changes
  nothing that announces, so it is silent by design and is read back from the COM standby
  status row (which is why both standby keys are listed as display variables too).
- NAV1 / NAV2: active, standby and OBS course readouts only. Entry goes through the
  existing universal Ctrl+N dialog (`NavRadiosForm`); the definition handles
  `HotkeyAction.SetNavRadios` and applies with `NAV1_RADIO_SET_HZ` / `VOR1_SET` /
  `NAV2_RADIO_SET_HZ` / `VOR2_SET`, as the PMDG 737 and iFly do. No NAV boxes on the
  panel — one way to do it.
- The G1000 mirrors these stock SimVars in both directions (known on FS2020's Working
  Title G1000; test-plan item 1 confirms it on 2024).

**Transponder panel**

- Squawk: entry box keyed exactly `TRANSPONDER_CODE_SET` (so MainForm's BCD path fires),
  read back from `TRANSPONDER CODE:1` with `Units="Bco16"` and rendered as four digits.
- Mode (Off / Standby / Ground / On / Altitude): readout from `TRANSPONDER STATE:1`.
  Read-only first; becomes a combo only if the probe (§8) shows the 2024 G1000 honours a
  stock state-set event.
- Ident button (`XPNDR_IDENT_ON`).
- Altimeter setting: entry box (inHg) written with `KOHLSMAN_SET` (**mb × 16**, the A380's
  convention, not inHg × 16), readout in both units.

Background callouts here: COM active-frequency changes and squawk changes. NAV changes
stay silent (read on demand via the existing NAV readout hotkey).

## 5. Background callouts and Ctrl+M

Every callout is a Continuous + `IsAnnounced` variable, so each earns its own Ctrl+M row.

Switch states, spoken on change: magnetos, master, alternator, both avionics buses, fuel
pump, fuel selector, pitot heat, each light, parking brake, flaps ("Flaps 10",
"Flaps up").

Warnings, edge-triggered, one-shot per excursion, composed in `ProcessSimVarUpdate`:

| Callout | Trigger | Re-arm |
|---|---|---|
| Stall warning (`AnnounceImmediate`) | `STALL WARNING` rising edge | flag falls |
| Overspeed | `OVERSPEED WARNING` rising edge | flag falls |
| Engine stopped | `GENERAL ENG COMBUSTION:1` falls while airborne or ground speed > 5 kt | combustion true |
| Low fuel left / right | tank < 5 gal | tank > 6 gal |
| Low voltage | main bus < 24 V with engine running | > 25 V |
| Oil pressure low / oil temperature high | outside C172 limits | back inside, with hysteresis |

Baseline-first: every tracker seeds silently on first delivery and is wiped on
`OnSimContextReset` (every connection drop and every `AircraftLoaded`), never in
`ResetAnnouncementBaselines` — the MD-11/iFly rule, so loading into a running aircraft
narrates nothing and a reconnect does not eat the next real change.

Status-only rows (RPM, oil, fuel quantity, volts, amps) are `ExcludeFromMonitorManager`
so they never earn a checkbox that mutes nothing.

Not included: turbulence, icing and 1,000-ft callouts (already app-wide), G1000 alert
messages (screen-only, out of scope).

## 6. Guidance numbers

`GetVisualGuidanceProfile()` — starting values; the flare rows are MEASURED on the live
aircraft (test-plan item 6) before they ship:

| Field | A320 | C172 | Basis |
|---|---|---|---|
| ReferenceVrefKnots | 140 | 65 | POH, flaps full |
| TypicalApproachAoaDeg | 6.0 | 5.0 | measure |
| MaxPitchRateDegPerSec | 2.5 | 4.0 | light aircraft |
| MaxBankRateDegPerSec | 3.0 | 6.0 | light aircraft |
| TonePitchRangeDeg | 6 | 10 | wider attitude envelope |
| ToneBankRangeDeg | 5 | 15 | 172 turns at 15–30° |
| GlideslopeAltitudeBiasFt | 60 | 5 | gear close to the ground |
| FlareTriggerWheelHeightFt | 30 | 12 | measure |
| FlareTargetPitchDeg | 6 | 8 | measure |
| FlareAltitudeBiasFt | 12 | 3 | measure |

`TaxiTurnLeadSeconds` = 0.5 (direct nosewheel steering, short wheelbase; sits with the
737s at 0.4, not the Airbuses at 1.6–1.8).

Tone-mapping defaults, hand fly, takeoff assist and the altitude callout are untouched.

## 8. In-sim test plan (run by the repo owner, per the sim-facing rule)

1. COM1 standby set + swap from the panel; tune on the G1000 knob and hear the callout.
2. Squawk set, read back; transponder mode readout.
3. Every switch on every panel: set each position from the app, confirm on the G1000 or
   by ear, confirm the readback follows a hardware change.
4. The three uncertain wirings: standby battery, fuel shutoff (selector Off vs its own
   switch), transponder mode set event. Anything that fails ships read-only or is dropped
   with a note in `docs/c172.md` — never a control that silently does nothing.
5. Engine start from cold and dark with the Start button (catch, and a deliberate no-start
   with mixture cut-off to see the timeout path).
6. A pattern circuit with visual guidance on, to measure the flare numbers in §6.
