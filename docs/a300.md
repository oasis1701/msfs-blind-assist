# iniBuilds A300-600

Aircraft code `INI_A300`, menu item "iniBuilds Airbus A300-600". Community package
`inibuilds-aircraft-a300` (MSFS 2024; built and tested against package 1.0.11). The four
variants (passenger and freighter, GE and PW engines) share one cockpit behaviour file, panel
configuration and code module, so one definition serves all four. Definition:
`MSFSBlindAssist/Aircraft/IniA300Definition*.cs` (+ `Aircraft/A300/`). Control map generator:
`tools/a300-gen/generate_a300_map.py`.

Covered: the switch panels and their lights, the master warning and caution and lever
announcements, the Ctrl+M monitor manager, the aircraft's own checklist, both MCDUs, the FCU,
autopilot and radios with typed values and hotkeys, the input-mode autoflight windows, the tablet,
the display readers (the FMA, the E/WD memos, the status boxes and four AI display reads) and the
flying aids (take-off call-outs, the altitude window, autopilot and autothrottle disconnects).

## How a control is written

Every map-driven row fires the control's own B: event, `value (>B:AIRLINER_<Name>_Set)`, which is
what the cockpit's mouse code calls, through `ExecuteCalculatorCodeUnique` (`A300WritePlan`).
Measured live at a cold-and-dark gate (2026-10-03):

- TWO-POSITION switches (`toggle`, and `command` where the position lives in a separate variable)
  FLIP whatever value the Set event is given; iniBuilds' own `_ON` and `_OFF` bindings flip too.
  So a write is sent only when the current position is known and differs; an unknown position (or a
  value that is none of the switch's positions, such as a valve part way across) is refused aloud
  with the PMDGs' words ("Switch not ready, please try again in a moment."), and what MSFSBA has
  just commanded is trusted for 2.5 s over the 1 Hz cache (`A300CommandedState`), kept per state
  variable: the courier and crew oxygen supply buttons, the dome light switches, the terrain mode
  switches and the autoland light switches each flip one variable through two events of their own.
- Selectors and knobs are absolute: Set n is position n. A knob's state variable is the Set value
  times the map's `scale` (0.1 for the cabin pressure limit and the weather radar gain).
- Hold buttons (`hold`: ECAM page keys, test buttons) are pressed with Set 2 and released with Set
  0 after 250 ms, which reached the ECAM page keys every time. The fire tests are held as long
  as the aircraft's own checklist holds them (`A300WritePlan.TestHoldMs`): 5 s for the APU loop
  test, 3 s for the squib tests. 250 ms never finished one: the APU loop test lights loop A at about
  1.5 s and the fire handle at about 3 s (measured 2026-10-04). The engine loop tests are held 7 s:
  their fire warning (handle light) comes at about 4.4 s and lasts while the button is held, so the
  checklist's 5 s lit the handle about half a second, netted away inside the lights' gather window
  (measured 2026-10-09). The takeoff config, landing gear warning and smoke tests have no
  duration in the checklist and are held 5 s (design decision, 2026-10-09): a 250 ms takeoff config
  press reported nothing even in landing configuration, while a 5 s hold warned at about 3.7 s; the
  gear warning test's master warning came at about 3.5 s and the smoke test's ECAM warning at about
  3.5 s (its master warning at about 6.3 s, measured 2026-10-04). The other test buttons (GPWS, CVR,
  oxygen) still get 250 ms.
- Spring switches (aileron, rudder and yoke pitch trim, the cabin manual V/S switch) are held at
  the chosen side for 1 s and then returned to rest; the aileron trim moved while held and stopped
  at rest. The row is read again once the hold is over (`ReReadAfterSpringAsync`): the hold can fall
  between two 1 Hz deliveries, which then see no change, and the combo kept the side picked.
- The two yoke pitch trim switches are worded the other way round from iniBuilds' tooltips: Set 0
  trims nose UP (measured 2026-10-06, `A:ELEVATOR TRIM POSITION` 0 to +0.55 for a 20 ms press),
  and the aircraft's own `AP::Update` calls its trim-up handler for 0 and trim-down for 2 on both
  yokes. So their rows read "Up, Neutral, Down" (`PositionOverrides`). They trim fast: about 1.6
  degrees for a 100 ms press, about 5 degrees for the 1 s spring hold.
- Encoders (knobs that only turn) are an "increase" and a "decrease" button, Set +1 and Set -1.
- The flaps lever, ground spoiler arm and speed brake are hand-written (`A300Levers`) with the
  stock events the A300 takes: `K:FLAPS_SET` with index x 4096 (`A:FLAPS HANDLE INDEX` 0 to 4),
  `K:SPOILERS_ARM_SET` (read back from `L:INI_SPOILERS_ARMED`; the stock armed flag stays 0), and
  `K:SPOILERS_SET` 0 to 16384 (read back from `L:INI_SPOILERS_HANDLE_POSITION`, 0 to 1). Measured
  2026-10-13: the handle read exactly 0, 0.5 and 1 after `K:SPOILERS_SET` 0, 8192 and 16384, never an
  in-between value, so the speed brake slider follows every delivery and needs no detent filter.
- External power, the gear lever and the parking brake fire their own Set event and are read
  from the stock variables (`A:EXTERNAL POWER ON:1`, `A:GEAR HANDLE POSITION`,
  `A:BRAKE PARKING POSITION`).
- Every write is refused aloud ("{name} unavailable") when `CalcWriteCanLand` is false, and the
  row's value is asked for again so its combo goes back.
- A toggle, command or selector pick is read back after `ToggleReadBackMs` (`CheckMovedAsync`). If
  the aircraft did not move it (the crossbleed button acts only in manual mode), the row is read again
  so its combo goes back, the position it stayed in is trusted over the pick (`A300CommandedState`),
  and it is said once, as the MD-11 and the iFly 737 say it: "Crossbleed did not move". Only the
  row's latest pick speaks, and a reading that is none of the switch's positions (a valve part way
  across) is neither said nor remembered. A knob always sends its
  value: its row is read only when the panel opens, so a step back to the opening value once read as
  already there and sent nothing. The A300 registers
  `MSFSBA_BRIDGE_PROBE`, so a missing MobiFlight WASM module is reported by the calc-path probe.
- Guard covers only move the 3D model, so they are not rows. The two cargo smoke agent guards
  are real switches: the agent switch springs back to off while its guard reads 0 (read from the
  aircraft's own click code), so they are rows, worded Closed and Open, placed just before their
  switch.

## The generated control map

`MSFSBlindAssist/Resources/a300_control_map.json` is GENERATED by `tools/a300-gen` from the
aircraft's compiled cockpit behaviour file and its `en-US.locPak` tooltips, and shipped as an
embedded resource. Never hand-edit it. After an iniBuilds update:

```bash
git show HEAD:MSFSBlindAssist/Resources/a300_control_map.json > old_a300_map.json
```

```bash
python tools/a300-gen/generate_a300_map.py --package "<Community folder>\inibuilds-aircraft-a300"
```

```bash
python tools/a300-gen/diff_maps.py old_a300_map.json MSFSBlindAssist/Resources/a300_control_map.json
```

`convert_checklist.py` rebuilds `Checklists/iniBuilds_A300_Checklist.txt` from the aircraft's own
checklist the same way. iniBuilds' files and any decoded copy of them stay out of the repo; the
generator's tests run against small fixtures in the same format.

## Panels

`A300PanelLayout` is the only source of panels ([A300-3]). Which section and panel a control belongs
to follows the component tree iniBuilds grouped the cockpit by, so an update is picked up by
regenerating the map, except where iniBuilds groups by place and the fleet's Airbuses by system:
there `ControlPanels` (`A300PanelLayout.Systems.cs`) sends each control to its system's panel and
`PanelSections` puts that panel in its section (design decision, 2026-10-09, after comparing the FBW
A320, A330 and A380, the Fenix and iniBuilds' A300 manual):
- Sections are the FBW Airbuses': Overhead, Glareshield, Instrument (was "Main Panel"), Pedestal,
  plus the A300's Displays, Cockpit and Cargo.
- The overhead lights panel is Signs, Interior Lighting and Exterior Lighting; the bleed panel is
  Bleed and Air Conditioning; Cargo Smoke leaves Fire.
- The main instrument panel is Warnings (both pilots' master warning and caution), Gear (with the
  gravity extension handle), Autobrake, Thrust Rating Panel, Landing Elevation, Standby Instruments,
  Source Switching, Clock, GPWS (with the pedestal's GPWS landing flaps switch), Captain Side and
  First Officer Side.
- The throttle quadrant is Engines (the fuel levers), Thrust Levers (with TOGA, which iniBuilds puts
  on the captain's EFIS panel), Flaps and Speed Brake, and Parking Brake; its cancel buttons and the
  takeoff config test join the ECAM Control Panel.
- The fleet's names: Pressurization, EFIS Captain and First Officer, Transponder, Audio Control Panel
  Captain and First Officer, Recorder. The manual's where the A300 differs: IRS (not ADIRS), Flight
  Controls (spoilers, pitch feel, rudder travel limiters; no flight control computers), SAS Control
  (the manual's "SAS control panel": pitch trim, yaw damper and autothrottle levers), Thrust Rating
  Panel, and separate VHF, Navigation and ADF radio panels (no RMP).
- Window and Probe Heat and the landing elevation knob stay where the A300 has them (design decision, same day).
- Rows both sides share a panel with say their side first ("Captain chrono").

The order is set in `A300PanelLayout.Order.cs`: `PanelOrder` is the FBW A320's order where the A300
has the same panel. Within each panel the rows follow the aircraft's own checklist (design decision,
2026-10-10): `tools/a300-gen` writes each control's first checklist step into the map (`checklist`),
counting the live checkpoints of `Airbus_A300_Checklist.xml` and naming a control by the cockpit part a
step points at, a variable it tests or sets, or an event it fires; 161 controls are named. The named
rows come first by step; a row inside a group one step names stays in it (the ADF transfer buttons);
`LeadRows` still opens Electrical on the batteries, external power and generators, Warnings on the
captain's buttons, Gear on the lever, Engines on the fuel levers and Flaps and Speed Brake on the flaps.
Every other row keeps the cockpit file's order, and a panel or row the lists do not name keeps its
place after the listed ones, so nothing an iniBuilds update adds is dropped; `A300PanelLayoutTests`
pins each section's panels and where each split control lands. The pedestal's radio and audio group
(iniBuilds' "STD") is split by what each control is: VHF radios, ADF radios, transponder, weather
radar, the captain's and first officer's audio control panels.
Left out: guard covers, the IDC's copies of the radio panel (the same variables), cosmetic parts,
and duplicate buttons that fire the same event. The main cargo door switch was left out too, as if the
145 and 70 degree buttons drove the door; they only pick how far it opens, and the switch moves it (see
"Cargo door").

Names come from `A300PanelLayout.Names.cs` where iniBuilds' titles repeat or are wrong ("BATTERY"
three times, "ALTITUDE KNOB" on the vertical speed knob, "CPT BAROMETER" on the first officer's),
from one rule for the audio panels ("VHF 1 receiver", "VHF 1 volume", "VHF 1 transmit"), and
otherwise from the tooltip title through `SpokenWord`. Position words come from the tooltips too,
except where `PositionOverrides` replaces a code, a blank or a wrong word: the pack mode buttons'
tooltips say OFF and ON, but 0 is automatic and 1 manual (measured 2026-10-04 on the ground: in 1 pack
1's outlet followed its manual temperature switch, in 0 it did not), so they read Auto and Manual.

**Autobrake** (Autobrake panel; read from the aircraft's code, 1.0.11; [A300-20]). The LO, MED and MAX
buttons show their lamp, as the FCU buttons do: "Autobrake low: Armed" while
`INI_AUTOBRAKE_LEVEL` is that level (1, 2, 3; 0 off), "Decel" while its DECEL light
(`INI_AUTOBRAKE_LOW/MED/HI_DECEL`) is lit, else "Off". `INI_autobrake_armed` is not used: only the
buttons write it, so the aircraft's own disarm (the gear handle leaving down) leaves it at 1.
Pressing the active level disarms it, by the aircraft's design, and is not blocked. Any other level
arms only with the gear handle down, green hydraulics at 2,200 psi or more and no autobrake fault.
A press says nothing about its own button's armed light: the screen reader reads the relabeled
button, so, as for every light-labeled A300 button, the light is left to the label for
`PressedLampMs` ([CORE-7], design decision, 2026-10-13); pressing the active level to disarm it says
nothing either. The other lights are spoken as they change, through the same path as the fault lights
([A300-23]): "Autobrake max armed light on" when the aircraft arms it without a press, "Autobrake low
armed light off" when a press of another level puts it out, "Autobrake low decel light on". A press the
aircraft refuses changes no light, so nothing is said. An armed light is not decided until its DECEL
light has been read (an unread input sets no baseline), while a button's label reads an unread DECEL as
"Armed". Both segments are on AC light power, so a button reads "Off" on a dark AC bus, as its lamp
does. The level and the DECEL lights stream on their own subscriptions (`A300Autobrake`); the level's
Ctrl+M row ("Autobrake armed lights") mutes the three armed lights, and each DECEL light has its own.

**Lights as the cockpit shows them** ([A300-23], `A300LampBoard`). In the aircraft's emissive code
every lamp is its state, times its bus's light power: `INI_DC_LIGHTS_FAILURE` (battery on, or the AC
emergency bus powered) or `INI_AC_LIGHTS_FAILURE` (the AC essential bus powered), 1 = powered. The
brightness (`INI_GENERAL_LIGHT_MULTIPLIER`) is 1 or 10 and never a power term, and the annunciator
test term is left out. So a light is spoken, and its status box reads On, only while it is lit: a
fault set or cleared on a dark bus says nothing (switching the aircraft off used to read a list of
lights "on" as the systems lost power), power coming on speaks the lights that light, and power
going off speaks the lit ones going out. Each of the 55 fault lights names its bus (26 AC, 29 DC);
a light lit by a power change still honours its own Ctrl+M row.

**When a light change is spoken** ([A300-24], `A300LampSpeech`). At the first batch end once it is
due, as one sentence, netted per light: a light that went on and back off since the last sentence
says nothing. A light's first change since the last sentence waits `GatherMs` (1.5 s) from its own
arrival, so a light power flag still on its way nets with it (on external power off a fault arrived a
second before the AC light power flag and was said on, then off); a further change of a light already
waiting adds no wait, so a light flashing through a power settle cannot keep the sentence back. A
change that is not spoken (muted, a pressed button's own light) still makes
the speech `Forget` that light, dropping its earlier held or pending change, so a stale opposite is
never spoken (pressing ECAM HYD then ENG within the off hold used to say "Engine page light off"
while it was lit). After either bus's light power changes, the sentence waits `SettleMs` (2.5 s), because
the power flag and the fault flags reach MSFSBA on separate once-a-second subscriptions: measured on
external power, the cabin regulator 2 fault cleared half a second before the AC light power rose,
MSFSBA heard the power first, and said the light on and a second later off. A power change still
speaks every light it lights or darkens, as the Fenix does, once the power has settled; in a live
comparison of four power steps that cut 13 announcements to 9 and removed every on-then-off pair.

**Flashing lights** ([A300-28]). A light going dark is spoken only once it has stayed dark
`OffHoldMs` (3 s), and a light lighting again inside that time says nothing, as the iFly 737 does
(design decision, 2026-10-10): a flashing light reads as one "on", and "off" once it stops; a light that
blinks once says "on", then "off". An off that comes with a power change is not held: it nets in
the power's own sentence. The autoland warning
light flashes about 0.6 s on and 0.6 s off; sampled once a second that looked like about 3 s on and
3 s off, so it streams every change.

**Lights read through their own rule** ([A300-25], `A300PanelLamps`, `A300LampRule`). Most cockpit
lamps are not one variable times power: external power AVAIL is ground power available AND external
power not on (no power term), the gear greens are the stock gear position at 100 percent, and many
light while a variable is clear. So `tools/a300-gen` copies all 496 annunciator lamps' own rules
from the emissive code into the map's `lamps`, and `A300LampRule` evaluates them (only the operators
the lamps use; every shipped lamp is pinned to parse). `A300PanelLamps` names the ones a pilot reads,
panel by panel: button, legend, "light". OFF and ON legends that mirror a
switch are left out. Each named lamp streams its rule's first variable on its own subscription,
which carries its Ctrl+M row and status box line; the rule's other variables stream once under
`A300_IN_` keys. Electrical so far: external power available, AC bus 1 and 2 off, AC essential bus
off, AC emergency bus on inverter, DC normal bus off, DC essential bus on battery, IDG 1 and 2
disconnected, override supply 1 and 2 flow. IRS: each IRS's align, on battery, battery fault and
fault lights; iniBuilds' second and third mode panel nodes read IRS 3 and IRS 2, in another order,
so each light is named from the IRS its rule reads. Fire: the three fire handle lights and each agent
button's SQUIB legend; the DISCH legend is the agent row's own position, read "Discharged". Pulling a
handle does not light the squibs in this aircraft; the squib test does. Fuel: the 12 pump low pressure
lights and the trim tank isolation valve flow bar (iniBuilds wires the left center pump's LO PR lamp to
the right inner pump 1's flag, read as it lights); the four tank isolation valves' bars follow their
switches at once, so they are left out. Air Conditioning: the two pack flow bars (the pack valves,
which close with no bleed air while their buttons stay on) and the ram air valve open light; the
bleed and hot air fault legends are never written by the aircraft. Bleed: the ground bleed valve
light, an indicator with no button named from its node, which follows the APU bleed (the APU bleed
button has no lamp). Ventilation: none (its fault legends are never written). Pressurization: the two system
buttons pick one system or the other (a press of the picked one does nothing), so they are buttons
(`A300PanelLayout.ButtonRows`, a press is Set 1) labelled by their own lights
(`A300PanelLamps.ByButton`), which also speak a press and an automatic change. Cockpit Door: the
door open light (the door button's own lamps are wired to the ground cooling control's variables,
so they are left out). Cargo Smoke: the three main deck smoke lights and each detector's lit legend
(named from its button); the smoke test lights all nine while held. Engine Start: each engine's
start valve open light (the manual's blue OPEN light, out at about 49 percent N2) and starter armed
light. EFIS: each side's map filter (constraints, waypoints, VORs, NDBs, airports), FPA, decision
height and ATC message buttons are labelled by their own lights (the filters pick one at a time, FPA
and decision height one or the other), and each side's stop rudder input light; the stop rudder
input test switch resets itself, so it is a button too (`ButtonRows`). Gear: each gear's green down
light (the overhead gear panel's), unlocked and door open lights (the main panel's; the overhead
repeats them); stock gear index 0 is the nose, 1 left, 2 right, and iniBuilds' GEAR1 the nose and GEAR2
the left. The gravity extension handle's own event only pulls it; Stowed fires its stow clickspot
(`PositionEvent`). Flaps and Speed Brake: the speed brake light. Autobrake: the autobrake and brake
fail indicators (named from their nodes), the brakes hot light, and the brake gauge's accumulator
and brake pressures as readouts ("PSI x 1000"). Source Switching: each switching button carries both
pilots' legends, crossed; each pilot's own legend labels their button. A light-labelled button's own
light is not spoken for `PressedLampMs` after MSFSBA presses it: the screen reader reads the focused
button's new label ([CORE-7]); the other lights it changes still speak. The battery buttons' upper
legend follows the charge current (measured in flight, 2026-10-06), so it is the "battery charge
light" (design decision, 2026-10-09).

**System values in the panel boxes** (`A300DisplayPanels.SystemLines`, design decision 2026-10-09,
as the FBW A320's panels carry their system's values). A system panel's status box lists its lights,
then its ECAM page's values (Electrical: the AC and DC pages; APU: the APU page; Hydraulics: the
three pressures; Fuel: the tanks and total in the tablet's unit, so the pounds-only total readout,
which the fuel hotkey uses, is not repeated there; Air Conditioning: the compartment temperatures;
Bleed: the ECAM bleed page; Pressurization: cabin altitude and differential pressure; Engine Start:
the engine instruments and the ECAM engine page, what a start is flown on); the Displays section keeps the
ECAM pages. A panel with gauges and no ECAM page carries its gauges as readouts (`A300Readouts`, by
panel): Oxygen reads its six needles from their animation code, the LP faces in psi and the HP faces
"PSI x 1000" (the gauge face texture). iniBuilds' `INI_OXYGEN_HIGH_PRESSURE_CURRENT` is the courier
LOW pressure gauge: it rises with the courier supply (live, 2026-10-09).

**Rows that share a variable.** iniBuilds wires the oxygen panel's third button (node `PAX_OXY_SUPPLY`,
tooltip "CREW OXYGEN SUPPLY", so "Crew oxygen supply") to the courier supply's variable, in both
variants. A row whose variable another row already carries on the batch streams on its own
subscription ([VAR-7]); read only at panel open, it went stale after the other row's write and its
next pick was planned from the old position (`Every_position_row_follows_the_cockpit_live`).

The standby instruments are one panel, Standby Instruments in the Instrument section
(the fleet's ISIS): its knob, its cage and its readings. MainForm keys a panel by its name alone, so
no name may be in two sections (`No_panel_name_is_in_two_sections`).

**Clocks** (`A300Clock`, measured 2026-10-10). The Clock box reads each clock's GMT time, composed
from its own digit variables (`INI_CLOCK_GMT_HOURS1` and so on, which follow the clock's mode), its
chrono (`INI_CHRONO_TIME`, seconds) and its elapsed time (`INI_ET_TIME`, seconds, shown in hours and
minutes). The chrono button cycles reset, running, stopped; the elapsed time button toggles running
and stopped, restarting from zero, so it is a button (`ButtonRows`); both are labelled by their state.
The landing elevation knob reads its value back after a step (`A300Readouts.KnobReadBacks`).

**Trim and flaps** (`A300Trim`, measured 2026-10-10). The Trim box reads the pitch trim from the stock
`ELEVATOR TRIM POSITION` ("1.1 degrees nose up") and the rudder trim as its display shows it: a side
digit (`INI_RUDDER_TRIM_DISPLAY0`, 0 L, 1 blank, 2 R), two digits (`DISPLAY1`, `DISPLAY2`) and the
tenths (`DISPLAY3`), so "left 2.8"; the reset button is labelled by its own light, on while the trim
runs back to zero. The Flaps and Speed Brake box reads the slat and flap angles from the stock
`LEADING EDGE FLAPS LEFT ANGLE` and `TRAILING EDGE FLAPS LEFT ANGLE`, in degrees through each move
(15/15 reads 15 and 15, 30/40 reads 30 and 40). The Thrust Levers panel carries each engine's reverser
unlocked and deployed lights (`INDICATOR_REV1/2`, `INDICATOR_REVLK1/2`).

**ECAM control panel** (measured 2026-10-10). Each page button's light (`ECAM_*_SEQ2`) is lit while
`INI_ecam_active_page` is its page and `ECAM_CURRENT_STATUS` is not 0 (1 a page picked, 2 the automatic
page), so the lit button names the page the lower ECAM shows; it labels its button (`ByButton`). A press
of the lit button goes back to the automatic page. The CLR button is labelled by the ECAM clear fault
light (`INI_ECAM_CLR_LIGHT`).

**Weather radar and transponder** (measured 2026-10-10). The Weather Radar box reads the antenna tilt
`INI_WXR_TILT` in degrees (the tilt knob's 0 to 100 is 15 down to 15 up). The Transponder box reads
`TRANSPONDER CODE:1` as BCO16, as the FBW A320 and A380 do, and a code knob step reads it back
(`KnobReadBacks`): the large knob steps the first two digits, the small knob the last two.

**VHF and ADF windows** (`A300Radios`, measured 2026-10-10). Each VHF and ADF panel has two windows
(`INI_COM1_FREQUENCY` and `INI_COM1_STBY_FREQUENCY`, kilohertz; `INI_ADF1_FREQUENCY` and `_STBY_`)
and a transfer switch that PICKS the window in use; it does not swap them. The VHF switch at 0 uses the
first window, the ADF switch at 1 (their window lights `CPT_COMM1_LX` and `CPT_ADF1_LX` agree). So a
knob iniBuilds calls "standby" tunes the frequency in use after a transfer: each status line and
read-back names a window by its role now, from the transfer switch, never by the knob's name. The
values are read together (`ReadBackWhenSettledAsync`): read one after another, a read-back came 3 s
after the press. The ADF bearing line is `ADF RADIAL` (relative) while `ADF SIGNAL` is not 0. The
Navigation Radios box reads NAV 1, 2 and 3 and its knobs read back; the VOR frequency knobs changed
nothing at the gate, the aircraft's WASM autotunes the VORs (`INI_autotune`). Each audio panel's
VHF transmit key is labelled by its light (`XMLVAR_COM_PANEL1/2_Transmit_Channel` 0, 1, 2); the `_IDC`
copies of those lights belong to no placed panel and are left out.

**Cargo door** (`A300CargoDoor`, measured 2026-10-10). The 70 and 145 degree buttons pick how far the
main cargo door opens (`A300_MAIN_CARGO_DOOR_70`/`_145`, which label them "Selected"); the door switch
moves it only while held, and it stops by itself at the picked angle or locked: 70 degrees took about
20 s, 145 to locked about 30 s. So MSFSBA holds the switch 35 s (`A300WritePlan.SpringHolds`), a pick of
Neutral stops it, and when the hold ends the door says where it stopped ("Cargo door open 70 degrees").
The box line is composed from `INI_MAIN_CARGO_DOOR` (travel: 0.7 at 70 degrees, 1 at 145) and its
closed, locked, 70 and 145 flags. The ECAM shows the doors page by itself while the door is open. The
three cargo light buttons write a command the aircraft consumes; no state is readable.

**Thrust rating panel** (Thrust Rating Panel; read from the aircraft's code, 1.0.11; [A300-21]). Each TRP
button shows its lamp, `INI_TRP_MODE` == its number: 1 TOGA, 2 MCT, 3 CL, 4 CR, 5 AUTO, 6 FLEX TO
("TRP climb: On"). In AUTO the mode stays 5 and `INI_TRP_AUTO_MODE` holds the limit the aircraft
chose (1 TOGA, 3 climb, 4 cruise), so only the AUTO button reads On. The panel's status box
has a TRP line: the mode, AUTO's limit or the flex temperature, and the N1 limit
(`INI_THRUST_MAXIMUM_N1`) on GE engines: "TRP: AUTO, climb, N1 limit 95.3 percent", "TRP: FLEX, 45
degrees, N1 limit 92.1 percent". PW engines (`INI_IS_PW`) show EPR on the TRP, so their line has
no N1 limit. The flex temperature knob's increase and decrease are read back once the step lands
("Flex temperature 46 degrees"); `INI_FLEX_TEMPERATURE` is the FMS's value, copied every update,
so it cannot be written directly. Not modelled: the TRP shows dashes in FLEX while the flex
temperature is below the outside temperature (`TRP::Draw`), and the line still reads the number.

## Announcements

Spoken from `ProcessSimVarUpdate`, inside MainForm's mute and echo wrap (`DefAnnounceMuteSets`
lists `INI_A300`): the master warning and master caution as they come ON only (pressing the light
writes 0 to the same variable, so speaking it going out would echo the pilot's own press), and
the flaps lever, ground spoiler arm, gear lever and parking brake when something else moves them.
Every other switch position is consumed silently; its combo follows the cockpit. A context reset
wipes the baselines and `Md11SeedGate` decides when the unchanged ones are seeded from the cache.
The flying aids (fault lights, take-off call-outs, engagement, the altitude window) are below.

## MCDUs

`FMGS::Draw()` publishes each MCDU's character grid to a SimConnect client data area,
`iniAirbusMCDU_1` (captain) and `iniAirbusMCDU_2` (first officer): 14 rows x 24 columns x 3 bytes
(character, colour, small-font flag), 1008 bytes, only while `L:INI_MCDU_OPTION` is 1 (the
tablet's External Hardware → MCDU Export). The option does NOT survive a flight load (it read 0
after one) and reads null until MSFSBA first writes it, so the definition keeps it on
(`EnsureMcduExport`): it remembers whether the option is on for this connection and flight, sends
`1 (>L:INI_MCDU_OPTION)` when it is not, and forgets on a disconnect, a flight load or a send that
could not land (before the sim connects, say). The MCDU window sends it every time it opens,
whatever is remembered. With the option off the area keeps its last content; an unpowered MCDU is
cleared to spaces.

**Annunciators** (`A300McduLights`, 2026-10-10). Each MCDU's four lamps, MSG, FAIL, DSPY and OFST (the
cockpit's `CPT_FMS_*_LIGHT`/`FO_FMS_*_LIGHT`: `INI_FMS1/2_message_light`, `_fail_light`, `_display_light`,
`_offset_light`, on the AC light bus), are shown in the window's status box ("Captain MCDU: MSG") and one
coming on is spoken while the window is open, as the MD-11's MCDU window does with the same legends: MSG
lighting has no text change behind it. A unit switch or a re-show takes them silently. The captain's MSG
is the exception (design decision, 2026-10-13): it is also a fault light, spoken anywhere ("MCDU message
light on"), so the window leaves it to the light rather than say it twice. FAIL, DSPY, OFST and the first
officer's MSG, which has no fault light, are still spoken by the window.

**IRS alignment** (`A300IrsAlignment`, measured 2026-10-10). A selector in NAV sets `INI_IRSn_IS_ALIGNING`
with `INI_IRSn_TIME_REMAIN` at 0 until ALIGN IRS is pressed on INIT A (right key 4), which `FMS_Init::draw`
offers once all three selectors are in NAV and the route has a FROM/TO; the time then counts down from
about 180 s, and the IRS reads `INI_IRSn_ALIGNED` 1. The IRS box reads each: "aligning, 2 minutes 27
seconds left", "waiting for ALIGN IRS on the MCDU", "aligned" or "off". The pitch trim levers drop while
the IRSs are unaligned.

The FMS also publishes an all-blank frame of 70 to 370 ms on every page key (measured in flight,
2026-10-04: 60 of 363 frames during four key presses), so a blank frame is not news. As in the MD-11 window
(`Md11McduPresence`), `A300McduBlankClocks` (one clock per unit; the window follows the selected
unit's) holds the page and the cursor through a blank and shows "is blank. It may be unpowered."
only once the blank has lasted 1 s; a window that opens or switches unit onto a blank it cannot judge
yet shows "waiting for data" until it can.

`A300McduDataManager` follows the MD-11 MCDU manager's lifecycle: one per SimConnect connection
(created or reused in `InitializePMDG`, ended by `Disconnect` and the drop path), a registration
that resumes after its last completed step, and per MCDU an ON_SET + CHANGED subscription PLUS a
one-time snapshot on its own request id (the subscription is handed only later writes).

Characters are read as the aircraft's MCDU fonts (INI_CDUA / INI_CDUB) draw them, decoded from the
glyph outlines (`A300McduText.Glyph`): `!` is an empty entry box (read as `#`), `^` the degree
sign, `a`/`l` a left arrow and `b`/`r` a right arrow (the "more pages" arrow beside a title),
`{`/`}` up and down arrows, `~` a delta; every other lowercase letter is drawn as its capital.

Keys are the cockpit's own L:vars, `INI_MCDU1_<KEY>` / `INI_MCDU2_<KEY>`: 1, held 80 ms, 0, then 80
ms before the next, through ONE queue in the definition (`PressMcduKeys`). Measured live: 40 ms
press and gap typed eight letters without a miss; a press and release in one calculator string
did not register. INIT B (read from the FMS code, 1.0.11): the zero fuel weight is right line key 2 (`FMS_Init::onKeyLSK2R`,
with FORMAT ERROR and ENTRY OUT OF RANGE checks); the take-off weight on right line key 3 is
computed, and `onKeyLSK3R` only ever posts NOT ALLOWED. The MCDU's SimBrief uplink (Menu, ACARS)
reads the route, alternate, cruise level, flight ID, cost index and winds, never the weights. The
hotkey guide says so. The cockpit MCDU has no PREV, DATA, PERF, FUEL, RADNAV, AIRPORT or ATC key:
the WASM and the key-click sounds name `INI_MCDU1_*`/`_2_*` variables for them, but no cockpit
button writes them (the behaviour file writes only the keys in `A300McduKeys`), so the window's
page keys are every page key the cockpit has, and adding those would be a route the cockpit lacks.

`SPACE` works though no cockpit button writes it. CLR deletes one character per
press, and a CLR on an EMPTY scratchpad puts "CLR" into it, so the window's clear-all re-reads the
screen after each press and stops the moment it reads empty.

## FCU, autopilot and radios

`A300TypedValues` holds every typed value and how it is written, each measured live
(2026-10-03): the FCU windows are their own L:vars (`INI_Airspeed_Dial`, `INI_HEADING_DIAL`,
`INI_Altitude_Dial`, `INI_vvi_dial`), which moved the autopilot's stock targets; the knobs stop at
100-399 knots, Mach 0.10-0.99, altitude 49,000 and vertical speed ±6,000, and heading wraps.
In Mach mode (`INI_Airspeed_is_mach`) the same speed variable holds the Mach number. A typed
value in the other unit presses SPD/MACH and WAITS before writing: the aircraft applies the
switch a moment later and converts what the variable holds then (a value written in the same
string came out as Mach 0.15). Whether to switch is decided from the mode MSFSBA last commanded
(2.5 s, the 1 Hz cache lags it), so a second entry, or a speed typed just after the SPD/MACH
button, does not flip it back; typed speeds go out one after another. VOR 1, VOR 2 and ILS
frequencies are written as their `_MHZ` and `_KHZ` parts (the combined value and the stock NAV
radio are rebuilt from them, so writing either is undone); VOR courses use
`K:VOR1_SET`/`K:VOR2_SET`, the ILS course `L:INI_ils_course`. VHF standby uses the stock set
events, the squawk `K:XPNDR_SET`, the altimeters `index value (>K:2:KOHLSMAN_SET)` (index first;
value first does nothing).

A typed altitude, vertical speed or decision height must be a whole number (PR #300 review,
2026-10-13). Both ways of typing a value (a panel's box and the value boxes) turn a comma into a
point, so "-1,500", the thousands separator the box's own hint showed, arrived as -1.5, rounded to
0 and was written and confirmed as "Vertical speed 0 feet per minute"; "1,200" became a decision
height of 1 foot. A number with a fraction is refused now (`A300TypedValues.WholeNumberError`:
"type a whole number, without a thousands separator"), and so is a non-zero vertical speed under 100,
as the MD-11 and the FBW A320 refuse it (0 stays valid: level off). The hints and errors write 49000,
6000 and 2500 with no separator, and the value box speaks the plan's own refusal rather than its
range (`ValidateBoxInput`), so "-1,500" is never answered with a range it is inside. A typed
altimeter setting is confirmed as the value written, in sixteenths of a hectopascal
(`Math.Round(mb * 16) / 16`): 29.90 inches is 1012.53 hectopascals but is stored as 1012.5 and read
back as 1012, and the confirmation said 1013 (about 3% of the inch entries were a hectopascal out).

The altimeter key (B) speaks every other aircraft's words (the MD-11, Fenix, FBW Airbuses, PMDGs
and iFly): "Altimeter standard" while the captain's side reads STD, else "Altimeter: 1018, 30.06",
hectopascals then inches (`A300Readouts.AltimeterReading`). The STD flag is the side's own
once-a-second stream (`A300Baro.Captain.ModeKey`), read from the cache; a mode not read yet leaves
the numbers. STD is a flag only on this aircraft ([A300-16]), so a side in STD reads "standard"
whatever its setting says. It used to say "Altimeter 1013 hectopascals, 29.92 inches" and never
"standard". F and Shift+F say "Fuel 12,345 pounds" and "Fuel 5,600 kilograms" (`A300Readouts.Fuel`).

The FCU mode buttons show their own lamps (`A300FcuState`: `INI_MCU_*_LIGHT`, `INI_AT_ON`,
`INI_CWS_on`, `INI_Airspeed_is_mach`), registered on the batch, consumed silently and shown only on
the button label through `TryDescribeControlState`. The flight mode annunciator is read by the
display readers below.

## Autoflight windows

The input-mode windows match the fleet's value-box pattern, the PMDG's and the MD-11's:

- **Ctrl+S, Ctrl+H, Ctrl+A and Ctrl+V** each open the FCU value box for that window. It holds the
  typed field plus that knob's push and pull and its mode buttons, with their lamps.
  - Speed: Speed Mach.
  - Heading: Heading select and NAV.
  - Altitude: Altitude hold, Level change and Profile.
  - Labels are the panel names plus iniBuilds' own words for each knob action ("Heading knob push,
    aircraft heading"; altitude knob push is "switch 100/1000").
  - A lamp button reads its result back; a knob push or pull says nothing, because the FMA call-out
    speaks the mode change.
  - Opening another box closes the open one.
- **Ctrl+B** sets all three altimeters from one typed value. The field is named with both units
  ("altimeter setting in inches or hectopascals"). One mode button ([A300-22]) shows the modes the
  aircraft reports, "Altimeter mode: QNH" or "STD", or each side while they differ ("captain STD,
  first officer QNH"), as the FBW A320 window's Mode control does.
  - A press runs STD when both sides read QNH, and QNH otherwise, so sides that differ both end in
    QNH (a design decision; the FBW A320 reads one side only).
  - In this version the aircraft's own STD pull only raises the STD flag; the altimeter keeps
    reading against the old setting (measured 2026-10-05).
  - So STD also sets all three to 1013, and QNH puts back the setting the aircraft saved when the
    knob was pulled.
  - Both read the three settings back.
  - A typed value with a side in STD first pushes that side to QNH and confirms it, then writes and
    confirms as before; a side that stays in STD is named and nothing is written. In flight
    (2026-10-06) a value typed in STD reached only the standby.
  - The Altimeter setting boxes on the Captain Side and First Officer Side panels do the same for
    their one side: a side reading STD is pushed to QNH and confirmed before the value is written
    (the other side is left alone), and a running sequence or an unread mode is refused aloud. The
    standby altimeter's box has no STD and writes at once.
- **Ctrl+N** tunes VOR 1, VOR 2 and the ILS, frequency and course. The ILS is a separate radio on
  the A300 (NAV 3).
  - The window opens on what the radios report, read when the key is pressed. If the NAV radios,
    the ILS frequency or the ILS course are not reported, nothing opens and you hear "NAV radios
    unavailable", so the window never shows made-up values. A radio that reads 0 (unpowered) opens
    on its band's lowest frequency (108.00 for the VORs, 108.10 for the ILS) and course 0.
  - Set writes only the fields changed since the window opened, so retuning VOR 1 leaves VOR 2 and
    the ILS as they are, and confirms just those; it says "NAV radios unchanged" when none changed.
    A field left on the value it opened with is not written, so to tune a radio that read 0 to
    exactly its lowest frequency, set another frequency first, then that one.
- **Ctrl+P** opens the autopilot window.
  - First, a status list: the four FCU windows, the FMA columns and the autopilot.
  - Then: Autopilot 1 and 2, CWS, VOR LOC, Land, the FCU autothrottle button, the two overhead
    autothrottle switches, the autopilot and autothrottle disconnects, TOGA and the bank limit,
    each showing its state.
  - Then the two flight director selectors.
  - Nothing is spoken on a press; errors are.

## Tablet

The tablet is the Coherent view "VCockpit18 - iniEfbA300", a Bootstrap-styled page with a real DOM,
read by `Resources/coherent-a300-efb-agent.js` through the shared `CoherentPmdgEfbClient`
(`ForA300`) and `FbwEfbForm` (Shift+T), the MD-11's arrangement. The agent walks the visible page:
buttons (`button`, `input[type=button]`, `.is-button`), fields labelled by their row's
`.flight-value-title`/`.ini-input-label` or the heading above them (unit from `.input-group-text`),
Bootstrap radio groups (`input.btn-check` + `label.btn[for]`) as ONE choice control each, range
inputs as sliders, headings and text. Measured live (2026-10-03):

- A press is ONE click: pointerdown, mousedown, pointerup, mouseup, click. A bare `el.click()` did
  nothing (the unlock button ignored it).
- The tablet wires its controls with `element.onclick`, and two of them hang it on the picture
  INSIDE the control: Unlock (`LockComponent` sets it on the first `.home-button`, the unlock
  image) and the header's gear (`#control-box-button-icon`, not `#control-box-button`). A press
  dispatched on the control itself never reaches either, which is why pressing Unlock did nothing
  (2026-10-04). So `A.pressTarget` sends the press where a finger on the control's centre would
  land: the topmost element there (`elementFromPoint`) when it is inside the control, else the
  first element inside the control with an onclick of its own, else the control. Events bubble,
  so a handler on the control itself still runs once. Never go back to dispatching on the stamped
  element alone.
- The page container is 2048 x 0 (its pages are positioned absolutely), so visibility cannot
  require a non-zero size on a container.
- Door state is in the classes (`door-open`, `door-transit`, else closed); slide state is the
  button's colour (red armed, green disarmed, the page's own legend). Automatic door arming is a
  tablet setting, on by default, which is why arming by hand did nothing at the gate.
- Never `focus()` a field: the tablet's on-screen keyboard opens over the page. Setting the value
  and firing input/change/keyup/blur is enough (Take Off's OAT took a typed 15).
- Password fields (Hoppie, SayIntentions) only report whether they are set.
- The SimBrief field (Settings, Third Party Settings) is the numeric SimBrief **Pilot ID**: the
  tablet fetches `xml.fetcher.php?userid=`, so a user name never loads a plan. The box is read as
  "SimBrief Pilot ID, numbers only" (its only label on the page is the heading "SimBrief").
- Messages are notie alerts appended to the body (`.notie-container`, text in
  `.notie-textbox-inner`); the tablet only ever calls `notie.alert`. They are emitted first, as
  `kind: 'alert'`, which the shell speaks once per appearance.

**Weight and Balance** (`#weights`, read from the tablet's code on 2026-10-04). Two halves,
`#page1` (payload selection) and `#page2` (loading), slide by 100vw: both stay laid out, so
`A.visible` treats an element wholly left of 0 or right of `innerWidth` as hidden, and the page
name carries the half (`Weight and Balance, loading`). What the buttons do:

- A preset (`payload_race` … `payload_post`) shows its cargo model (`L:INI_LOAD_*_SHOW`), fills
  the three hold fields with a third of its load each and slides to the loading half. Custom
  cargo (`payload_cargo`) slides with the fields untouched; Cargo from SimBrief
  (`payload_cargo_sb`) runs Update from SimBrief and slides. A preset's label is its two spans
  ("31'000Kgs / 68'300Lbs", "Racing Team Charter"), rebuilt as "Racing Team Charter: 31,000
  kilograms, 68,300 pounds"; the two custom buttons read badly as spans ("Custom Custom Cargo")
  and are named by id. The forward chevron (`switcher_page2`, display:none until a load is
  chosen) is "Loading page"; the back chevron (`switcher_page1`) "Back to payload selection".
- Unload Cargo (`payload_clear`) only zeroes the cargo-model L:vars and shows "Payload
  Removed". The station weights stay on board; the selection half's help line says so.
- Update from SimBrief fills the holds (a third of the plan's payload each) and the fuel field
  (the plan's ramp fuel). Apply Load to Aircraft (`weight_freight_apply`) clamps the holds,
  writes `PAYLOAD STATION WEIGHT` 6/7/8 (3/4/5 zeroed) and loads the fuel at the speed of
  Settings → Maintenance Mode (`L:INI_MAINT_SETTING`): 0 Disabled at once, 1 Realistic (the
  default) 32 kg a second, 2 Fast 256 kg a second, the last two under `L:INI_IS_REFUELING`. With
  engines running and the separate Realistic Fueling switch (`L:INIB_REALISTIC_FUELING`) on it
  refuses ("Unable to fuel aircraft when engines are running.").
- Fields are named by id (`A.FIELD_NAMES`: Total fuel, Forward/Middle/Aft hold) or by their
  label (LOAD or CARGO → Total cargo). The results (`output_*`) are readonly inputs printed in
  thousands of the tablet's unit or in % MAC; they are read-outs, not fields ("Gross weight:
  102.40 tonnes", "… thousand pounds" when the fuel box's unit is lbs).
- Each half opens with a help line, then the live line (`live: 'polite'`, key
  `status:onboard`): payload = stations 3 to 8 (1 and 2 are the pilots), fuel rounded to the
  nearest 100 so an APU's burn does not change it every poll, "fuelling in progress" while
  `L:INI_IS_REFUELING` is set so a moving number is never spoken.

**The header and what covers the page** (swept live 2026-10-04). The header gives one status line
(the local and Zulu clocks as 13:57, and the battery from `#charge-state`'s icon: plug charging,
battery full, half, low), the simulation-rate badge while it shows, then Home and a Control box
button (the gear). What the tablet puts over its pages is read ALONE, under its own page name, as
it covers the page for a sighted pilot (`A.OVERLAYS`, most covering first): the powered-off screen
(`#powered-off`, "Power on"), the pause dialog (`.paused-overlay`; title, text and Resume Flight
when the pause allows it: Top of Descent and AFK mode do, a plain pause does not), the panel-state
confirmation (`#confirm-box`; the box itself does not say which state, so the reader adds the one
it saw pressed), the control box (`#control-box`: Power Off EFB, Lock EFB, time compression with
its state line, brightness, the four panel states, and "Close control box", the dimming
background the tablet closes it on), and My Flight's checklist and flight plan viewers. Overlays
are found with `A.shown`, which checks every ancestor: a viewer on a hidden page keeps its own
display. Running maintenance (`#timerContainer`, shown and hidden by the header's maintenance
button) is not modal and is read above the page, each timer's Finish Now naming its job.

**The pages** (swept live 2026-10-04):

- My Flight: the checklist is a picture (`a306checklist.png`) and says so; the flight plan is a
  `<pre>`, given as one `controlType: 'pre'` block with its lines kept, as on the MD-11 and PMDG.
- Take Off and Landing: a runway button reads "Runway 18L: 3,000 metres, 9,843 feet"; the tablet
  colours it red at or below its shortest table (1,700 m take-off, 1,300 m landing), read as
  ", marked short". A disabled or read-only box is a result, read "V1: blank" until calculated.
- Aircraft Maintenance: brake and tyre wear are coloured blocks only. The reader reads the same
  variables (`L:INI_Brake_Wear_Indicator_*`, 0 to 1; `L:INI_TIRE*_WEAR`, 0 to 200) in the tablet's
  own five bands (fifths of the scale, green to red, black beyond it): "Brake wear: all 8 under
  20 percent", or the commonest band as a count and the other wheels by name. The fuel panel and
  cowl buttons carry no state, so it comes from the variable each toggles (above 0.5 is open).
- Throttle Calibration: "Left throttle: 50%"; the TOGA and IDLE scale marks are not read; the
  instruction (`#calibration`) is live.
- Settings: a choice button with `data-active="true"` (Maintenance Mode) reads "(selected)".
- Charts (`.termcharts`) and Enroute Map (`.enroute-map`) are named from the page container's
  class and open with a line saying they are pictures. Each chart is a button ("CONDR 4 RNAV
  [ATC], STAR") with its own Pin or Unpin; the icon buttons are named. The map's "<" toggle, which
  stays on screen while its list of map types is off it, is "Map type".
- Ground Equipment: the slide colour legend is not read (it sits after the slide buttons, which
  already say armed or disarmed).

A text line split by inline tags ("Complete in <span>4:59</span>") reads as one line, and a button
whose words are only a symbol takes its title ("+" is "Zoom in").

`tools/a300-efb-test` (jsdom, in CI) pins all of this against hand-made fixtures of the page.

## Display readers

Every status box value and call-out is an aircraft L:var or a stock SimVar. Nothing there reads
the simulator's memory, a picture or AI (design rule, 2026-10-04), so two things are NOT in
them: the upper ECAM's warnings, and the ND's waypoint name and bearing. Both live inside the
aircraft's own display software (the E/WD's warning list, the FMS flight plan) and in no variable;
with a route loaded the FMS fills none of the stock GPS waypoint variables either (measured
2026-10-10). The MCDU's F-PLN page gives the next waypoint; the master warning and caution
call-outs give warnings.

**AI display reads** (`A300DisplayReads`, [A300-8], design decision 2026-10-10). Where data cannot
reach, output mode has the fleet's AI reads, as on the Fenix: Alt+P the captain's PFD, Alt+N the
captain's ND, Alt+E the ECAM warning display (the left ECAM screen: warnings and memos) and Alt+S
the ECAM system display (the right screen). Each moves the camera to a measured instrument view
(index 3 for the PFD and ND, 17 for the warning display, 4 for the system display; measured live
2026-10-10) and puts the pilot's view back before the AI is asked. Alt+I is not bound: the standby
instruments are all data. The A300's own prompts say what differs from the A320: the PFD has no
altitude tape (the round altimeter beside it is in frame), and the warning display has no engine
gauges.

**E/WD memos** (`A300EwdMemos`, 2026-10-10, design decision). The memos are read by transcription:
the twenty conditions are the aircraft's own `Message_MemoN::is_active` (v1.0.11) over its variables,
in the E/WD's order, each shown once active for 2.5 s (`EWD::UpdateMemo`). The ECAM Memos box in the
Displays section lists them ("APU running, Parking brake on"); a flight load's memos are the baseline.
They are never spoken (design decision, 2026-10-11, [A300-27]): most follow a switch, whose own read-back says it,
as on the Fenix, the PMDGs, the iFly and the MD-11.

**Flight mode annunciator.** `A300Fma` decodes the FMA from the A300's own mode numbers
(`INI_PITCH_MODE`, `INI_ROLL_MODE`, `INI_PITCH_ROLL_MODE`, `INI_at_mode`, the four armed slots
`INI_PITCH_MODE_ARM`, `INI_PITCH_MODE_ARM2`, `INI_ROLL_MODE_ARM`, `INI_PITCH_ROLL_MODE_ARM`, and
the flags `PFD::drawFMA` tests). The word table was characterised on 2026-10-03 by running that
routine (v1.0.11) on chosen mode numbers, and `A300FmaTests` pins it: pitch 1 SRS, 2/4 SPD or
MACH, 3/24/27 P.CLB, 5/13/16/25 P.DES, 6/28/29 ALT, 7 GS, 8 V/S, 9 the last profile mode,
12/14/15/20/26 P.ALT, 22 ALT*; roll 1 NAV, 2 HDG/S, 3 HDG, 4 RWY, 5 LOC, 7 VOR, 8 VOR*; combined
1 LAND, 2 FLARE, 3 ROLLOUT, 4 GO AROUND; thrust MAN THR with a master switch on and the
autothrottle off or in mode 0, 1 SPD/MACH (P.SPD in a profile pitch mode), 2 A/THR, 3/12 THR or
P.THR, 5 THR, 9 RETARD, 13 and any TOGA lock THR L; CMD 1, CMD 2, DUAL. The words are read out:
"Profile climb", "Altitude capture", "Heading select", "Heading hold".

The PFD draws the guidance columns only with an IRS aligned, essential bus 2 powered, and pitch
trim 2 or pitch trim 1 with the captain's FD source switch. The decoder blanks the thrust column
with them (the PFD keeps it): cold and dark the mode numbers hold old values (`INI_PITCH_MODE`
read 8 at the gate). Not characterised, and so not read: MORE DRAG, the A/THR-for-RETARD swap
that depends on the engines' idle N1, and the FD column (FD1/FD2).

`A300FmaSources` lists the 27 source variables (two only carry the engagement call-outs' Ctrl+M
rows); six are shared with existing rows and lights and never registered twice. All ride ONE continuous batch, and the FMA is composed when that batch
has finished dispatching (`DeferredFlushWatchVariable` is the pitch mode key, so MainForm calls
`OnDeferredFlushBatchDelivered` every sample): a change that moves several variables is read
complete. `A300FmaTracker` speaks a column that changes to a new word ("Pitch mode: Altitude
capture"), a combined mode alone ("Land") and each newly armed mode ("Glide slope armed");
baseline-first, silent when the columns appear, and silent while `Md11SeedGate` is settling a
flight load. Each column has a Ctrl+M row, checked by the definition itself because this runs
outside MainForm's mute wrap.

**Status boxes.** The Displays section (`A300DisplayPanels`, after the Instrument section) holds the PFD,
ND, Engine Instruments and nine ECAM page boxes; the standby instruments are read on the Instrument
section's Standby Instruments panel (see "System values in the panel boxes"). The PFD box reads the FMA
lines, the FCU windows, attitude, heading, airspeed, altitude, vertical speed, radio altitude, the
take-off speeds (V1, VR and V2, see "Take-off speed entry") and the speed tape: `INI_VLS_SPEED`, `INI_max_speed` (the tape's top: 270 knots with the gear
down; `INI_VMAX_SPEED` is VMO), `FMGEC_GD_SPD`, `FCPC_S_SPEED`, `FCPC_F_SPEED` (green dot, S and F
read only at flap lever 0, 1, and 2 or 3, as `PFD::drawSpeedTape` draws them), `INI_VS_SPEED` and
`INI_MINIMUMS_PILOT`. Output mode Shift+1 to Shift+6 read green dot, S, F, VLS, VS and VMAX. Where
the tape does not draw green dot, Shift+1 names the speed it draws in its place ("Green dot not
shown. S speed 198 knots": S at lever 1, F at 2 and 3; at lever 4 the tape draws none of the three,
`A300DisplayText.TapeSpeedAt`). The PFD box also reads the localizer and glideslope deviation
(`A300IlsDeviation`, design decision 2026-10-10; the marker beacons are not read): `INI_LOC_DEV` and `INI_GS_DEV`,
which `AP_LOGIC::updateRadioReceiver` stores already in dots (the radio's angles over 0.8 and 0.4, the
FBW's conversion), shown only as `PFD::DrawPFD` draws them: with the captain's EFIS nav selector on ILS
("not shown, EFIS not on ILS" otherwise), the localizer while `INI_LOC_VALID` is 1 and the glideslope while
`NAV HAS GLIDE SLOPE:3` is 1 ("no signal"), "more than 2.5 dots" past the end of the scale. A positive
localizer value puts the pointer right (the aircraft is left of the course: "1.2 dots left of
localizer"), a positive glideslope value puts it low (the aircraft is above: "0.8 dots above glideslope",
the FBW A320's wording). The
ND box has mode and range (the EFIS selectors), `FMGS_DIST` (the distance `ND::drawWaypointInfo`
prints), ground speed, true airspeed, wind, VOR 1 and 2 (NAV 1 and 2) with DME, the ILS (NAV 3:
the radio panel's ILS frequency shows there) and both ADFs. The standby altimeter is `INDICATED
ALTITUDE:3`: it followed baro 3 when that was set to 1020 and back (measured 2026-10-03).

`A300EcamPages` lists each ECAM page's values: only what its own drawing routine (`ECAM_ENG::Draw`
and its siblings) prints as a number. A generator load is a needle, the hydraulic reservoirs are
bars, and the oil quantity, pack flow, cabin vertical speed and engine fuel pressure have no unit
the page establishes, so they are left out rather than guessed. The fuel tank weights
(`INI_FUEL_WEIGHT_*`) are kilograms (5,997.7 kg in the tanks against the stock 13,222.6 lb) and
read in the tablet's unit (`L:INI_IS_METRIC`), as does the engine fuel flow. The engine
instruments are the simulator's N1, EGT, N2 and fuel flow.

## Flying aids

Measured 2026-10-04 on the gate, unless said otherwise.

**Decision height.** `L:INI_MINIMUMS_PILOT` is the stored decision height: the aircraft's
`increaseFPA_DH()` reads and writes it (5 feet a click, floor -5), and only while
`L:INI_DH_SELECTED` is 1; otherwise the same knob steps the flight path angle. A direct write of
200 held and nothing rewrote it. The typed Decision height box (EFIS Captain panel,
`A300TypedValues.Minimums`) writes both `INI_MINIMUMS_PILOT` and `INI_MINIMUMS_FO`, whole feet from
0 to 2500.

**FCU windows.** Only the altitude window speaks on its own (`A300FcuWindows`,
`A300WindowTracker`): `INI_Altitude_Dial` is written by the altitude knob handlers alone, while
the heading, speed and vertical speed windows are also written by the autopilot's own logic
(`AP::Update`, the managed-speed routines, `SyncVerticalSpeed`), so a change there is not
necessarily anyone's. The altitude window rides the batch with a Ctrl+M row ("Altitude window"),
baseline-first, seeded by the seed gate, and silent for 2.5 s after MSFSBA's own typed altitude
or altitude knob step. A knob step from the FCU panel (any of the four knobs) is read back once
it lands, through the same read-back the autopilot hotkeys use.

**Take-off call-outs.** `A300TakeoffCallouts` on the shared `TakeoffVSpeedCallouts` machine. V1
and VR are `L:INI_V1_FMGS` and `L:INI_VR_FMGS` (they followed the MCDU take-off page: 140 and
145 typed, 140 and 145 read). `L:INI_V2_FMGS` follows the FCU speed window instead (250 with V2
typed as 150), because the A300 crew sets V2 there for take-off, so it is V2 only when it is at
or above VR and no more than 30 knots above it (`PlausibleV2`). The three speeds ride the batch,
consumed, each with a Ctrl+M row named for its speed (V1, VR, V2) that mutes its call; airspeed
streams per SIM_FRAME (`AIRSPEED INDICATED`, paused airborne once the roll is over). The arm is
dropped on every context reset and reconnect, never the speeds. The calls a sample crosses are one
`AnnounceImmediate`.

**Take-off speed entry (2026-10-11).** V1 and VR are spoken as they are entered, in the FBW A380's
words ("V1: 148 knots"), and "not set" when cleared: the FMS writes them in `FMGS::SlowUpdate` from
the flight plan, and clears them only in `resetFMC` or a reload (the TAKEOFF page's LSK1L and LSK2L
are their only other writers), never after take-off. The definition speaks them, not the monitor:
the speeds stay registered in "number", because a batched L:var is read in its registered unit and a
speed unit would convert the FMS's plain knots. Each read-back is an `A300WindowTracker`, as the
altitude window's is: baseline-first, seeded by the seed gate after a load, checked against its
speed's Ctrl+M row (the same row mutes the call). V2 is never spoken: it moves with every FCU speed
change ([A300-11]). The PFD box shows all three; V2 only while `PlausibleV2` takes the FCU speed for
it, "not set (V2 is the FCU speed window)" otherwise.

**Fault and warning lights.** `A300FaultLights` lists 55, each named from the cockpit button it
lights. The names came from mapping the cockpit model's emissive nodes to the light variables
(for example `INI_hyd_blue_light` lights `HYDPUMP_B_E1`, the engine 1 blue pump, and
`INI_APU_LO_PR` lights the APU fuel pump's LO PR). Each is shown on its panel's status box, has a
Ctrl+M row and speaks both ways. They stream on their own once-a-second subscriptions, never the
batch: 58 more names there pushed the FMA's pitch trim sources into a second batch. The changes
are collected in `ProcessSimVarUpdate` only while the announcer is not suppressed (MainForm's
wrap), and spoken together when the next continuous batch ends (`A300LampCallouts`: "3 lights
off: Spoiler 7 fault, Spoiler 6 fault, Spoiler 5 fault"). The annunciator light test
(`L:INI_ANNLT_SWITCH` 0) does not move them. Left out: the FCU lamps, the servo OFF and override
supply lights (switch positions), the reverser and altitude alert lights (frequent, and other
call-outs cover them), and lights the cockpit model draws nowhere. The gear lights are `A300PanelLamps`
(design decision 2026-10-09). The three fire handle
lights are `A300PanelLamps`: MSFSBA read `INI_fire_handle_*_light` with no light power, but the
handle lamps draw `INI_ENG1/ENG2/APU_FIRE_TEST` on the DC light bus; both light together in the
fire test (sampled 2026-10-09).

**Autopilot and autothrottle.** `A300EngagementTracker`, read at the FMA's batch end from the
same sample: "Autopilot disconnected", "Autopilot CMD 1/CMD 2/Dual" (`INI_ap1_on`,
`INI_ap2_on`), "Autothrottle disconnected" and "Autothrottle armed" (either arm switch,
`INI_autothrottle_master_switch1/2`; the A300's disconnect trips them). A change MSFSBA itself
commanded within `A300CommandedState.HoldMs` is the pilot's own pick and silent. Their Ctrl+M
rows ride on `INI_AUTOPILOT_DISCONNECT` and `INI_AUTOTHROTTLE_DISCONNECTED`, registered as FMA
sources only to carry the rows; nothing reads their values, because what they mean was not
measured.

## Budget

309 switch, lever, light, FMA and take-off speed variables ride the continuous batches (two
batches, no individual definitions; every FMA source in batch 1); the knobs and the readouts are
on-request, and the fault lights, the panel lamps and their inputs, the two light power flags, the
take-off airspeed, the altimeter modes, the autobrake level and DECEL lights and the four TRP values
have their own subscriptions (about 280 individual definitions in all); buttons and encoder steps
are write-only. A position variable two rows share rides the batch once and the second row streams
it on its own subscription.
