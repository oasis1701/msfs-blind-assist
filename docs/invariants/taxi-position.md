## RTE-4

- Take-off assist's under-aircraft runway probe — the take-off-assist toggle's fallback when no lineup reference is set (`TaxiGuidanceManager.TryDetectRunwayUnderAircraft`, then `TaxiGraph.TryGetRunwayAtPosition`) — must use a strict tolerance — `RunwayShape`'s own half-width, no +5m fudge — and stay gated on `_lastOnGround`: its centerline math needs the runway actually under the aircraft, and a 5 m fudge could pick the runway beside a high-speed exit the aircraft sits on. Where-Am-I's `DescribeLocation` keeps half-width + 5 m on purpose; the strict test is the take-off probe's, not Where-Am-I's. → [taxi-guidance.md](../taxi-guidance.md)

Corrected 2026-10-08: the strict tolerance belongs to take-off assist's under-aircraft probe; this rule had named Where-Am-I, whose runway answer keeps half-width + 5 m. Evidence: `TaxiGraph.TryGetRunwayAtPosition` (`Contains(lat, lon, 0.0)`), called only by `TaxiGuidanceManager.TryDetectRunwayUnderAircraft` from the take-off-assist toggle in `MainForm.Announcers.cs`; `TaxiGraph.DescribeLocation` (`ContainsAlongLateral(along, lateral, 5.0)`).

## RTE-11

- "Where Am I" is ground-only by design (gated on `_lastOnGround`); runway detection must use `TaxiGraph.RunwayCenterlines`, never rely on `taxi_path.type='R'` edges (the DB has none): `DescribeLocation` keeps a branch for them, dead on navdatareader databases, and no runway answer may depend on it. → [taxi-guidance.md](../taxi-guidance.md)

Evidence: `TaxiGraph.DescribeLocationLocked`, whose R-edge branch is commented as firing only for databases that store runway centerlines as `type='R'` rows, which navdatareader's do not.

## RTE-12

- `TaxiGraph.DescribeLocation` is NOT a UI-thread-only query: Alt+L's surroundings lookup runs it on a thread-pool thread through `TaxiGuidanceManager.DescribeCurrentLocation`, which hands it the ACTIVE guidance graph when the airport matches — `TaxiAssistForm`'s own `_graph`, which the form SUBDIVIDES on the UI thread whenever it projects a painted holding point onto a taxi edge (`NamedHoldingPointResolver.SnapOrInsert` → `InsertHoldingPointNodeOnEdge` → `SplitEdgeAt`). Both hold the graph's `_structureLock` — the query for its whole run INCLUDING its lazily built index, the projection for its whole scan-then-split — so never read that index outside the lock, never add a post-Build mutation that skips it, and any `TaxiGraph` query reachable from a pool thread must take `_structureLock` inside TaxiGraph. UI-thread readers (routing, guidance, the taxi form) need no lock only because every post-Build mutation also runs on the UI thread. The index is DROPPED wherever `TaxiGraph`'s own mutators change the structure (`InvalidateCellIndex`, from `AddEdge`, `SplitEdgeAt` and `ResolveNode`'s new-node branch) and rebuilt by the next query — never detected by recounting adjacency lists on every query; writing the public `Nodes`/`Adjacency` directly (hand-built test graphs, the standalone probes) drops nothing, so never do it to a graph `DescribeLocation` will be asked about. Pass 1's three node answers have DIFFERENT reaches ON PURPOSE (owner ruling on the PR #230 review, the stand's narrowed further on 2026-09-23 — GC-5 fix round 1): the fallback (60 m) is TRUE metres in every direction at every latitude, unconditionally — `NodesNear` over the index's node half (every node, not only edge endpoints) on a ring sized separately in latitude and longitude — and takes the nearest node that HAS a taxiway name (taking the nearest node of any kind let a nearer unnamed one silence it); this decision never touches it. The stand (40 m) gets the same true-metre reach, but ONLY AWAY FROM A RUNWAY: near one — on runway pavement (the same `RunwayShape` test the runway answer uses), where a "near a runway start" answer is in reach (below), or where a hold-short node sits within the stand radius (from the navdata endpoint types `Build` records into `TaxiGraph._navdataHoldShortNodeIds`, NEVER `TaxiNode.Type`, which the parking pass can overwrite to Parking for a node within 100 m of a stand — exactly the nodes this predicate most needs to catch) — only a stand ALSO inside today's ring may answer, exactly as before this whole PR; letting the wider reach win unconditionally there put a stand ahead of "Runway X" at about 2,255 hold-short nodes across 2,036 fs2024 airports and on runway pavement itself at >= 1,660 more, breaking the original ruling's own promise that "nothing said at a hold line changes". The "near a runway start" answer (50 m) keeps EXACTLY the old ±30-cell ring of the 1.1 m node hash (±33 m north-south, ±33·cos(latitude) m east-west), because it outranks the taxiway you are on and `Build` names the entry junction or hold line "Runway X". `RunwayStartReach` replicates that ring's key arithmetic bit for bit (a distance test is not the same set) and `TaxiGraphLocationRadiusTests` pins it, and the near-runway stand carve-out, against a verbatim copy. Never widen the runway-start reach without asking the owner again; never gather FALLBACK candidates from a fixed ring of the 1.1 m node hash — it reached ±20 m east-west at 52°N, ±7 m at ENSB; and never let the STAND'S wider reach win near a runway without the same three-predicate gate (pavement, runway-start reach, hold-short radius). → [taxi-guidance.md](../taxi-guidance.md)

## RTE-27

- The start grace window (`START_WARNING_CHATTER_GRACE_SEC`, 12.5 s: a destination warning followed by the route-start turn cue measures 10.4 s at System.Speech Rate 0) opens for either start warning, the unmapped-leg warning or the runway reach warning, and turn, destination-ahead and curve callouts WAIT it out when it is safe to (`StartWarningChatterGate` -- one that would otherwise be lost for good speaks immediately over the warning instead); the taxiway-change callout has no such loss hazard (it just names whichever taxiway the aircraft is currently on), so it always defers while the window is open and, once it closes, either speaks or — if the route has since moved on to a different taxiway — silently drops the stale name (`TaxiwayChangeGate`): never make any of them skip, and never gate hold-short or runway-crossing callouts on it. → [taxi-guidance.md](../taxi-guidance.md)

## RTE-41

- **The hold-short countdown, the turn advance notice and its "… now", and "Slow for turn" measure ALONG THE ROUTE** (`Navigation/RouteAhead`): from the aircraft to the end of the current segment, then every segment's length up to the next stop (`NextStop`, the first segment at or after the cursor that ends at a hold short, within the outer tier's 600 ft cap) or the next junction (`NextJunction`, the first segment end where the route turns or goes onto another named taxiway, never at or beyond the next stop; `TurnsWithin` for the speed warning's window). A junction is judged on the route, not on one navdata piece: its turn and its direction out are taken over 20 m or more either side (`TurnAngleAt`, `RouteBearingOutOf`; a straight line is never made a turn), junction points less than 10 m apart are ONE junction said at the first (`RunEnd`, `ContinuesEarlierJunction`, never across a hold short), and an unnamed piece between two pieces of a taxiway is no change of taxiway (`TaxiwayBefore`). A 90 degree corner drawn as two 45 degree kinks was otherwise two turns, neither sharp, and a piece drawn off the line and back a phantom turn that took the advance notice from the real one. Never to the current segment's end alone: the cursor moves on `WAYPOINT_CAPTURE_RADIUS_M` (25 m) before a segment's end, so a callout measured that way can start no earlier than 25 m plus the last segment's length out, and the navdata splits taxiways densely around hold lines and junctions. In the FS2024 database 75 % of the 81,068 hold-short nodes have no taxiway piece into them longer than 66 m, 32 % none longer than 25 m. KEWR, 2026-11-26, two departures to 04L via AA: the navdata puts a node 2.1 m before the hold and another 6.4 m before that, so the countdown began 87 ft out and the only line was "Hold short runway 04L at AA in 75 feet. Stop." at 13.6 kt; the F3 turn after a run of 4 to 9 m segments had only "Sharp right now, taxiway F3." 105 ft out. Replayed from the logged frames after the change: the outer, slow-down and stop lines at 299, 168 and 90 ft, and "In 400 feet, sharp right onto taxiway F3, 90 degrees." 10 s before the turn.
- **Latches belong to the stop or the junction, never to a segment.** The countdown's three tier latches are keyed to the stop's hold node (`_holdShortCountdownNodeId`); a different next stop re-arms them, a stop beyond the lookahead keeps them. The advance notice and "… now" latches are keyed to the junction (`_approachJunctionRoute`/`_approachJunctionIndex`, `_turnImminentJunction…`): never cleared by `AdvanceSegment` or `AdvanceToNearestSegment`, which would say the notice again on every short segment before the junction; cleared on a route load, recalculation, stop and Continue (`ResetJunctionCallouts`).
- **The turn word of a junction further ahead.** On the segment that ends at the junction both words stay heading-based exactly as [STR-16] has them. For a junction beyond it, the advance notice's word comes from the route's own direction into the junction (`RouteAhead.RouteBearingInto`, over at least 20 m of route so a short navdata piece never sets it), as the aircraft will be on the route when it gets there, and the notice waits until the aircraft is moving (`ADVANCE_NOTICE_AHEAD_MIN_KTS`); the "… now" keeps the heading, carried through the route's own bends from where the aircraft is up to the junction (`RouteAhead.HeadingChangeTo`, exactly 0 when the junction ends the current segment; measured from the segment the aircraft is on, `distToTargetM` back from the current segment's end, never from the cursor's segment, which on short pieces is one ahead and left a bend before it out: a 40 degree left after a 50 degree right bend not yet made read "continue"). From the heading alone, KATL L4's right-hand curve into a sharp left onto L read "In 120 metres, continue onto taxiway L." before "Sharp left now, taxiway L.", and KDTW's first frame at stand D 3 said "In 110 metres, sharp right onto taxiway E2, 120 degrees." for a sharp left, over the start sentence (VirtualPilot).
- **The incursion guard and the next stop.** The route's next stop on a LATER segment within the countdown's reach along the route (`HOLD_SHORT_COUNTDOWN_LOOKAHEAD_M`, 600 ft, from the aircraft), or once its countdown has begun (`_holdShortCountdownNodeId` with a tier latch set), is never spoken about by `CheckRunwayIncursion` ("Passing the runway 04L at AA hold line." came two seconds before the KEWR "Stop." for that line). Farther along the route it is spoken about as on main: a next stop near the aircraft but far along the route (a route that comes back to it) would otherwise be approached with nothing said. Not "only once a countdown line was said": on a curving approach the node comes within the guard's 40 m before the outer tier, and EFHK 34 heard "Passing the runway 34 hold line." 0.4 s before the countdown's first line, 97 m out along the route (VirtualPilot). Silenced, it stays a candidate and, picked, is latched and opens the cooldown exactly as the spoken line did, in silence. Skipping it outright was measured and REJECTED: it freed false off-route warnings for a neighbouring line of the same runway in the countdown's last seconds (KSLC 16L at G beside the H hold), false warnings on route 67 → 98 flights; latched in silence 67 → 61, with the off-route decisions main's.
- **"<destination> ahead."** is not said on the last segment once the countdown for that same stop has begun (it came 0.2 s after the KEWR "… Stop." and cut it off).
- Measured with VirtualPilot (fs2024, plain navdata, 100 airports, `taxi wrongturn turnpicks departures missturn`, 19,258 scenarios), against a frozen build of main with the same harness: the first countdown line more than 30 m after its outer tier 4,063 flights → 0, "Passing"/"Crossing" said about the line then stopped at 1,586 → 355 (the rest is a second hold node of the same line, which [HLD-21] keeps), a turn "… now" with no advance notice 647 → 7, an advance notice whose side is not its "… now"'s 951 → 403 flights; wrong turns warned 384 → 376 and silent 11 → 12, flights that differ in time, not in the guard. See [virtual-pilot.md](../virtual-pilot.md), eleventh round. → [taxi-guidance.md](../taxi-guidance.md)
