# Synaptic A220-300 panels — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/a220-panels.md`, which Claude Code loads when it reads matching code. Background: [a220.md](../a220.md). The other A220 rules are in [a220.md](a220.md) and [a220-fms.md](a220-fms.md).

## A220-40

- The speedbrake lever is moved the way its cockpit lever moves itself. `FCTL_SPD_BRK_LEVER` (Pedestal/FlightControls.xml, template `A220_Lever`) reads `(L:A22X Spoiler Lever)` as a 0-1 travel and writes `<travel> 0.5 - 32768 * (>K:SPOILERS_SET)`, stepping 0.1 per wheel click. The `A22X_SPOILER_LEVER` combo sends exactly that string (`A220Panels.SpeedbrakeCalc`, seq-prefixed, invariant fixed-point per [VAR-5]) and shows the read-back as the nearest detent (`A220Panels.SpeedbrakeDetentForTravel`). Its six positions are the cockpit's RET, quarter, half, three-quarter, FULL and MAX — the pilot guide describes friction detents at the quarter positions and a lift gate between FULL and MAX — and the ECL's sensed SPOILER_LEVER_0..5, so the ECL maps all six. The detent travels 0, 0.2, 0.4, 0.6, 0.8 and 1.0 are pending a live sweep of the travel in 0.1 steps against the aircraft's own sensed bits (Plan B's live task); change them only from such a sweep. Never use the stock `SPOILERS_ON`/`SPOILERS_OFF` events (the old Retract/Full buttons, which bypassed the lever) or a 0-16383 `SPOILERS_SET` value: the lever's own write is centred on half travel. → [a220.md](../a220.md)

## A220-41

- An A220 control's "(guarded)" label is the cockpit's guard, read from the behaviour XML (`IS_GUARDED`, carried into the `guarded` column of `tools/a220-gen/reference/cockpit-controls.csv`), never a habit carried over from another Airbus. `A220PanelStructureTests.GuardLabels_FollowTheCockpitXml` checks it both ways for every definition whose L:var is a cockpit control. The labels it corrected on 2026-10-12: gravity transfer was marked guarded and is not; cabin power, evac, PFCC 1-3, both hydraulic SOVs, aural warning inhibit, TAWS gear/terrain/flap inhibit, gear aural cancel, alternate brake and alternate flap are guarded and were not marked. The fire bottles carry no guard in the XML. Regenerate the CSV with `tools/a220-gen/cockpit_inventory.js` after an aircraft update; the test follows it. → [a220.md](../a220.md)

## A220-42

- The cockpit's pushbutton template decides the write. `A220_ButtonPBA` without `IS_LATCHED` — probe heat (ground test), both engine fire pushes, EXT PWR, master caution — sets `SET_STATE_EXTERNAL` to `1 (>VAR)`: the cockpit writes 1 and the WASM consumes and clears it (simvars.mdx says so for probe heat; measured live for EXT PWR, probe heat pending Plan B's live task). MSFSBA models these as write-1 buttons (`LPress`, `IsMomentary` false). They used to be level combos ("Probe Heat: Auto/On", "Left Engine Fire Push: Normal/Pushed") whose 0 wrote nothing the aircraft reads and whose shown state never matched. `A220_ButtonMomentary` and `A220_ButtonMomentaryClicky` pushes (chrono, nav source, crosstune, FD, CVR, mech call, transmit select) and `IS_HELD` pushes (gear aural cancel) keep the 1-then-0 pulse (`LMomentary`, `IsMomentary` true) as two calc strings. Latched korrys (`IS_LATCHED`) toggle a level the WASM reads, so they are two-position combos written by the generic L:var path. `A220PanelStructureTests.Pushbuttons_WriteTheWayTheCockpitDoes` derives all three from the inventory's `kind` column. → [a220.md](../a220.md)

## A220-43

- The standby instrument (ISI) has no set event and no CommBus action. Its baro knob (`A220_KnobContinuous`) writes a per-click delta, `p0 (>L:A22X ISI Altimeter Set)` with p0 = ±1, which the WASM applies and clears; its push writes `1 (>L:A22X ISI Altimeter STD)`. The only read-back is the ISI's own `A22X.ISI Data` store (`qnh_hpa`), which the displays agent exposes as `isi()`. So the "Standby Baro" entry is a walk under the FCP walks' rules ([A220-7], [A220-9], [A220-10]): one ±1 write per calc string, paced so two never land in one WASM tick, the step and the direction measured on the first click of this walk, `round(|delta|/step)` clicks after that, and a straddle stops on the nearest selectable value. With no read-back, or a knob that does not move, the walk refuses aloud and never clicks blind. → [a220.md](../a220.md)

## A220-44

- The audio control panel's only functional receive controls are the three VHF volume knobs (`A220_ACP_Knob` → `A220_KnobPotentiometer`, `Pedestal/ACP.xml`, `Lib/Knob.xml`). The rotation writes `(O:SwitchState) 1 28 / * (>L:A22X ACP VHFn Volume)`: 29 detents, the level 0 to 1 in 1/28 steps, and the knob follows a direct write of the L:var. The push (`BTN_TOGGLE True`) runs `(L:A22X ACP VHFn Rx) ! (>L:A22X ACP VHFn Rx)`, a 0/1 toggle drawn as the knob pulled out. The aircraft's `systems.wasm` reads all three names and composes `COMn_RECEIVE_SELECT` and `COMn_VOLUME_SET`, so they drive the stock COM receivers (string scan 2026-10-15; the polarity and the volume mapping are pending Plan B's live task).
- MSFSBA writes the TARGET receiver state, 0 or 1, never the toggle: a toggle would undo a pick the aircraft had already taken (main's PMDG 737 VHF receivers, #307, send the target state for the same reason). It writes the volume as `step 28 /` (`A220Panels.AcpVolumeCalc`), so the sim computes the exact level and the knob lands on its detent; never the combo's step index, which the generic L:var path would write (14 into a 0-1 L:var), and never a four-decimal level.
- Each write is read back once, after the pilot has stopped on a value (700 ms with no newer write to that control): silent when it landed (the screen reader read the pick, CORE-7), "did not change — still …" / "reads …%" when the aircraft kept another value, "not confirmed" when nothing came back. A write the pilot has arrowed past is never read back, so the 29-position volume combo neither reports a false failure nor snaps back mid-arrow.
- HF 1-2, SAT, CAB, INT, PA, SPKR, NAV and DME have no variable on this aircraft (their cockpit nodes only animate), so they are not offered. → [a220.md](../a220.md)
