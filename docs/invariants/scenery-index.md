Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/scenery-index.md`, which Claude Code loads when it reads matching code. Background: [taxi-guidance.md](../taxi-guidance.md).

## SUR-6

- The scenery tier: a model name reaches speech ONLY through `SceneryModelNameClassifier` (raw `KTIW_*` / `concourse_a_02` strings never do), and ground equipment is caught by TWO nets that are BOTH required — the LEXICAL one in that classifier (a `StopWords` token, a `StopList` phrase, or no kind word at all condemns the model; `VendorTokens` is NOT a rejection rule, it only strips a leading vendor token in `Tokenize`; every rule pinned to a measured package name, so extend the test table FIRST; every regex `static readonly` + `CultureInvariant`, none built per call) and the STRUCTURAL one in `SceneryPackageIndexer` (a name scattered over many separate clusters is clutter; a real building becomes one feature PER CLUSTER, never a package-wide average, which put MK Studios BIKF's seven "DS Hangar" buildings 2.3 km apart at one phantom point between them). `Tokenize` strips the vendor prefix up to and INCLUDING the airport's ICAO token (`mk_bikf_…`, `iniscene-egss-…`), or failing that the PACKAGE's own ICAO from its `<vendor>-airport-<icao>-…` folder name (`PackageIcao`); where the ICAO instead ENDS the name (`DHL_YSSY`, `TankOil_KPHX`, `Hangar_KTIW_02`) — the words after it holding no kind word and the words BEFORE it holding one ON THEIR OWN — only the ICAO token goes. The kind test there is `HasKindWord`, the prefilter's own test over `KindWordPatterns` (positive patterns only, never the FBO veto). "On their own" is load-bearing: `MightBeFeature` knows no ICAO and sees the whole name, so a kind phrase completed ACROSS the removed token (`Jet_KXYZ_Centre`) would be accepted by `Classify` and already rejected by the prefilter. Measured over all 26,098 model names in 35 installed airport packages, the rule affects five models the old strip threw away whole and NAMES four: YSSY "DHL" and "Security DHL" (single placements ~100 m from its cargo stands), YSSY "Cargo Rwy" (`cargo_rwy25_yssy` — the author's own words, a RECORDED residual beside EIDW's pre-existing "Rwy 28 Poi Bud 2 Cargo": runway designators inside a model name are a separate lexical question) and KPHX "Tank Oil"; the fifth, `Fuel-truck_KPHX`, stays clutter. What the rule owes those models is that they are no longer DROPPED: their names follow the classifier's existing rules ("Terminal", "Hangar 2", "Boeing Hangar"), never a hand-picked "Main Terminal" or "Hangar 02" (scenery-index review item 3). A concourse or terminal is named from the keyword that DECIDED its kind (`Terminal_1_pier_2` is Concourse "Pier 2", never a second "Terminal 1"). The 2026-09-24 audit of all 360 installed-scenery airports pinned stop words for ground equipment (`gse` is a STOP word, not a vendor token — a Signature-branded GPU became an FBO), masts named "… tower" (`radar`/`ils`/`radio`), city landmark packs and `poi` (MK/iniBuilds' landside-landmark tag); a second pass on 2026-09-25, reading every kept name by eye, pinned brand-carrying props (KATL's `…_signature` benches, bins and people were FBOs), taxi guidance signs (`tgs`, `taxisign`), fire-training wrecks and planes (routable "fire stations"), masts (`lamps`, `dme`, `comm`, "steel tower"), landside fuel (`costco`, `propane`) and cargo-area dressing, and widened the freighter test to a separated `B777_F` — never `canopy` (part of KATL's Concourse T) or a bare `box` (`KLAX_TheBoxTerminal`), only "cargo box"; residual: an unmarked skyscraper at a city heliport still reads as a tower. `FeatureKind.Terminal` and `FeatureKind.Concourse` are EXEMPT from the PLACEMENT cap (`PlacementCapApplies`) and exempt BY KIND, never by a cluster count: a 46-part terminal and a 41-container blob are the same single-cluster shape, so no cluster rule can tell them apart. Measured across 34 installed packages, NO Terminal/Concourse group was clutter while the cap had dropped EDDB Terminal A/B/C (46/49/49 parts) and its generic Terminal (175), KPHX Terminal L (21 parts at one coordinate) and KATL Terminal E; 308,833 placements → 837 features before the clutter rule → 533 after. The CLUSTER cap still applies to every kind (EGSS's real 4-cluster "Inflite Jet Centre" is an accepted, recorded residual). The disk cache (`%APPDATA%\MSFSBlindAssist\scenery-index`, schema-versioned, keyed on a hash of the full package path and stamped with `layout.json`'s length + mtime) stores RAW placements per model, so a change to HOW a name classifies reaches a warm cache — but WIDENING the classifier's kind keywords does NOT, because the names in there are the ones `MightBeFeature` accepted at BUILD time, and that needs a `SceneryPackageIndexer.CurrentSchemaVersion` bump (never `SceneryPackageCensus.CurrentSchemaVersion`, which versions the census file) — 2 → 3 is that rule firing for the first time, when the Concourse leg moved onto `FeatureLexicon.Concourse` and gained "flugsteig", so every schema-2 cache had already filtered those models out, and 3 → 4 fired it again when `FeatureLexicon.Fbo` gained sheltair, tac air, clay lacy and a glued "millionair" and `FeatureLexicon.Deice` gained deiced, deicer and deicing; a document of the CURRENT schema with no `Models` key is REBUILT, `"Models":[]` is believed, and ANY older schema is rebuilt whole. Readers never load a whole file: the model GUID is the 16 bytes at `size − 20` of a LibraryObject record (+44 in the classic 64-byte layout, +72 in the MSFS 2024 SDK's 92-byte one, where +44 holds a latitude double instead), names come from a streamed byte search for `<ModelInfo`, each tag decoded as UTF-8 (Latin-1 only when it is not valid UTF-8) with its XML entities (`&amp;`, `&#233;`) unescaped — none of the 26,098 names in 35 installed airport packages needed either, so this guards the next package rather than fixing a current one (scenery-index review item 8), and there is NO size cap — the 600 MB one dropped the model library, i.e. every name, of ten real packages. `BglPlacementReader` is bounded by a CUMULATIVE byte budget per call (`DefaultMaxTotalBytes`, 128 MB), not only per buffer: a file declaring millions of small, individually in-bounds entries that all point at one region would otherwise refill a 64 MB buffer millions of times. It holds ONE parser — the span overloads DELEGATE to the stream ones, and must stay that way: as a second implementation it had already drifted (it clamped a truncated entry where the stream reader rejects it, and had no per-subsection cap), and the tests that used it were pinning a parser no production caller runs. A name must classify the SAME WAY in every tier, because `AirportFeatureCatalog` never merges across kinds (a "Cargo Terminal" read as Terminal here and Cargo there is one building listed twice): ONE function, `FeatureLexicon.NamedKind`, reads a name Cargo, then Fbo, then Concourse, and the OSM tier (`TerminalKind` and its named-building branch, which admits only Cargo or an FBO), `GsxTerminalFeatureSource.KindOf` (words first, stand types only for a header whose words say none of the three) and this classifier all call it — Cargo first because "DHL Aviation", "Menzies Aviation Cargo" and "Virgin Atlantic Cargo" are cargo operations carrying an FBO word and a "Cargo Satellite" is no passenger pier, Fbo before Concourse because "pier" and "satellite" are shapes any building has. An FBO needs an FBO word AND no office or government word (`FeatureLexicon.IsFboName`: "Civil Aviation Authority", a terminal operated by the "City of Atlanta Department of Aviation", KSEA's "Port of Seattle Aviation Maintenance" and — there being no bare "atlantic" any more — EGLL's "Virgin Atlantic Upper Class" are not FBOs); the FBO chains Signature, Million Air, Sheltair, TAC Air and Clay Lacy are FBO words, the fuel brand Avfuel never is (an "Avfuel" fuel point is Fuel, and an FBO word would have made a scenery "Avfuel Tank" a second kind of the same facility). `MightBeFeature` asks only the POSITIVE patterns (`KindWordPatterns`), never the veto, or it stops being a superset of what `Classify` accepts. Hangar stays FIRST here ("Narrows Aviation Hangar" is a hangar); ONE de-ice pattern (`FeatureLexicon.Deice`: deice, de-ice, de ice, deicing, deicer — whole words, so a glued "Deicepad" is not one) serves the OSM and scenery tiers; and the keyword set a concourse's spoken name is built from is made from the SAME `FeatureLexicon.ConcourseWords` array the `Concourse` pattern is, so the two cannot drift — pinned by `Every_concourse_word_in_the_shared_list_is_classified_and_named`, which walks that array. Every vocabulary change here changes which model names `MightBeFeature` lets into the scenery cache. → [taxi-guidance.md](../taxi-guidance.md)

## SUR-7

- Package discovery: the folders `airport.scenery_local_path` names where navdata has them (an MSFS 2020 build), otherwise `SceneryPackageCensus` — an MSFS 2024 navdata build records a package path for NO airport, so the package is found by where its objects STAND: a header-only scan (section table plus placement subsections, never a model library's bulk), disk-cached per package on `layout.json`'s length + mtime, at least `MinPlacementsInBox` (20) placements inside the airport box grown 300 m — grown by `GrownBox` (`Navigation/Surroundings`), the ONE margin conversion `AirportFacilities.ContainsPoint` and `CurrentAirportResolver` use as well, at the BOX's own latitude (the resolver alone used to convert at the aircraft's; review CL-4). Community AND, on MSFS 2024, `Community2024` — the SDK's folder for 2024-only add-ons, where the 2024-native airports and the MD-11 live; a Community-only census reported "no installed scenery package found" at CYYZ with FlyTampa's package on the disk (2026-10-02) — both from the one `MsfsPackagesLocator.TryGetCommunityPaths`, never Official/OneStore; whether a package is scenery at all (its `manifest.json` `content_type`) is memoised on its `layout.json` stamp, so a catalog build re-reads no manifest a package update has not rewritten (review CL-8). Measured on a real Community folder (the `Community2024` half is unmeasured): 40 scenery packages of 88, 2,443 BGLs, 21.3 MB read, 2.58 s cold / 16 ms warm (measured BEFORE a scan also parsed each package's own `layout.json` content list — scenery-index review item 1 — which a cold pass now adds and which has not been re-measured), the right package at KATL, EGLL, KJFK, LMML, EDDF, KSEA, EHAM (`flytampa-amsterdam`, no ICAO in its folder name), OMDB, OMDU, EGSS and KMEM, and NONE at KTIW / KSNA. A hand-edited row that names nothing is dropped at load — a null census row, a null `Models` entry in an indexer cache — and **NEITHER the census NOR the indexer ever PERSISTS a scan that could not read every file**: both serve what they read for THAT call, because one moment's exclusive lock, antivirus sweep or package update would otherwise freeze a short count under `layout.json`'s stamp until the package is next updated (for the indexer that means every placement resolving to "without a model name", i.e. an airport with no buildings, with nothing in the status line to say so — it now carries `, 1 file unreadable` / `, 3 files unreadable`, pluralised because a screen reader speaks it). A file that could not be OPENED and a read a TRANSIENT I/O error cut halfway both count (`BglPlacementReader.Read(stream, out bool complete)`, which reports only `IOException`/`ObjectDisposedException`: a malformed file or a spent byte budget is deterministic, so it stays cacheable or the package is re-read forever). A THIRD cause counts, because reading every file FOUND is not finding every file the package HAS: an installer writes `layout.json` FIRST, with its final stamp, and the BGLs after it, so each scan is held to the package's OWN `layout.json` content list (`SceneryPackageDisk.UnfinishedLayoutFiles`, scenery-index review item 1; the list is opened through the same shared-read `SceneryPackageDisk.OpenShared` as every BGL) — a listed BGL the walk did not find, or read at another length than listed, makes the scan short (the indexer's status then carries `, 1 file missing or incomplete` / `, 3 files missing or incomplete`). A listed BGL absent BESIDE a copy of itself carrying one of the three MEASURED suffixes (`SceneryPackageDisk.SwitchedOffSuffixes`: `X.bgl.disabled`, `X.bgl.off`, `X.off`, compared `OrdinalIgnoreCase`) is an option the vendor's configurator switched OFF, NOT a missing file — measured on a real Community folder, 24 listed BGLs in 6 of 46 healthy packages (Aerosoft EDDF/ENGM, iniBuilds EGKK/EGLL/PHNL, Orbx KATL) are exactly that, a bare missing-means-short rule would keep all six out of the cache for ever, and 0 of the 2,451 present BGLs has a sibling of ANY `<stem>.*` shape. NEVER widen it to "any file named `X.<anything>`": an installer's staged `X.bgl.part`/`X.bgl.tmp`, a backup or a same-stem `X.xml` would then pass for an option and a half-installed package would be cached as complete — the frozen short answer this check exists to prevent (pinned by `A_listed_bgl_beside_any_other_sibling_is_still_unfinished`). Paths compare IGNORING CASE (`layout.json` says `modellib.bgl`, the disk `modelLib.BGL`); the listed `date` is NEVER compared (it equals the installed file's mtime for 0 of 2,451); a row outside the package or deeper than the walk's depth bound is not held against it; and a `layout.json` that is absent, unparseable or carries no content list holds a scan to nothing. The census cache went to schema 2 with this, so a row an earlier build froze mid-install is read once more. Residuals: only Community packages were measured — an MSFS 2020 Official package that `scenery_local_path` hands the indexer, whose list names a BGL it does not ship as a plain file, would read short for good; and a file an installer PRE-ALLOCATES at its final size and fills in afterwards passes the size check (unmeasured). The indexer additionally MEMOISES an incomplete scan for `IncompleteMemoLifetime` (5 minutes) so a 600 MB model library is not re-read on every call, and gives that memo up afterwards so the condition cannot outlive itself. Both walks use the ONE `SceneryPackageDisk.BglFiles` (`EnumerationOptions { RecurseSubdirectories, IgnoreInaccessible, MatchCasing.CaseInsensitive, AttributesToSkip = 0, MaxRecursionDepth = SceneryPackageDisk.MaxBglRecursionDepth (12) }`) — `AttributesToSkip = 0` is DELIBERATE (the default skips Hidden/System, and reparse points must be FOLLOWED: add-on linker tools put whole packages behind junctions), so the depth bound is what ends a junction cycle, and it is ONE field because the indexer is handed a package the census found in Community, so bounding one walk and not the other just moves the cycle. `SceneryPackageDisk` owns every other disk rule the two share as well — the `layout.json` stamp, the ONE shared-read open `OpenShared` (`FileShare.ReadWrite | FileShare.Delete`, since the simulator may hold the file), `WalkBgls` (each BGL opened through it and handed to the caller's reader), and the whole-file-or-nothing `.tmp`-then-move `PersistJson` — because each was written twice and kept in step only by comment (review CL-4). `MsfsPackagesLocator` is the one resolver of `InstalledPackagesPath` FOR THE NAVDATA BUILD AND THE CENSUS (`NavdataReaderBuilder` delegates to it) — `EFBModPackageManager`, `AircraftCfgCatalog` and `GsxAirplaneProfile` each still parse `UserCfg.opt` themselves — and whether an `InstalledPackagesPathNextBoot` line counts is its CALLER's choice (`includeNextBoot`, passed explicitly with no default): the navdata database build keeps it (`TryGetInstalledPackagesPath`, preserved deliberately — it has always resolved its base path that way), the census NEVER does (`TryGetCommunityPaths`, active key only, the rule the other three readers apply — and with no `includeNextBoot` parameter of its own, so no caller can take the NextBoot line by accident), because it reads while the simulator RUNS and the simulator writes the NextBoot line the moment the pilot PICKS a new folder in-sim, a folder that normally already exists — so the first-existing rule scanned a Community folder the running simulator was not loading (scenery-index review item 5). `airport.tower_lonx/laty` is NULL on an MSFS 2020 build but present for 1,952 of 84,278 airports on an MSFS 2024 one (measured 2026-09-21) — the tower comes from navdata WHEN NAVDATA HAS A TOWER OBJECT (`airport.has_tower_object`, carried as `AirportFacilities.HasTowerObject`), and the old "NULL on every row, so the tower never comes from navdata" is retired. A position alone is NOT a tower: 319 of those 1,952 carry `has_tower_object` 0 and no tower frequency — the tower-VIEW camera point, KAST's 319 ft above a 7 ft field — and read as a building they put a phantom "Control tower" in Look around and the passing callouts (measured 2026-09-22; the other 1,633 all have a tower frequency). A UserCfg.opt that EXISTS but cannot be READ is not "no Community folder": `MsfsPackagesLocator.TryGetCommunityPaths` reports it (`readFailed`) and `SurroundingsCatalogBuilder` marks the scenery tier SHORT on it, so the catalog is degraded and rebuilt — the old shared null left a catalog with no scenery tier cached as complete for the session. Every OPTIONAL tier (GSX, OSM, scenery/census) is read through `SurroundingsTier.Read` so its failure costs only itself: one corrupted `census.json` row used to fail the WHOLE catalog build — navdata stands and GSX places included — and be retried every 60 s forever. Navdata stays the required base. A base-library (Asobo) name index was measured (0 % of unresolved placements at KATL/KJAC/KTIW classify as a building) and rejected. → [taxi-guidance.md](../taxi-guidance.md)

## SUR-11

- `MsfsPackagesLocator` finds the packages root by reading the simulator's own config, `UserCfg.opt` (`TryReadUserCfg`), and since the scenery census it reads it while the simulator is running. It opens the file `FileShare.ReadWrite | FileShare.Delete` and closes it before its first `Directory.Exists`: a reader that permits no writer, or one held open across the directory probes, can make the simulator's own write to its config fail. Evidence: `MsfsPackagesLocator.TryReadUserCfg` in `Database/MsfsPackagesLocator.cs`, whose `FileStream` is opened `FileShare.ReadWrite | FileShare.Delete` and released by its `using` block before the `Directory.Exists` loop over `ParseInstalledPackagesPaths`. → [taxi-guidance.md](../taxi-guidance.md)

Known gap (2026-10-08): `AircraftCfgCatalog.FindInstalledPackagesPath` reads the same file with `File.ReadLines`, which shares it for reading only and keeps it open while its loop runs. That is the pattern this rule forbids, not a second one to follow.

Promoted 2026-10-08 from the Background in docs/invariants/core.md, which keeps its text.

## SUR-20

- Both scenery walks use the ONE `SceneryPackageDisk.BglFiles`, whose `EnumerationOptions` keep `AttributesToSkip = 0` DELIBERATELY: the default skips Hidden and System files, and reparse points must be FOLLOWED, since add-on linker tools put whole packages behind junctions.
