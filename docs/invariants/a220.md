# Synaptic A220-300 — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/a220.md`, which Claude Code loads when it reads matching code. Background: [a220.md](../a220.md).
The text is verbatim from CLAUDE.md on `feat/synaptic-a220` as of `fda36823`; a trailing "→ doc" pointer is the original's. One original bullet held two rules and is split across A220-28 and A220-29.

## A220-1

- A220 L:var names contain SPACES (`L:A22X APU Switch`) — every A220 write goes through `ExecuteCalculatorCode` directly (the def's `HandleUIVariableSet` claims EVERY settable control); never let one reach `SetLVar`, whose space/colon guard routes it to the unreliable data-def write (and `CalcPathVerified` never goes true for non-FBW defs anyway). Do NOT weaken the global guard — it protects stock-SimVar shapes for every other aircraft. Classification exception: `A22X `/`INI_` prefix = L:var despite spaces. → [a220.md](../a220.md)

This is the A220's exception to VAR-2, which since 2026-10-07 classifies by an add-on's own prefix or source and leaves an aircraft whose L:vars contain a space or a colon to say so in its own rules. The rule line names VAR-2 since the same date; the bullet above is unchanged.

## A220-2

- Never register the `L:A22X Aural *` native playback flags — the aircraft speaks its own callouts (V1, radio heights, TAWS, takeoff config); announcing them doubles the audio. Three same-prefix names ARE real controls (Aural Warn Inhibit + Lamp, Aural Internal Test). Test-pinned. → [a220.md](../a220.md)

## A220-3

- APU start is HOLD-to-start (sustain 2 for ~3 s with seq-prefixed re-writes, release to 1) inside the control write, and every A220 calc string carries the `{seq} 0 *` anti-coalescing prefix. → [a220.md](../a220.md)

## A220-4

- A220 cache-fresh quiet vars must be `Continuous+IsAnnounced=true` swallowed in `ProcessSimVarUpdate` (`_silentReadoutKeys`) — `IsAnnounced=false` Continuous vars get NO subscription at all (stale cache). → [a220.md](../a220.md)

## A220-5

- NAV radios are STANDBY-set only — no NAV active-set or swap control may ever exist; manual active ILS tuning breaks the A220's NAV-to-NAV transfer incl. the 400 ft go-around retune. No spoiler-arm control (the aircraft masks the stock arm events). Both test-pinned. → [a220.md](../a220.md)

## A220-6

- A mode/TOGA press is never followed by silence — FG transitions announce via the monitor, `AnnounceModeResult` adds the deferred honest "no change" call, TOGA diffs an FG snapshot and always speaks. → [a220.md](../a220.md)

## A220-7

- FCP dialogs walk, never set — RE-PROVEN 2026-08-10: every stock SET event leaves the WASM's FCP untouched (re-proven 2026-09-21: 12000 written to `AP_ALT_VAR_SET_ENGLISH`, the selector did not move), inc/dec ignore their parameter, and the JS→WASM CommBus surface has no FCP channel. The ALTITUDE walk is grid-based (the selector SNAPS to round 1000s/100s per ring — coarse for thousands, fine for hundreds); every other knob keeps the self-calibrating measured walk; never reintroduce open-loop step-count math. The VS thumbwheel is DEAD until VS/FPA mode engages — engage first, then walk (LVFR lesson). → [a220.md](../a220.md)

## A220-8

- The FCP walk's read-back PREFERS the aircraft's own `A22X.FCP Data` CommBus block at 30 Hz and falls back to the 1 Hz SimConnect cache — and that fallback is a SOUND source, not a degraded guess: measured live 2026-09-21, the stock `AUTOPILOT ALTITUDE LOCK VAR` / `HEADING LOCK DIR` / `AIRSPEED HOLD VAR` each track their FCP knob click for click (0→1000→2000→2100→2200→2300→3000 on the altitude selector; 245→246; 80→81). **This bullet used to say they were NOT published and that cost every link-less session the good walk** — `ReadAfdxLiveAsync()` returning null dropped the altitude entry straight onto the inferior measured fallback, so a user without the Coherent display agent could never get the grid walk at all. Only the TIMING degrades on the cache (1 Hz, so keep the 1.3 s settle — never converge fast on a stale source); the per-knob step stays measured (`moved / clicks`, cached per session), never assumed. → [a220.md](../a220.md)

## A220-9

- The A220 knob walk must AIM, never hunt: fire `round(|delta|/step)` clicks (`A220Afdx.AimClicks`) to land on the nearest selectable value, and treat 0 clicks as "already closest — stop and say so". `floor()` plus a one-click creep straddles the target forever on a coarse step (live: asked 6000 ft, got 5085 ft — the FCP altitude selector was in METRES, where 5085 ft = 1550 m and the day-one "492 ft/click" is 150 m; a round number of feet is often not selectable at all, so the walk must NAME the metres mode in its result). Walk DIRECTION is calibrated on the first move (swap inc/dec if it went the wrong way), never assumed. → [a220.md](../a220.md)

## A220-10

- An A220 walk must never quit before it has moved the knob — "nothing closer is selectable" is only valid from a step measured ON THIS walk; an inherited `_fcpStepCache` step larger than the remaining delta makes round 0 fire ZERO clicks and announce a result untested (live: "set heading 270, stopped at 239"). And never batch several `(>K:EVENT)` statements into one calc string — MEASURED 2026-09-21: four `(>K:AP_ALT_VAR_INC)` in one string moved the selector by exactly ONE click (2100→2200), so the WASM samples the event once per frame and a batch of n applies as 1, feeding the step estimator a value n times too small. → [a220.md](../a220.md)

## A220-11

- The A220 ALT knob's PUSH is the fine/coarse ring (`FCU_ALT_PUSH` `BTN_VAR = L:A22X FG Altitude Fine`, `BTN_TOGGLE`), and that L:var is a **LEVEL, not a pulse** — measured live 2026-09-21: write 1 and clicks become 100 ft, write 0 and they become 1000 ft, and the value persists across clicks (the WASM resets it to 0 at power-up, not per click). So the walk's ring writes are sound, but they must be CHECKED: a ring that did not flip makes every later click a tenth (or ten times) the assumed size, so the walk measures what a burst actually moved and re-selects the ring once when the step is off by more than 2× (`A220Afdx.StepIsWrongRing`). In METRES the coarse ring steps ~492 ft, which is where "round altitudes are unreachable" comes from; in FEET the grid is exact (coarse = round thousands, fine = round hundreds), so the walk uses coarse for the thousands and fine for the hundreds and puts the pilot's own ring back afterwards. → [a220.md](../a220.md)

## A220-12

- **No stage of the altitude walk may stop "close enough".** Its coarse stage used to exit at `|delta| < step/2` — 500 ft — while the final verdict demands 50 ft, so an off-grid start within 500 ft of a round thousand fired ZERO clicks and then announced *"Altitude did not reach 5000 — selector reads 5085 feet"* for a target ONE click away (the metres-leftover case, and the "always something close but not quite right" report). Every stage exits only when it is genuinely ON its value (5 % of a step); `GridClicks` has always been able to make that click, it was never asked to. → [a220.md](../a220.md)

## A220-13

- A220 stabilizer trim is set by the same calibrated walk over the RATE events `ELEV_TRIM_UP`/`_DN` reading `efcs.pitch_trim` back — there is no set event and no trim L:var. It must REFUSE when the display link is down (no read-back = open-loop on a stabilizer), and the number to type is the EFB takeoff-perf figure, which that EFB renders as `abs(trimUnitsNoseUp).toFixed(1) + "UP"`. → [a220.md](../a220.md)

## A220-14

- A220 stab/rudder trim exist ONLY on the CommBus (`efcs.pitch_trim`/`efcs.rudder_trim`) — there is no trim SimVar on this aircraft, and `L:A22X Horizontal Stabilizer` is the ANIMATION ratio, never the cockpit's units. The stab read-out must quote the `pitch_trim_dn`..`pitch_trim_up` takeoff band so it ANSWERS a CONFIG STAB TRIM warning; don't expose aileron trim (the EICAS renders that block `visibility: "hidden"`). → [a220.md](../a220.md)

## A220-15

- `RegisterViewListener` is ASYNCHRONOUS — a CommBus `.on()` made before its ready callback fires is silently dropped. Subscribe from the ready callback, retry while nothing has ever arrived, and ship a `diag` block with the tap (the A220's `A.afdx()` → `A220Afdx.DescribeTap` names the failing layer on Alt+F). A silently-dead tap cost a full live session of shipping fixes on top of fallbacks; build the diagnostic WITH the feature, never after it fails. → [a220.md](../a220.md)

## A220-16

- A220 FD state must come from `A22X.Autoflight Data` `l_fd`/`r_fd`, NEVER from `L:A22X L/R Flight Director` — that L:var is bound to `A220_ButtonMomentary` (a press pulse), so it reads 0 whatever the FD is doing and a level write to it is meaningless; the FD panel entries are momentary BUTTONS plus separate CommBus-fed state rows, and a missing link renders "Unknown", never "Off". → [a220.md](../a220.md)

## A220-17

- A220 FD-command, trim and rudder-trim signs/scales were decoded from the aircraft's own rendering maths and are test-pinned — `cmd_lateral` + = bank RIGHT, `cmd_vertical_fpa` + = UP, `cmd_vertical_pitch` + = NOSE UP (the TO/GA cue, null otherwise), `rudder_trim` + = nose RIGHT with ±1 = FULL SCALE. Never re-derive one by eye: a wrong sign in a guidance readout is confidently wrong, not obviously broken. → [a220.md](../a220.md)

## A220-18

- ONE DisplayUnits inspector socket, owned by `A220DisplaysClient` — the display pump, FMS form, and ECL form all share it (`CallAgentAsync`); never open a second connection to that view. The EFB has its own view/client. → [a220.md](../a220.md)

## A220-19

- The A220 FMS is driven by `H:A220_KBD_*`/`H:A220_CTP_*` events (calc-path, seq-prefixed) + synthetic clicks on field value nodes — NEVER via the aircraft's hardware-keyboard Entry Mode (it disables ALL sim input; lethal trap for a blind user). The input authority is the UNENCRYPTED `ModelBehaviorDefs\Synaptic\A220\` on disk, not the JS bundles (pure renderers). → [a220.md](../a220.md)

## A220-20

- The A220 field-commit click hunt must SKIP GRAY tokens (a label is never a value) and rank INLINE (the label's own row) above BELOW before nearest-dx — the FUEL page right-aligns its labels into a column, so nearest-dx clicked GWT for ZFW and TAXI for BLOCK (live 2026-07-30). The agent's `bestValueNode` and `ParseFms` must stay identical, or the form reads one field and clicks another. → [a220.md](../a220.md)

## A220-21

- MKP typing is a LOSSY transport — a paced open-loop send drops keystrokes at random positions (live: `109270` → `10970`/`09270`/`1020`), so every character must be confirmed against the scratchpad tap before the next is sent; never "fix" a dropped keystroke by raising the inter-key delay. → [a220.md](../a220.md)

## A220-22

- The MKP CLEAR key is a ONE-CHAR backspace that ARMS `--DELETE--` on an empty scratchpad — never use it to "clear before typing"; a refused entry leaves its text in the scratchpad, so scratchpad clearing must go through the agent's `resetScratchpad()` store event with tap-confirmed emptiness + typed-buffer verification (`PredictScratchpadBuffer`), or every entry after one INVALID ENTRY concatenates into the next (live 2026-07-30 FUEL page). FMS FUEL page: FOB is NOT enterable on the ground (BLOCK/TAXI are the ground entries and are air-disabled), and entry ranges follow the aircraft's KG/LB setting — the "WT(LB)/WT(KG)" header is how the pilot tells. → [a220.md](../a220.md)

## A220-23

- ECL actuation goes item → `checklists.json` `"sensed"` NAME (a string, not an ABI index) → `A220EclActionMap` (all 215 vars mapped or explicitly excluded, coverage-pinned) → `HandleUIVariableSet`; MSFSBA never ticks a checkbox itself, item-at-a-time only, fire handles/thrust levers/sidestick stay excluded. → [a220.md](../a220.md)

## A220-24

- A220 CLOSED dropdowns must be detected structurally via React fibers (component with an `options` array + `onSelect` → `dd` flag on the value token → `FmsField.IsDropdown`), because a closed Fusion dropdown renders only its current value and is otherwise indistinguishable from a data row; Enter opens the list and must never type the scratchpad into a chooser. Never announce the closed dropdown's option count — the props array includes options the aircraft hides (plan selector says 3, opens 2). An open dropdown closes via `dropdownClose()`, never `taskMenuClose()` (which needs the menu frame and no-ops on a dropdown). → [a220.md](../a220.md)

## A220-25

- An A220 FMS follow-up dialog (direct-to's `INTC CRS`, HOLD, CROSSING, FIX, AIRWAYS…) must be read via `agent.fmsDialogTokens()` — scoped to the dialog's own `<g>` subtree — never by a geometric clip of the page: a dialog floats over the list, so a rect clip swallows the page text beneath it (live: RNP/DISCONTINUITY/DTG inside an INTC CRS dialog). Going direct DOES expose a settable course (`CRS` field → `ee.setCourse`); tspan runs must be space-joined ("HOLD ATRDS"), a value's separate gray unit label attached to it, and a graphic dialog's loose labels collapsed into one row so the entry field isn't buried. Each follow-up raises a MOD needing EXEC. → [a220.md](../a220.md)

## A220-26

- Every A220 LEGS-page action must be addressed by the aircraft's own `legIdx` read from React fibers (`agent.legs()` / `openLegMenuAt` / `deleteLegAt`, which CALL the row's real `onClick`/`onDelete` props), never by ident text + occurrence + geometry — duplicate idents and a list shifting under an edit made text addressing open the wrong waypoint's menu (live 2026-07-30).

## A220-27

- `Row.LegIdx` must be paired to the fiber `legs()` rows by CONTENT via `A220FmsLegParsing.AlignLegIndices` (ident match, disco ↔ placeholder, short lookahead, unmatched → -1), NEVER a positional zip — the fiber walk omits rows the grouper shows (origin, runway leg), so a zip shifted every index by 2 on a live plan (2026-07-30 evening): the disco addressed as a real waypoint (WRONG_ROW refusals) and twin-ident clicks landing on the wrong twin. → [a220.md](../a220.md)

## A220-28

- A discontinuity can SHARE its `legIdx` with a neighbouring waypoint: `legs()` must never dedupe rows by idx alone (only co-located same-idx texts), and same-idx actions must say which row they mean — `deleteLegAt(idx, true)` must REFUSE (`WRONG_ROW`) rather than run a non-placeholder row's `onDelete`. An idx-keyed dedupe shifted every row below a gap by one and DEL on the discontinuity silently deleted real waypoints until the plan collapsed into a ~710 nm direct (live 2026-07-30). → [a220.md](../a220.md)

## A220-29

- The ident node is found STRUCTURALLY (inside the row Input: props have both `onDelete` and `value`), never by x — the track line shares the row's left column and legIdx and is the earlier DOM node. A menu header is ident PLUS navaid detail ("KEA 115.00"), so compare the first token only. Deleting a discontinuity may raise the aircraft's real `SELECT CONSTRAINT` dialog (two identical SELECT buttons — name each by the value on its row); that is a prompt, not a failure. → [a220.md](../a220.md)

## A220-30

- The A220 LEGS revision menu opens ONLY from the row's fix-symbol icon (canvas x=144, `agent.openLegMenu`) — NEVER by clicking the waypoint ident: the ident is a Fusion scratchpad Input whose click COPIES (empty scratchpad) or SUBMITS (text) into the leg, which live-corrupted a flight plan (GENOS-over-RDS, 2026-07-30). The discontinuity delete must ABORT when `armStatus()` never confirms — an un-armed click submits the scratchpad instead of no-opping. → [a220.md](../a220.md)

## A220-31

- Every A220 FMS overlay (waypoint revision menu, dialog, open dropdown) must render MODALLY — one `agent.overlay()` call per poll, detected STRUCTURALLY from the renderer's constants (white-stroke menu / `#232323`+5px dialog / 41-unit transparent-rect dropdown column), with dialogs CLIPPED to their rect via `ClipTo` and Escape dismissing the overlay before the window. Never flatten an open overlay into the page rows — that was the "clunky/messy FMS" report. The FMS's amber rejection box (`#ffe300`, self-clears after 3 s) must be read out; it is the only place the aircraft says WHY an entry was refused. → [a220.md](../a220.md)

## A220-32

- A220 EFB `setField` must dispatch `keyup` in addition to `input`+`change`+`blur` — the EFB binds every Settings save handler (SimBrief ID → DataStore + `SetSimbriefUsername` CommBus push, which the FMS uplink AND loadsheet import both need) and the Takeoff-perf sanitizers to `el.onkeyup`; without the keyup the text sets visibly but never commits. → [a220.md](../a220.md)
