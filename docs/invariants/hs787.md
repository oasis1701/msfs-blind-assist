# HorizonSim 787-9 — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/hs787.md`, which Claude Code loads when it reads matching code. Background: [hs787.md](../hs787.md).
The text is verbatim from CLAUDE.md as of `1f37801a`; a trailing "→ doc" pointer is the original's. Cross-references such as "the bullet below", "above" or "under Core" point at CLAUDE.md's old single list, whose rules now live in several files: search `docs/invariants/` for the rule's key name to find it.

## HS-1

- The HS787 EFB is intentionally REMOVED — its perf-page inputs cannot be driven externally (a custom MSFS keyboard mechanism rejects both programmatic value-set and synthetic keyboard events); never re-attempt driving it without a different input mechanism. → [hs787.md](../hs787.md)

## HS-2

- The realistic "TIME TO ALIGN" IRS state must be read from the ND/PFD `.time-to-align` DOM element, never inferred from `WT_IRS_POS_SET_N` alone — that L:var means "position accepted," not "alignment complete." → [hs787.md](../hs787.md)

## HS-3

- The WT787 `boeing-mfd-button` component reacts to MOUSE events — `clickElement` must dispatch the full pointerdown/mousedown/pointerup/mouseup/click sequence, or CDU page-key navigation silently does nothing (LSKs alone still work, masking the bug). → [hs787.md](../hs787.md)

## HS-5

- A display-only Flight Data sub-panel must have a (even empty) `BuildPanelControls` entry, or MainForm's panel-build logic early-returns and the panel renders nothing. → [hs787.md](../hs787.md)

## HS-6

- Before concluding an HS787 readout is "dead," confirm the aircraft isn't in a genuine failure state — several "dead" readouts were actually correct values during a fuel-exhaustion failure. → [hs787.md](../hs787.md)

## HS-7

- APU generator control must use the un-indexed `APU_GENERATOR_SWITCH_SET` (ganged both gens) — the per-index `APU_GEN1/2_SWITCH_SET` events are no-ops. → [hs787.md](../hs787.md)

## HS-8

- Autobrake control must step `INCREASE/DECREASE_AUTOBRAKE_CONTROL` toward the target and read `AUTO BRAKE SWITCH CB` — `SET_AUTOBRAKE_CONTROL` is a no-op and `AUTOBRAKE CONTROL SWITCH POSITION` is stuck at 0. → [hs787.md](../hs787.md)

## HS-9

- Strobe light control must use `STROBES_SET`, not `STROBE_LIGHTS_SET` (a no-op on the Asobo-template lighting). → [hs787.md](../hs787.md)

## HS-10

- The Community-folder HS787 bridge (HTML patching + injected JS) is fully removed on both sims — never reinstate the installer; the Coherent transport needs no Community mod and no sim restart. → [hs787.md](../hs787.md)

## HS-11

- The 787 altimeter is set with `K:KOHLSMAN_SET` in MILLIBARS × 16 (`HS787Altimeter.KohlsmanSetParameter`), never inches × 16: inches × 16 is about 29.9 mb, which the sim clamps to its floor, so every Ctrl+B entry set 948 hPa / 27.99 inHg and the dialog's STD button said "Not set" (fixed 2026-11-19; measured live on the HorizonSim 787-9: 16208 sets 1013 hPa, 16320 sets 1020). STD is the aircraft's own captain-altimeter toggle, `K:BAROMETRIC_STD_PRESSURE` with parameter 1 (the WT `AltimeterBaroKeyEventHandler`), and its state is `L:XMLVAR_Baro1_ForcedToSTD` (`HS787_BaroSTD`) — the flag the PFD shows "STD" from; switching it off restores the QNH set before. Never write `L:XMLVAR_Baro_Selector_STD_1` (nothing in the avionics reads it) and never fire the event without the index (it jumps to 1013.25 without engaging STD, so "back to QNH" stayed on 1013). A QNH typed while STD is on switches STD off first, then sets the value; sent back to back the set wins over STD's own restore (measured). → [hs787.md](../hs787.md)

## HS-12

- The CDU agent finds PREV PAGE and NEXT PAGE by their LABEL (`A.PAGE_LABEL`), never by position: the page-button DOM order, captured live 2026-11-19, ends `… PREV PAGE, NEXT PAGE, CLR MSG` (CLR MSG lives in `.wt787-cdu-message-controls`), so the old "last two buttons" rule sent PageUp to NEXT PAGE and PageDown to CLR MSG — PageDown did nothing and PageUp paged forward, which pilots reported as "inverted". A fixed 14/15 index is wrong too, because OFST/RTA are conditional. → [hs787.md](../hs787.md)

## HS-13

- A Flight Data navigation row must be READ in the unit the avionics write it in (`HS787FlightData`, from each var's `SimVarValueType` in the MFD bundle), never the default `"number"`: an L:var read as "number" returns the sim's base unit — metres, radians, metres per second — whatever unit the aircraft wrote. Measured live 2026-11-19: `WTBoeing_LNavData_Destination_Distance_Direct` read 1,850,148 as "number" and 999 as nautical miles, and a 90° scratch L:var read 1.5708. That is how a trans-oceanic destination distance read "13653434". The same applies to ANY L:var with a real unit on any aircraft: a units-free registration of a distance, angle or speed is a bug. → [hs787.md](../hs787.md)
