# Cessna 172 Skyhawk — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/c172.md`, which Claude Code loads when it reads matching code. Background: [c172.md](../c172.md).

Every measurement here was taken on 2026-10-16 on MSFS 2024's stock "C172SP G1000 Passengers Skis", over SimConnect (a scratch harness running MSFSBA's own `SimConnectManager` and `CessnaC172G1000Definition`) and the Coherent debugger (`SimVar.GetSimVarValue`, which reads B: input events too, though it cannot write them). The Classic variant has not been measured.

## C172-1

- **The main battery is index 2.** With both batteries on, battery 2 carried the whole load (about 20 A) and battery 1, at a higher voltage, carried none. Switching index 2 off alone killed every circuit; switching index 1 off alone changed nothing while the main battery was up. The cockpit's battery master input event, `ELECTRICAL_BATTERY_1`, follows index 2 (setting it to 0 set `ELECTRICAL MASTER BATTERY:2` to 0 and left index 1 alone). The port read index 1 as the master and index 2 as the standby, the wrong way round.
- **`TOGGLE_MASTER_BATTERY` with parameter 0 flips BOTH batteries**; with parameter n it flips only battery n. The panel's master combo sent it with no index, so a misread (the flight starts with the standby armed and the master off, which the port's index-1 read showed as "On") put both batteries the opposite way to the one chosen. The G1000's old "Standby Battery Toggle" button sent parameter 2 through MainForm's plain event-button path (which never calls `HandleUIVariableSet`) and so switched off the MAIN battery. → [c172.md](../c172.md)

## C172-2

- **Write the input event, with the value.** Setting a cockpit input event is what the cockpit switch does, so a combo set is deterministic and a misread can never move the switch the wrong way. The stock events the port used do not all reach this cockpit: `AVIONICS_MASTER_1_SET`/`_2_SET` moved only `AVIONICS MASTER SWITCH:n` and left the avionics switches and buses where they were (bus 2's nine circuits stayed dark); `FUEL_SELECTOR_SET` did nothing at all. `SwitchInputEvents` names each switch's event; a combo's value is the event's value (magneto 0 Off, 1 Right, 2 Left, 3 Both; standby battery 0 ARM, 1 OFF; fuel valve 0 closed, 1 open).
- **Read what the switch drives.** The new fuel system's `FUELSYSTEM PUMP SWITCH:1` and `FUELSYSTEM VALVE SWITCH:1`, never `GENERAL ENG FUEL PUMP SWITCH:1` (never moved) or `GENERAL ENG FUEL VALVE:1` (stayed 1 with the valve shut). `PITOT HEAT SWITCH:1`, never `PITOT HEAT` (stayed 0). The lights' `LIGHT NAV` (and BEACON, STROBE, LANDING, TAXI), never `LIGHT NAV ON`, which is 1 only while the lamp is lit: with the battery off a switched-on light read Off.
- **Three switches drive nothing a SimVar reports**, so they are read from the input event itself (`SimVarType.InputEvent`, SIM-23): both avionics buses (bus 1's loads are all dual-fed from the essential bus, so no circuit changes when it moves) and the standby battery (`ELECTRICAL MASTER BATTERY:1` stays 1 in both positions; only the battery's load changes). The magneto key is read the same way, because no SimVar holds its position (`RECIP ENG LEFT MAGNETO:1` is one magneto, a Bool).
- Before the input-event catalog arrives (a few seconds after the aircraft loads) no write can land, and the pilot hears a refusal rather than a silent fallback to the events measured not to work. → [c172.md](../c172.md)

## C172-3

- **The GFC 700's keys are pressed.** Each `AS1000_AUTOPILOT_<KEY>_PFD` set to 1 is one press of the bezel key; 0 does nothing. Measured key by key: AP engaged AP and FD in ROL and PIT and a second press disengaged it; FD was refused while the autopilot flew; HDG, ALT (holding the current altitude) and VS engaged; VERTICALSPEED_UP/DOWN stepped the VS target 100 fpm; FLC was refused until an altitude was selected, then engaged with ALTS armed; NAV, VNV, APR and BC did nothing on the ground with no flight plan or signal, as the real unit does. Marshall's "NAV refused while HDG is on" was this autopilot arming, not a fault, and his turn-HDG-off-first workaround is gone.
- **The selected altitude.** `AP_ALT_VAR_SET_ENGLISH` ignores its value on this G1000: the first one set the current altitude rounded up to the next 100 ft and each later one added 1,000 ft (as DA40A-2 found on the DA40). `ShowSelectedAltitudeDialog` sends one `AP_ALT_VAR_INC` (which marks the altitude SELECTED; a direct write alone leaves FLC refused) and half a second later writes the exact value to `AUTOPILOT ALTITUDE LOCK VAR` with a data-definition write. Both are SimConnect, so no MobiFlight is needed; measured 6000 and 3500 exact, and FLC engaged after it on a fresh flight. `HEADING_BUG_SET`, `AP_VS_VAR_SET_ENGLISH` (a descent as 32-bit two's complement) and `KOHLSMAN_SET` (millibars × 16) land exactly as sent. → [c172.md](../c172.md)

## C172-4

- **MSFS 2024 can park the aeroplane with its walkaround covers fitted, and an engine with its cover in does not run.** On a fresh cold-and-dark flight `COVER ON:1`, `:2` and `:3` were all 1; the sim's own autostart cranked for ten seconds with no fuel flow and gave up, and MSFSBA's Starter did the same. With the covers off, one press of the Starter started the engine at once.
- The input events `UNKNOWN_COVER_ENGINE`, `UNKNOWN_COVER_PITOT` and `UNKNOWN_COVER_STATIC_PORT` each TOGGLE their cover (the B: value stays 0); one press at a time showed engine = `COVER ON:1`, pitot = 2, static port = 3. A toggle pressed against a stale state puts the cover the wrong way, so `SetCoverAsync` presses only after a fresh read says the cover differs from what the pilot chose (a second "Installed" leaves it installed, measured). The covers are announced, so the Starter can say "Engine cover installed" from the cache before it cranks. → [c172.md](../c172.md)

## C172-5

- **Measured by which tank drained**, with the engine at 1,500 rpm for 40 s a setting: on junction setting 1 only the left tank dropped (0.048 gal), on 2 both dropped equally (0.024 each), on 3 only the right. The selector's input value 0, 1, 2 sets the junction to 1, 2, 3. The cold-and-dark flight starts on setting 1, LEFT; the sim's autostart moves it to BOTH. The provisional labels written before the measurement (1 Both, 2 Left, 3 Right) were wrong, which is why a label is never taken from an assumed order. → [c172.md](../c172.md)
