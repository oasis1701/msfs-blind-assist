# VirtualPilot harness hooks — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/virtual-pilot.md`, which Claude Code loads when it reads matching code. Background: [virtual-pilot.md](../virtual-pilot.md).
These rules came with the taxi/landing port (`feat/taxi-landing-port`) and are verbatim from that branch's CLAUDE.md as of `4854ec3d`; a trailing "→ doc" pointer is the original's.

## VP-1

- The VirtualPilot hooks (`SimClock.Override`, `TaxiSteeringTone.Headless`, `Log.Redirect`, the `…ForHarness` accessors and `Legacy…ForHarness` A/B switches) are internal and must stay INERT in the app — never set one outside `tools/VirtualPilot`. Any new clock read in the taxi/rollout guidance must go through `SimClock.UtcNow`, or the harness's simulated seconds silently stop applying to it. → [virtual-pilot.md](../virtual-pilot.md)
- Visual guidance joined the harness on 2026-11-02 (the approach mode): its hooks are `VisualGuidanceManager.HeadlessForHarness` (an instance `init` flag, so tests that set it need no shared collection) and the `DesiredPitchForHarness`, `DesiredBankForHarness` and `PhaseForHarness` accessors, and every clock read in `VisualGuidanceManager` goes through `SimClock.UtcNow`; `VisualGuidanceHarnessHookTests.Visual_guidance_reads_time_only_through_SimClock` pins the clock. Since stage 2 of the redesign (2026-11-04) those reads go through the instance `ClockForHarness`, an `init` property that defaults to `SimClock.UtcNow` in the app (and so to the harness's override), and lets unit tests such as `VisualGuidanceRealTimeTests` give each manager its own clock without a shared `SimClock.Override`, as `GroundTrafficMonitor`'s injected clock does (TRF-11). The clock test also rejects `DateTime.Now`, `DateTimeOffset`, `Environment.TickCount` and `Stopwatch`.
