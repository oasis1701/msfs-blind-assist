# VirtualPilot harness hooks — rules in full

Each section is the complete text of one rule. Its one-line form, under the same ID, is in `.claude/rules/virtual-pilot.md`, which Claude Code loads when it reads matching code. Background: [virtual-pilot.md](../virtual-pilot.md).
These rules came with the taxi/landing port (`feat/taxi-landing-port`) and are verbatim from that branch's CLAUDE.md as of `4854ec3d`; a trailing "→ doc" pointer is the original's.

## VP-1

- The VirtualPilot hooks (`SimClock.Override`, `TaxiSteeringTone.Headless`, `Log.Redirect`, the `…ForHarness` accessors and `Legacy…ForHarness` A/B switches) are internal and must stay INERT in the app — never set one outside `tools/VirtualPilot`. Any new clock read in the taxi/rollout guidance must go through `SimClock.UtcNow`, or the harness's simulated seconds silently stop applying to it. → [virtual-pilot.md](../virtual-pilot.md)
- Visual guidance joined the harness on 2026-11-02 (the approach mode): its hooks are `VisualGuidanceManager.HeadlessForHarness` (an instance `init` flag, so tests that set it need no shared collection) and the `DesiredPitchForHarness`, `DesiredBankForHarness` and `PhaseForHarness` accessors, and every clock read in `VisualGuidanceManager` goes through `SimClock.UtcNow`; `VisualGuidanceHarnessHookTests.Visual_guidance_reads_time_only_through_SimClock` pins the clock. Since stage 2 of the redesign (2026-11-04) those reads go through the instance `ClockForHarness`, an `init` property that defaults to `SimClock.UtcNow` in the app (and so to the harness's override), and lets unit tests such as `VisualGuidanceRealTimeTests` give each manager its own clock without a shared `SimClock.Override`, as `GroundTrafficMonitor`'s injected clock does (TRF-11). The clock test also rejects `DateTime.Now`, `DateTimeOffset`, `Environment.TickCount` and `Stopwatch`.
- Stage 3 (2026-11-04) added `FlightRecordForHarness`, an instance `init` sink for the flight recording (VP-2). The app never sets it, so its lines go to `visual_guidance_flight.log`; the harness gives each run its own sink (a file with `--record`, else none), and unit tests give `VisualGuidanceTestRig` theirs. The harness sets it by reflection so it still builds against an app from before the recording (the baseline procedure flies today's harness against the stage-1 app); its self-test's `record-hook` check fails if the hook is renamed.
- Stage 4 (joining final, 2026-11-04) added `CaptureGainForHarness`, an instance `init` property defaulting to `VisualGuidanceJoin.DefaultCaptureGain`, which the harness's `--capture-gain K` sets by reflection to sweep the gain (the app never sets it), and the read-only `DecisionForHarness` (OnFinal, Joining, Vectoring or Pattern, "None" before the decision), which the joining keys of the results line read. Both are reached by reflection, so the harness still builds and flies against an app from before stage 4: `--capture-gain` refuses to run there, and the decision keys read `NA`.

## VP-2

- Every visual guidance update writes one `VisualGuidanceFlightRecord.Frame` line through `VisualGuidanceManager.FlightRecordForHarness`, with a `start` line at `Initialize`, a `say` line for everything the manager speaks (all of it goes through its `Say`), and a `stop` line at `Stop`. `tools/VirtualPilot/analyze_vg_flight.py` parses those lines by key, so a field or format change edits the record and the script together, and every number stays in the invariant culture (`VisualGuidanceFlightRecordTests` pins the frame line, under sv-SE and de-DE too). → [virtual-pilot.md](../virtual-pilot.md), "Flight recordings"
- Why: the owner finds sim testing slow and their own flying error-prone, so every test flight is recorded and measured with the harness's own measures instead of judged by feel (decided 2026-11-04; not in the redesign's spec). The script reproduces the harness on its own runs: on `FINAL-A-JET-x0.2R-h+200-d0.5` cross-track and path RMS to 0.1 ft, the command rates within 1.2 %, the touchdown sink exactly; on `NOISE-A-JET-f30` the sensor noise within 2 % of the assumed spreads.
- Precision is per field, not uniform: at two decimals cross-track in nautical miles resolves 61 ft and a command moving 0.0007° a frame turns into 0.01° steps, and the script could no longer reproduce the harness.
