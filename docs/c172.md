# Cessna 172 Skyhawk

> **Read this when:** working on the Cessna 172 Skyhawk, either the Classic (steam gauges) or the G1000.

## Where it came from

Marshall Fairbrother wrote the C172 on his fork (`MarshallF03/msfs-blind-assist`); his last C172 commit was on 2026-06-01, on that fork's `build/citation-longitude` branch. It was brought over on 2026-10-16, on top of the COWS DA40 (#242), with his definitions unchanged apart from the API rename (`GetVariables()` became `BuildVariables()`) and the fixes listed under each section below. The C172 builds on #242 because its G1000 is flown through #242's G1000 windows: without them it is not flyable, so it follows #242 into `main`.

His G1000 NXi flight-plan navigator was **not** brought over: a Coherent GT client (`CoherentGTClient`, `G1000FmsClient`), the `G1000NavigatorForm` window on Shift+M, and a SimBrief route loader built on them. The shared G1000 work from the COWS DA40 (#242) replaces it.

The same day the G1000 was audited live, control by control, on MSFS 2024's stock "C172SP G1000" (below, and the rules in `docs/invariants/c172.md`). Most of the port's G1000 controls read the wrong variable or wrote an event this cockpit ignores; they were rebuilt on the measurements. The Classic has not been audited and still runs the port's definitions.

## The G1000 windows

The G1000 opens the COWS DA40's `Forms/DA40/CowsDA40DisplayForm` on the same views (`AS1000_PFD`, `AS1000_MFD`): the stock Working Title G1000 is the same instrument in both aircraft (the DA40's G1000 agent also read the C172's CAS and FMA during the audit). `CessnaC172G1000Definition.HandleHotkeyAction` takes the DA40's keys: Alt+P for the PFD; Alt+M, Alt+N and input-mode Shift+M for the MFD (`CowsDA40Definition.OpensMfdWindow`). The windows are tracked (`ShowTrackedWindow`), so a second press focuses the open one and an aircraft switch closes them.

No owner is passed to the form. What it hands its owner (CAS rows to announce, display units, radio-tune notes) are DA40 callbacks, so on the C172 the CAS is listed in the PFD window but not announced by itself. Marshall's navigator worked differently: it drove the flight plan through the FMS's own API with buttons of its own (insert waypoint, "Set up ILS"); this window reads the screens and presses the real bezel keys, as a sighted pilot operates the G1000.

## Shape

All three files are in `MSFSBlindAssist/Aircraft/C172/`.

| File | Aircraft code | What it adds |
| --- | --- | --- |
| `CessnaC172BaseDefinition.cs` | (abstract) | Everything both variants share: electrical, engine, fuel, lights, flaps and parking brake, the KAP140 autopilot, COM/NAV radios, transponder, annunciator test, pitot heat, alternate static, the background warnings and the hotkeys. Subclasses add variables through `GetC172Variables()`. |
| `CessnaC172ClassicDefinition.cs` | `C172_CLASSIC` | The airspeed true-airspeed calibrator (Instruments section) and an earlier vacuum caution, because the attitude and heading indicators run on vacuum. |
| `CessnaC172G1000Definition.cs` | `C172_G1000` | The audited G1000: every switch written through its cockpit input event, the reads fixed, the standby battery, the walkaround covers, the GFC 700 in place of the KAP140, and the selected-altitude dialog. |

## Transport

Over SimConnect only: no MobiFlight, no WASM. The Classic writes stock K: events through `_stateToEventMap` in the base definition (a toggle event ignores the chosen value, a set event passes it).

The G1000 writes cockpit **input events** (B: events) with an explicit value, the way the cockpit switch does (C172-2): `SwitchInputEvents` for the switches, `AutopilotKeys` for the GFC 700's bezel keys, `CoverInputEvents` for the covers. Four of its states are READ from the input event too, through the shared input-event subscription (SIM-23): both avionics buses, the standby battery and the magneto key, which no SimVar reports. The input-event catalog arrives a few seconds after the aircraft loads; a write before then is refused aloud.

The GFC 700 panel has a button for each key on the G1000 bezel: Autopilot (AP), Flight Director, HDG, NAV, APR, Back Course, ALT, VS, FLC, VNAV, Nose Up and Nose Down, each pressing the real key (C172-3), then the heading bug, selected altitude, VS target and FLC airspeed. A mode button shows its state. Nose Up and Nose Down say the target they moved, interrupting the last one so a run of presses reads fast: the VS target in VS, the airspeed in FLC, the pitch in PIT (the mode the autopilot engages in, read from `AUTOPILOT PITCH HOLD REF`, negative for nose up); in ALT they move nothing in this sim (measured: the FMA's held altitude stayed put), and say so. VNAV, which has no state to read, says "VNAV pressed".

The Covers panel lists the engine, pitot and static-port covers, Installed or Removed (C172-4).

The Circuit Breakers section has the cockpit's 30 breakers, each In or Pulled, on four panels by the bus each was measured on (C172-7). What pulling each one did, engine off, with the loads switched on:

| Panel | Breaker (catalog name) | Pulled, it cut |
| --- | --- | --- |
| Essential Bus | PFD (`ESS_PFD`), ADC (`ESS_ADC`), Nav 1 (`ESS_NAV1`) | nothing alone: each is also fed through avionics bus 1; both pulled cut circuits 3, 6 and 35 |
| Essential Bus | Com 1 (`ESS_COMM1`) | circuit 37 |
| Essential Bus | Standby Indicator (`ESS_STBY_IND`) | circuit 5 |
| Essential Bus | Standby Battery (`ESS_STBY_BATT`) | the whole essential bus, with the standby on ARM and the master off |
| Avionics Bus 1 | Avionics Bus 1 (`AVN1`), PFD, ADC, Nav 1 | nothing alone: every avionics bus 1 load is also fed from the essential bus |
| Avionics Bus 1 | FIS (`AVN1_FIS`) | circuit 7 |
| Avionics Bus 2 | Avionics Bus 2 (`AVN2`) | the whole bus: circuits 4, 32, 33, 34, 36, 38, 39, 40, 41 |
| Avionics Bus 2 | MFD (`AVN2_MDF`, the catalog's spelling), Nav 2, Com 2, Audio Panel, Autopilot, Transponder (`XPNDR`) | circuits 4, 36, 38, 39, 40, 33 |
| Systems and Lights | Nav Lights, Beacon, Landing Light, Taxi Light (`RECOG`), Strobe Lights | circuits 14-16, 17, 18, 19, 20-21 |
| Systems and Lights | Lights Power (`LTS_PWR`), Warning (`WARN`), Fuel Pump | circuits 28-29, 42, 9 |
| Systems and Lights | Flaps, Pitot Heat | flagged pulled (circuits 11, 12); neither circuit was running to cut |
| Systems and Lights | Alternator Field (`ALT_FLD`), Panel Lights (`PANELS_LTS`) | nothing seen: the engine was off, and the panel lights' dimmer was down |

`RECOG` is spoken as the taxi light because the circuit it cut is the one the taxi light switch lit. A breaker that pops by itself (or goes back in) is spoken, "Fuel Pump breaker popped"; the pilot's own pulls are not (C172-7).

The Cabin Controls panel has cabin heat and cabin air in quarter steps, Closed to Open (percent in and out over SimConnect; the Coherent debugger shows the same lever as a fraction, which misled the first build, C172-9), and the pilot's and passenger's windows, Open or Closed, read from where each window is. The cabin door is not there and must never be added (C172-8).

The ELT panel has the ELT switch, On or Arm. On transmits (`ELT ACTIVATED`), and Arm is where it rests; going back to Arm stops a transmission, which is how the real ELT is reset.

On the G1000 the Starter (Engine Controls) turns the key to START, which cranks for about 3 seconds and springs back to BOTH by itself; a cold engine that needs longer is pressed again. It cannot be held longer: nothing MSFSBA can send keeps the key on START past its spring-back, and a crank kept going by re-pressing cuts out every 3 seconds (C172-6). It says "Engine cover installed" first if it is.

## Background announcements

Each warning speaks once when it crosses its threshold and re-arms when the value recovers:

- left or right fuel below 5 gallons;
- oil pressure at or below 20 psi (above 0, so a stopped engine is quiet);
- vacuum below 3.5 inHg on the G1000; on the Classic a caution below 4.0 inHg replaces it;
- engine RPM above 2700;
- the stall warning, on and off;
- each autopilot mode (AP, HDG, ALT, NAV, APR, BC, VS; on the G1000 also the flight director and FLC) as it engages and disengages;
- on the G1000, a walkaround cover installed or removed;
- on the G1000, a circuit breaker that pops or goes back in by itself (no Ctrl+M row).

The autopilot's own trimming is not spoken (both variants): the shared Shift+T announcer re-bases silently while the autopilot is engaged, as the DA40 does, so the first pilot trim after a disconnect speaks only what the pilot moved. The GFC 700 FMA's ARMED modes (ALTS, GS, a NAV source armed) are not announced: no SimVar carries them, only the PFD, and the DA40's FMA watcher is tied to #242's window (an open question for the owner).

Oil temperature, EGT, fuel flow and bus voltage are read continuously for the status displays and the hotkeys, and never spoken by themselves, so they carry `ExcludeFromMonitorManager` and have no Ctrl+M row (VAR-9, pinned by `CessnaC172MonitorRowsTests`).

Ctrl+M opens `Forms/C172/CessnaC172MonitorManagerForm`, one window and one list (`UserSettings.C172DisabledMonitorVariables`) for both variants. The warnings above are spoken from inside `ProcessSimVarUpdate`, so the C172 is in `Services/DefAnnounceMuteSets` and an unticked row mutes its warning through MainForm's `announcer.Suppressed` wrap (VAR-8). The window is rebuilt on every aircraft switch, Classic to G1000 included, because the two variants list different variables.

## Hotkeys

The pilot's list is `HotkeyGuides/Cessna_C172_Hotkeys.txt`, shared by both variants. It names only keys whose handler runs on the C172: the app-wide ones in MainForm, the base class's (local and Zulu time), and the C172's own in `HandleHotkeyAction` (fuel in gallons, flaps, fixed gear, altimeter, gross weight, the autopilot vertical speed, Ctrl+M, and the heading bug, altitude, vertical speed and altimeter dialogs). On the G1000 the autopilot hotkeys (AP, HDG, FLC, APR) press the GFC 700's keys, and the altitude dialog uses the measured selection sequence (C172-3). Shift+M in input mode opens the G1000 MFD window on the G1000; on the Classic it takes `McduWindowRouting`'s answer for an aircraft with no MCDU.

## Measured live (2026-10-16, G1000)

The audit's measurements are in `docs/invariants/c172.md`, one rule per finding. In short:

- **Electrical.** The main battery is index 2, the standby index 1, and a bare `TOGGLE_MASTER_BATTERY` flips both (C172-1). The standby switch is ARM (0) or OFF (1) and the flight starts OFF. The avionics bus switches are input events that `AVIONICS_MASTER_n_SET` never touches.
- **Engine and fuel.** The magneto key reads 0 Off, 1 Right, 2 Left, 3 Both, 4 Start; START springs back to BOTH 3.0 to 3.6 s in, and one press of the Starter started the engine first time (C172-6). The fuel pump, valve and selector are the new fuel system's (C172-2, C172-5); the flight starts with the selector on LEFT. The mixture's `MIXTURE1_SET` and the flaps' `FLAPS_INCR`/`FLAPS_DECR` were already right.
- **Lights and anti-ice.** The light SimVars with ON report the lamp, not the switch; pitot heat's switch is `PITOT HEAT SWITCH:1`.
- **Covers.** The cold-and-dark flight starts with the engine, pitot and static-port covers fitted, and the engine will not start with its cover in, autostart included (C172-4).
- **GFC 700.** Not a KAP140: the owner's cockpit picture shows the AP, FD, HDG, ALT, NAV, VNV, APR, BC, VS and FLC keys and nose wheel on both bezels, and the Coherent page list holds no KAP140 gauge. Each key and the value setters measured (C172-3).
- **The two fixes made at the port, now verified.** Ctrl+B: `KOHLSMAN_SET` 16320 set 1020 hPa / 30.12 inHg (Marshall had sent inches × 16). Ctrl+V: a descent sent as the 32-bit two's complement landed as −500 fpm (Marshall had sent 65536 plus the rate).

Marshall's 2026-05-31 note that NAV is "refused while heading hold is on" was the GFC 700 arming NAV, not a fault; his turn-HDG-off-first workaround was removed with the KAP140 modelling.

## Not yet confirmed

- **The Classic.** Not audited. It shares the base definition's reads and toggles, several of which were wrong on the G1000 (the fuel system, pitot heat, the light SimVars, the magneto, the avionics events), so it very likely has the same faults; it needs its own measurement before anything is changed. Its Starter sends `MAGNETO1_SET` 3 and `SET_STARTER1_HELD` 1, and on the G1000 the cockpit undid `SET_STARTER1_HELD` within one frame (C172-6), so it may not crank at all.
- **The magneto key's bounce.** A set of the key has been seen to settle somewhere other than where it was sent: START from BOTH back to BOTH after 150 to 180 ms (3 of 17 times, which the Starter's backup set covers, C172-6), and once OFF onto RIGHT about 100 ms later, when the Magneto combo was arrowed Left, Right, Off with 0.2 to 0.25 s between steps. Stepped the same way at 0.6 to 0.7 s, OFF held and the engine stopped (the owner's test, 2026-10-16), so it looks tied to writes in quick succession; not measured further.
- **The standby battery's TEST position.** It exists as a switch position and does nothing else that can be measured (2026-10-16, per-frame recorder, cold and dark). `ELECTRICAL_BATTERY_STBY_2` set to 2 reads 2 for 0.24 to 0.37 s, then springs back to OFF (1) by itself, from ARM as well, like the real spring-loaded switch; −1 is ignored. The control check worked: ARM with the master off made the standby battery supply 15.5 A and switched on circuits 0, 3, 5, 6, 7, 31, 35 and 37 (the essential bus, as the real preflight's "PFD comes on"). TEST drew nothing and switched on no circuit: from ARM it dropped all eight at once, so electrically it is OFF. A TEST lamp, if the cockpit draws one, is not readable from outside. The earlier note that the event takes only 0 and 1 came from a probe too slow to see it; a first run with the engine running showed nothing either way, because the alternator carried every load (ARM drew 0 A too). The panel keeps ARM and OFF.
- **The ELT's third position.** `SAFETY_ELT_1` also holds 2, which stopped a transmission like ARM and did nothing from ARM; its placard name is not known, so the panel offers On and Arm only. `ELT ACTIVATED` going on by itself (a hard landing trips a real ELT) could be announced; not built.
- **Number parsing.** #242 branched before `Utils.NumberParsing` reached `main`, so the heading, altitude, vertical speed and baro validators use `double.TryParse`, as #242's `ShowFCUInputDialog` does. Once this branch takes `main` (after #242 merges), switch them to `NumberParsing.TryParseTyped` (CORE-17).
