# Cessna 172 Skyhawk

> **Read this when:** working on the Cessna 172 Skyhawk, either the Classic (steam gauges) or the G1000.

## Where it came from

Marshall Fairbrother wrote the C172 on his fork (`MarshallF03/msfs-blind-assist`); his last C172 commit was on 2026-06-01, on that fork's `build/citation-longitude` branch. It was brought onto `main` on 2026-10-16 with his definitions unchanged apart from the API rename (`GetVariables()` became `BuildVariables()`) and the fixes listed under each section below.

His G1000 NXi flight-plan navigator was **not** brought over: a Coherent GT client (`CoherentGTClient`, `G1000FmsClient`), the `G1000NavigatorForm` window on Shift+M, and a SimBrief route loader built on them. The shared G1000 work from the COWS DA40 (#242) replaces it.

## Shape

All three files are in `MSFSBlindAssist/Aircraft/C172/`.

| File | Aircraft code | What it adds |
| --- | --- | --- |
| `CessnaC172BaseDefinition.cs` | (abstract) | Everything both variants share: electrical, engine, fuel, lights, flaps and parking brake, the KAP140 autopilot, COM/NAV radios, transponder, annunciator test, pitot heat, alternate static, the background warnings and the hotkeys. Subclasses add variables through `GetC172Variables()`. |
| `CessnaC172ClassicDefinition.cs` | `C172_CLASSIC` | The airspeed true-airspeed calibrator (Instruments section) and an earlier vacuum caution, because the attitude and heading indicators run on vacuum. |
| `CessnaC172G1000Definition.cs` | `C172_G1000` | The standby battery (switch, toggle, test) and the NAV-mode engagement described below. |

## Transport

Stock SimVars and K: events over SimConnect only: no WASM, no MobiFlight, no Coherent debugger. The one L:var is `XMLVAR_STBYBattery_Test`, the G1000's standby battery test switch. A combo box on a state SimVar sends its event through `_stateToEventMap` in the base definition: a toggle event ignores the chosen value, a set event passes it.

## Background announcements

Each warning speaks once when it crosses its threshold and re-arms when the value recovers:

- left or right fuel below 5 gallons;
- oil pressure at or below 20 psi (above 0, so a stopped engine is quiet);
- vacuum below 3.5 inHg on the G1000; on the Classic a caution below 4.0 inHg replaces it;
- engine RPM above 2700;
- the stall warning, on and off;
- each KAP140 mode (AP, HDG, ALT, NAV, APR, BC, VS) as it engages and disengages.

Oil temperature, EGT, fuel flow and bus voltage are read continuously for the status displays and the hotkeys, and never spoken by themselves, so they carry `ExcludeFromMonitorManager` and have no Ctrl+M row (VAR-9, pinned by `CessnaC172MonitorRowsTests`).

Ctrl+M opens `Forms/C172/CessnaC172MonitorManagerForm`, one window and one list (`UserSettings.C172DisabledMonitorVariables`) for both variants. The warnings above are spoken from inside `ProcessSimVarUpdate`, so the C172 is in `Services/DefAnnounceMuteSets` and an unticked row mutes its warning through MainForm's `announcer.Suppressed` wrap (VAR-8). The window is rebuilt on every aircraft switch, Classic to G1000 included, because the two variants list different variables.

## Hotkeys

The pilot's list is `HotkeyGuides/Cessna_C172_Hotkeys.txt`, shared by both variants. It names only keys whose handler runs on the C172: the app-wide ones in MainForm, the base class's (local and Zulu time), and the C172's own in `HandleHotkeyAction` (fuel in gallons, flaps, fixed gear, altimeter, gross weight, the KAP140 vertical speed, Ctrl+M, and the heading bug, altitude, vertical speed and altimeter dialogs). Shift+M in input mode says the C172 has no flight management window instead of falling through to the Fenix MCDU.

## Measured live (Marshall, 2026-05-31, G1000)

- NAV mode engages with `AP_NAV1_HOLD`. `AP_PANEL_NAV1_HOLD` does nothing on this aircraft.
- `AP_NAV1_HOLD` is refused while heading hold is on, so the G1000 definition's NAV button turns heading hold off first, waits half a second, sends `AP_NAV1_HOLD`, and reads the NAV state back. Marshall's version waited inside `Task.Run`, which sent the event off the UI thread; since the port the delays are awaited on the UI thread instead (SIM-20), with the same order and timings.

## Changed since the port, to verify in the simulator

- **Altimeter (Ctrl+B).** Marshall sent the typed inches times 16 to `KOHLSMAN_SET`, which takes millibars times 16 (the A380's live check: 16320 set 1020 hPa), so 29.92 would have set about 30 hPa. The dialog now converts inches to millibars first.
- **Negative vertical speed (Ctrl+V).** Marshall sent a descent as 65536 plus the rate, a 16-bit form `AP_VS_VAR_SET_ENGLISH` reads as a large climb. It now sends the 32-bit two's complement, as the HS787 does.

## Not yet confirmed

- **Autopilot type on the G1000.** Both variants model a KAP140. Marshall's NAV-mode test above was on the G1000 and behaved like one, but whether the stock C172 G1000 carries the KAP140 or a GFC 700 has not been checked against the aircraft's own panel files: on MSFS 2024 the package is streamed, so they cannot be read offline.
- **Starter.** The Starter button sets `SET_STARTER1_HELD` to 1 and nothing releases it.
- Nothing has been flown in the simulator since the port.
