# Fenix channel ND Implementation Plan (plan 03)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Task 0, the claim, is done. A **[sim]**, **[in flight]** or **[owner]** task is the controller's, with the owner,
> never an implementer's.

**Goal:** The captain's whole ND, read from the display channel while the ND is trusted: a live window on output Alt+N
that lists, in screen order and each item as drawn, the header, the map (the route and its markers, the map points,
traffic), the ROSE LS and ROSE VOR content and the messages, with the captain's EFIS controls under the list; the next
waypoint on output Ctrl+W; and an "ND messages" announcement row.

**Architecture:** The ND is read in layers (header, route, map points, radio, traffic), each a decoder of its own fields
from one snapshot (plan 01's `FenixChannelSnapshot`) with its own status row. A pure geometry places a map item on the
screen as each mode and range draws it; a look table holds every symbol and color the captures measured; a composer
joins the layers in screen order. The map points come from `GetMapData` through the monitor, polled while the window
is open and checked against the snapshot. The owner's time in the sim is three sittings: one at the gate and one flight,
each before the code that needs it (captures cropped and read by the controller, the EFIS set by the controller with the
owner's go-ahead), and the final check on the finished build. One switch commit at the end.

**Tech Stack:** C# 13 / .NET 10, Windows Forms, xUnit; plan 01's `FenixChannelPush`, `FenixChannelSection<T>`,
`FenixChannelRows`, `FenixChannelSpeech`, `FenixChannelDisplayForm`, `FenixChannelAnnouncers`; `NavigationCalculator`;
`FenixChannelProtoWriter` (tests).

**Spec:** `docs/fenix-channel/spec.md` 1, 2.1 (the map points' call), 2.2 (the ND verdict, the map points' check), 2.4
(the ND window), 2.5 (Ctrl+W), 2.6 (colors, the ND map's rule), 2.7 (ND messages), 3.3, 4, 6; answers 1, 2, 6, 19-22,
24, 30 and 46-56.

**History:** rewritten on 2026-11-03 for the whole ND (spec rows 46-56), then consolidated the same day at the owner's
choice from 24 tasks in seven sim sessions to these 16 in three sittings: the code stays layer by layer, only the
owner's sim time is batched. The old plan's Task 2 (the `d` letter) is gone: plan 02 made `d` and `p` known (the owner's

  `Only_the_captains_route_is_read`).

  (Task 3: `An_unknown_code_in_any_nd_line_stops_the_nd`; Task 4: `An_unknown_code_stops_the_whole_nd`).

  `The_track_reads_on_the_compass`).
- The map points never come from a stale or disagreeing reply (Task 9: `A_disagreeing_or_stale_reply_is_not_used`).
- One layer's problem never takes another layer down (Task 4: `A_layer_problem_leaves_the_other_layers`).
- A color is spoken only from the channel or a measured look (Task 4: `An_item_with_no_measured_look_speaks_no_color`,
  `Every_look_cites_its_evidence`).
