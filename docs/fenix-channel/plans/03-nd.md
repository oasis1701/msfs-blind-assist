# Fenix channel ND window and Ctrl+W Implementation Plan (plan 03)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> Task 0, the claim, is the controller's own, done before Task 1 is dispatched.

**Goal:** A live window of the captain's ND on output Alt+N and the next waypoint on output Ctrl+W, both read from the
display channel only while the ND is trusted, with the ND's `d` format letter measured before any read uses its line.

**Architecture:** One reader, `FenixChannelNd`, decodes the captain's ND fields from a snapshot's message (plan 01),
checks each field's shape, the ND's own content and every line's format letters, and composes the window's rows;
`FenixChannelNdWaypoint` turns the next-waypoint lines into Ctrl+W's sentence. One switch commit implements the
definition's `ChannelNdKey` seam (Alt+N opens the window through `OpenChannelWindow` on the ND verdict; Ctrl+W speaks)
and `AddChannelNdWindows`, after everything else is in place and inert. A [sim] task measures the `d` letter, the EFIS
fields and the ND's sides before any code that depends on them: `d` joins `FenixChannelText` as an unspoken attribute
only if that measurement confirms it, and otherwise the window leaves the ground speed and TAS line out.

**Tech Stack:** C# 13 / .NET 10, Windows Forms, xUnit; plan 01's `FenixChannelPush`, `FenixChannelSection<T>`,
`FenixChannelRows`, `FenixChannelSpeech`, `FenixChannelDisplayForm`; `FenixChannelProtoWriter` (tests).

**Spec:** `docs/fenix-channel/spec.md` 2.2 (the ND verdict), 2.3 (the `d` letter), 2.4 (the ND window), 2.5 (Ctrl+W),
2.6 (colors), 3.3, 4, and section 6's checks for plan 03 (the `d` letter, the EFIS mode numbering, ND message sides);
answers 1, 2 and 6.
